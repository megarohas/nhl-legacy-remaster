# Маски вратарей из NHL 27 (`tools/fb/masks.py`, 03.11.2026)

Пользователь: «перенос вратарских шлемов Юты, Вегаса и Сиэтла, а также цветов экипы (не покроя щитков, а хотя бы просто
расцветки)». У трёх клубов вратари были в белом наборе с белой маской 0/120 (своего набора EA нет, у Юты — набор Аризоны,
`goalie_gear.json` → `white_names`). Цвета щитков, блина, ловушки и клюшки — [legacy-data.md](legacy-data.md), «Расцветка
вратарей UTA, SEA, VGK из NHL 27»; здесь — рисунок маски.

## Как устроено

- **Legacy.** Модель маски — `rendering/goaliehelmet/helmet_<masktype>_<L>.rx2`; тип 0 — itech (шейдер
  `helmet_goalie_current_itech_high`), решётка — отдельная модель `cage_*`. Рисунок — `goaliehelmet_<masktype>_<maskid>_cm.rx2`
  (512² DXT1). У типа 0 номера 0…291 заняты EA, поле `maskid` — 9 бит (до 511). Маску вратарю задают поля
  `exhibitiongoalieequipment.masktype` и `maskid`.
- **NHL 27.** Рисунок — `character/skater/goalie/helmet/itech/textures/goalie_helmet_itech_<N>_color` (2048²), модель —
  `goalie_helmet_itech_mesh` (секция `mat_helmet`, решётка в той же сетке). N у вратаря — `maskid` в `nhl_game.db`.
- Развёртки двух моделей похожи (купол, затылок, ремни), но не совпадают (`game/work/models-check/probe/mask_uv.png`),
  поэтому перенос по 3D: модель NHL 27 без прутьев решётки (связные куски, у которых развёртка по v уже `CAGE_UV` 0,03)
  вписывается в рамку модели Legacy по осям (у NHL 27 голова на ~6–8 см выше и впереди, размеры — до 2 см), каждый тексель
  Legacy берёт цвет с ближайшей точки NHL 27 (`kit3d.transfer`). Без исключения решётки серый цвет прутьев ложился полосой на
  лоб и подбородок.
- Новые маски — свободные номера, план `tools/fb/mask_slots.toml` (номер Legacy ← номер NHL 27). Файл рисунка — по шаблону
  белой маски 0/120 (растр переименовывается на новый номер).
- Вратарю маску ставит этап `goaliegear` (`tools/legacy_data/goalie_gear.py`): у клубов `nhl27_colors` маска — его маска
  NHL 27 из плана, если она там есть.

## Запуск

```bash
cd tools
FB_GAME=nhl27 python -m fb.extract "goalie/helmet/itech/.*goalie_helmet_itech_(<номера NHL 27 из mask_slots.toml через |>)_color$" --out masks27
FB_GAME=nhl27 python -m fb.masks build    # → game/work/nhl27/out/masks/cache/rendering/goaliehelmet/*.rx2 и PNG
python -m fb.masks sheet                  # → game/work/nhl27/out/masks/sheet.png: Legacy сейчас | NHL 27 | в Legacy
python -m kitport put --from ../game/work/nhl27/out/masks/cache --tag masks-<дата> --yes   # рисунки в cache: с копией
python legacy_data/goalie_gear.py db БАЗА.db --clubs "<клубы через запятую>"
python legacy_data/goalie_gear.py save СЕЙВ_ROSTER --write --clubs "<клубы через запятую>"
```

Добавить вратаря: номер его маски в NHL 27 (`nhl_game.db`) → новая строка `[mask.<свободный номер>]` в `mask_slots.toml`,
выгрузка, `build`; клуб — в `goalie_gear.json` → `nhl27_colors.clubs`.

## Проверка и остаток

- Лист `game/work/nhl27/out/masks/sheet.png` (по два ракурса): рисунок на Legacy совпадает с NHL 27 — полосы Кракена,
  надпись UTAH, мамонт, золотой дракон Хилла, золото Харта.
- Остаток: в проёме маски у лба видна часть подкладки NHL 27 (кусок с логотипом изнутри) — в игре её закрывает решётка.
- Модели щитков, блина и ловушки — Legacy (белого набора), покрой не переносится.

## Стандартные маски без логотипов (`tools/fb/mask_gen.py`, 03.11.2026)

Пользователь: «в игре есть дефолтные шлемы разных цветов. Можно ли расширить этот список … Там есть чёрно-серый,
серебристо-чёрный шлем, который мне всегда нравился … Можно разных цветов в схожем стиле, а может, в совершенно другом».

- **Где список.** Маски в выборе экипировки — каталог редактора в образе игры (`default.bin`, адрес 0x83A2C5D8): 86 масок
  по 36 байт (+4 — тип маски, +8 — номер, +28 — номер закрытой вещи, −1 — открыта) и запись-ограничитель
  `NotAvailable` (тип 99), разбор — `tools/unlockables.py catalogs`. Это не таблица базы: новый номер, поставленный через
  `exhibitiongoalieequipment.maskid`, игра показывает на вратаре, но в выборе его нет. Расширение каталога — правка exe
  (агент «Порт»: новые записи из файла-списка, формат — его раздел ниже); имеющиеся маски каталога не заменяются.
- **Образец** — 0/125 (запись 6 каталога): купол серебро, низ чёрный с серебряным узором; подтвердил пользователь.
- **Генератор.** Только оболочка (острова развёртки купола и затылка), ремни, пряжки и подкладка — как в образце;
  вентиляционные отверстия — тёмные по белой маске 0/120. Стили: `swoosh` (рисунок 0/125 перекрашен: серебро → light,
  чёрное → dark, рельеф и блики — яркостью внутри своего класса), `stripes`, `carbon`, `gradient`. Варианты —
  `VARIANTS` в коде: 12 в стиле 0/125 и 4 других. Номера — свободные после 319.

```bash
cd tools
python -m fb.mask_gen sheet [--only имя,…]           # лист → game/work/nhl27/out/masks-gen/sheet.png
python -m fb.mask_gen build --pick имя,… --from 320  # выбранные → masks-gen/cache (затем kitport put --from …)
```

**Свободные дизайны (`tools/fb/mask_designs.py`, 03.11.2026).** Пользователь: «забей на референс, просто поэкспериментируй
на шлемах». 34 дизайна с постоянными номерами (`DESIGNS`): ретро-двухцвет, широкая и узкие полосы, диагональ, шевроны,
пиксельный и обычный камуфляж, сетка, градиенты (матовый и металлик), переход спереди назад, пламя, молнии, номерные
плашки (без цифр), шашки, волны, тигр, растровые точки, соты, однотонные металлик и мат — в базовых схемах (чёрный,
серебро, белый, красный, тёмно-синий, синий, зелёный, золото, оранжевый, фиолетовый, бордовый, бирюзовый). Рисунок
считается от 3D-позиции текселя — через швы развёртки он непрерывен, черт по краю островов нет. В стилях `carbon` и
`gradient` генератора `mask_gen` прежняя окантовка по линии лба убрана: на листе она читалась белой чертой поперёк лица.


## Свои маски в редакторе (exe, `nhl_extra_masks`, 03.11.2026)

Каталог масок редактора удлиняет exe: новые записи читаются из простого списка, пересобирать exe для новых номеров не
нужно. Код — `nhl-legacy-port/src/nhllegacy_masks.cpp`, как устроено — [legacy-port.md](legacy-port.md), «Каталог масок
вратаря».

**Файл** — `userdata/cache/guest/nhllegacy_masks.txt` (рядом с модами `cache:`; на ПК пользователя —
`nhl-legacy-port/userdata/cache/guest/`). Строка — одна маска:

```
# masktype maskid [preview_id] [цвет]      # — комментарий
0 320
0 321 1321 red
```

| Поле | Что | Если не указано |
|---|---|---|
| `masktype` | тип маски 0–3 (0 — itech, как у 0/292–319) | — |
| `maskid` | номер рисунка 0–511: файл `rendering/goaliehelmet/goaliehelmet_<masktype>_<maskid>_cm.rx2` | — |
| `preview_id` | номер превью в списке: файл `fe/ion/artassets/createplayer/mask/mask<preview_id>.big` | 1000 + `maskid` (у EA заняты 1…221) |
| цвет | ключ подписи из каталога EA (`white`, `red`, `blue`, `black`, `green`, `orange`, `yellow`…): в списке «BAUER <цвет>» | как у первой маски того же типа в каталоге |

- Новые маски стоят в списке после 86 масок EA, в порядке файла. Маска, которая уже есть в каталоге, и повтор в файле
  пропускаются (строка в журнале).
- Превью — BIGF/Apt, как превью экипировки EA (у EA 88 файлов `mask*.big` в `cache.big`; холст 256 × 128). Делают его
  генераторы «Моделей» вместе с маской. Без файла превью клетка в списке пустая, маска выбирается.
- Нет файла или `nhl_extra_masks = false` в `nhllegacy.toml` — список как у EA. Файл читается при старте игры.

**Проверено 03.11.2026** на копии userdata (exe 742aba40, файл с 0/292 и 0/295): в Edit Player у вратаря (Brossoit, ANA)
88 масок, первые 86 — как у EA (места и превью те же), новые — в последнем ряду, на превью справа их рисунок; выбранная
надета, после выхода из Edit Player игра записала ROSTER, в нём у Brossoit 0/295 (было 0/126). Известное: если на вратаре
маска не из «стандартных» диапазонов EA (82AE2EF0: тип 0 — 119…125 и 212…221 и т. п.), курсор в списке встаёт на первую
маску — так же у EA для командных масок; сама маска на вратаре остаётся.

**Превью в редакторе (03.11.2026).** `fe/ion/artassets/createplayer/mask/mask<ID>.big` — BIGF/Apt 8888, холст 256×128, у EA
маска 3/4 с решёткой на стойке. У записей каталога EA ID — первое слово записи (запись 6 = [9, 0, 125] → `mask9.big`), у
своих масок — 1000 + maskid (список «Свои маски в редакторе»). `fb.masks.write_fe` рисует его по шаблону EA `mask9`: стойка
из шаблона (выше её — только штанга), маска — рендер модели itech с решёткой `cage_0_0_2` под углом `FE_YAW` 45° в рамке
`FE_BOX`. `fb.masks build` и `fb.mask_designs build` пишут превью вместе с рисунком; `python -m fb.masks fe` — превью для
уже собранных масок плана. Отличие от EA: маска на превью чуть меньше и правее (у EA вид немного сбоку и шире).
