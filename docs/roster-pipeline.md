# Конвейер современной базы: составы НХЛ 2026/27 → nhlng.db

`tools/roster/` автоматически наполняет `nhlng.db` нынешними составами 32 клубов НХЛ: игроки,
биография, принадлежность к клубу, номера, реальные звенья (DailyFaceoff) и буквы, рейтинги
NHL 27. Этап 1 — только клубы НХЛ. Фото, логотипы, формы, контракты — следующие этапы (место
в данных заложено: поля `photo`, `contract`, `ea.avatar` в players.json; контракты в базе —
заглушка).

Источники выбраны по [research-data-sources.md](research-data-sources.md) и
[research-rosters-community.md](research-rosters-community.md); устройство команд —
[teams.md](teams.md); подмена базы — [modding.md](modding.md); год —
[year-and-date.md](year-and-date.md).

## Запуск

```bash
python tools/roster fetch     # API → game/work/roster-cache/ (~2000 запросов, около часа в первый раз;
                              # части можно гонять параллельно: --only nhl,ea,wiki и --only nhlratings;
                              # звенья — --only dfo, 33 запроса)
python tools/roster build     # кэш → game/work/roster/players.json
python tools/roster lines     # звенья DailyFaceoff + players.json → lines.json
python tools/roster match     # players.json + база → match.json
python tools/roster write     # → game/work/roster/nhlng.db (+ nhlng-meta.xml рядом)
python tools/roster report    # → game/work/roster/report.md, report-lines.md
python tools/roster all       # всё подряд; --offline — без сети, только кэш
python tools/tdb.py verify game/work/roster/nhlng.db --meta game/work/nhl32/nhlng-meta.xml

# своя папка вместо game/work/roster (промежуточные файлы, отчёты, база):
python tools/roster all --offline --work roster-lines      # → game/work/roster-lines/

# и фарм-клубы Сиэтла и Вегаса (база tools/nhl32.py --ahl32, составы из Wikipedia):
python tools/roster fetch --only ahl --work roster-ahl32
python tools/roster all --offline --ahl32 --db-in game/work/nhl32-ahl32/nhlng.db --work roster-ahl32

# расширения (docs/roster-expansion.md); без флагов база — прежняя байт в байт:
python tools/roster fetch --only fa,liiga                 # свободные агенты и Liiga — в кэш
python tools/roster all --offline --stats-ratings --fa --skin --league liiga --work roster-custom \
       --db-in game/work/nhl32-custom/nhlng.db
python tools/roster photos --work roster-custom           # фото не из НХЛ → кадр НХЛ, затем tools/photos.py build
```

Интерпретатор — Python 3.14, только стандартная библиотека. Каталог `game/` (не в git)
ищется рядом с `tools/`, а из рабочей копии git (`.claude/worktrees/…`) — в основной копии
(по файлу `.git`); переопределить — переменная `NHL13_GAME` или `--game`. Опции:
`--db-in`/`--db-out` (вход по умолчанию `game/work/nhl32/nhlng.db` — НХЛ на 32 команды,
[tools/nhl32.py](../tools/nhl32.py)), `--work` (папка `players.json`, `lines.json`,
`match.json`, `write.json`, отчётов и выходной базы: имя внутри `game/work/` или абсолютный
путь; в новой папке `artid-registry.json` берётся из `game/work/roster/` — artid новых те же),
`fetch --only nhl,ea,nhlratings,wiki,dfo,ahl,fa,liiga`, `--refresh` (скачать заново), `--pause` (не
меньше 1 с), `write --rating-lines` (звенья всех клубов по рейтингу, как до этапа lines), `--ahl32`
(ещё и клубы АХЛ из `common.AHL_CLUBS` — ниже).

Расширения — [roster-expansion.md](roster-expansion.md): `--stats-ratings` (OVR по статистике трёх
сезонов с NHL-эквивалентами лиг, `statsrating.py`, отчёт `report-ratings.md` «было → стало»),
`--fa` (реальные свободные агенты 2026/27 → `exhibitionfreeagents`, `fa.py`), `--skin` (типовая
голова под тон кожи на официальном фото, `skin.py`, лист проверки `skin-sheet.html`, поправки
`game/work/roster/skin-overrides.json`), `--league liiga` (клубы SM-liiga 74–87 — нынешними составами
liiga.fi, `league.py`), этап `photos` (портреты лиг и NHL latest → кадр портретов НХЛ,
`photos_other.py`, лист `photos-sheet.html`).

`write --payroll-max МЛН` (`write.cap_payroll`) нужна потому, что контракты — заглушка по OVR и возрасту. Ведомость состава клуба НХЛ (сумма `contractdollars` × 5000 $ по `exhibitionrostertable`; так её считает и игра, сверено в NHL Legacy) выходит 94–135 млн. Если она больше МЛН, все контракты клуба (по `proteam`) выше минималки 850 тыс. умножаются на один коэффициент. В итоге получается наибольшая ведомость, которая ≤ МЛН. Сводка — `write.json` → `payroll`. Без флага база прежняя; для NHL Legacy `build-all.sh` ставит 100 (потолок 2026/27 — 104 млн, [legacy-data.md](legacy-data.md)). Настоящие кэп-хиты — CapWages ([research-data-sources.md](research-data-sources.md) §2): платный API или разбор страниц клубов, решение за пользователем.

`write --fa-only` работает вместе с `--fa`. В пуле свободных агентов (`exhibitionfreeagents`) остаются только настоящие свободные агенты конвейера. Свободные агенты исходной базы, чьи строки не ушли новым игрокам, из пула убираются, строки игроков остаются. Список убранных — `write.json` → `fa_dropped`. Без флага пул прежний: у NHL 13 там остаются свободные агенты 2012 года. Для NHL Legacy `build-all.sh` ставит флаг: иначе в пуле были бы 35 игроков 2015 года.

### Клубы АХЛ (--ahl32)

Фарм-клубы Сиэтла и Вегаса — Coachella Valley Firebirds (строка 220) и Henderson Silver Knights
(221) — новые клубы базы `tools/nhl32.py --ahl32`; составы 2012 года у них нет, конвейер заполняет
их сам (`tools/roster/ahl.py`). Источник — статья клуба в английской Wikipedia, раздел «Current
roster» (шаблоны `{{Ice hockey team player}}`: имя, номер, амплуа, хват, дата и место рождения,
гражданство, чей контракт, C/A; закомментированные — не в составе); у Coachella Valley состав —
отдельный шаблон «Template:… roster», он подтягивается сам. Кэш — `wiki/ahl/`, `nhl/search/ahl/`,
`nhl/ahl/<клуб>.json`. ID НХЛ — поиском search.d3 по имени без фильтра active (находит и игроков с
контрактом только в АХЛ), проверка — дата рождения в карточке landing; дальше игрок собирается как
игрок НХЛ (рост, вес, драфт, игры, фото), номер — из состава АХЛ. Кого поиск не нашёл — запись
только из Wikipedia (рост и вес — типовые по амплуа, ID 90 000 000 +). Рейтингов EA и
nhlratings.net у игроков АХЛ нет: OVR — уровень АХЛ исходной базы (медиана 76 против 83 у НХЛ),
моложе 21 — на 1 ниже, с опытом НХЛ (40+ и 200+ игр) — на 1–2 выше. `proteam` — клуб-хозяин,
если контракт с ним, иначе 0 (как у игроков АХЛ с контрактом АХЛ в исходной базе). Звенья — по
рейтингу, буквы — из Wikipedia. Если игрок есть и в составе НХЛ (вызван), он остаётся в НХЛ.

**Установка** (вручную, после проверки отчёта): `game/work/roster/nhlng.db` (или из своей
папки `--work`) и `nhlng-meta.xml` → `game/userdata/cache/guest/db/`. Сам конвейер в
`game/userdata/` ничего не пишет. Сейвы франшизы несут свою копию базы — новые составы видны
в новой франшизе и «Играть сейчас».

### fetch: источники

Только GET, пауза между запросами к одному хосту ≥ 1 с, на 429/5xx — повтор с растущей
паузой, редиректы 307 urllib проходит сам. Ответ, уже лежащий в кэше, повторно не
запрашивается (404 запоминается файлом `.404`).

| Источник | Запросы | Что берём |
|---|---|---|
| `api-web.nhle.com/v1/roster/{TEAM}/current` | 32 | состав: имя, амплуа, хват, номер, рост, вес, дата и место рождения |
| `api-web.nhle.com/v1/player/{id}/landing` | ~800 | драфт, игры НХЛ по сезонам (регулярка и плей-офф), результативность, клуб |
| `api.nhle.com/stats/rest/en/{skater,goalie}/bios` | 4 | гражданство (`nationalityCode`) за 2025/26 и 2026/27 |
| `search.d3.nhle.com/api/v1/search/player?q=*&active=true` | 1 | игроки, которых состав не показывает (ниже) |
| `ea.com/games/nhl/ratings?page=1…6` | 6 | топ-300 NHL 27: ID EA, OVR, 40 атрибутов (`__NEXT_DATA__`) |
| `nhlratings.net` | ~1100 | страницы 32 клубов, игроков с них (OVR, атрибуты у части, стиль) и 13 списков топ-100 вратарских атрибутов; сборщик — по образцу `tools/providers/ea_ratings.py` puckpeak (MIT) |
| `en.wikipedia.org` (`/wiki/<статья>?action=raw`) | 1 | «List of current NHL captains and alternate captains» (robots.txt закрывает `/w/`, поэтому не `index.php`) |
| `www.dailyfaceoff.com/teams/{slug}/line-combinations` | 32 + robots.txt | реальные звенья: 4 тройки, 3 пары, вратари, PP1/PP2, PK1/PK2, травмированные (`__NEXT_DATA__`, ниже — раздел lines) |

**Игроки вне `/roster/current`.** Состав API не показывает травмированных (Джарвис, Барзал,
Терри, Густавссон…; `/roster/{TEAM}/20262027` — тот же список). Их находит поиск
search.d3: клуб НХЛ, в составе нет, и либо 40+ игр в НХЛ в прошлом сезоне, либо EA числит
его в топ-300 за этим клубом. В players.json у них `omitted: true`. Эвристика: среди них
могут попасться отправленные в АХЛ или на просмотр.

```json
   "rookie": false, "omitted": false, "letter": "C",
   "ea": {"ea_id": 1082, "ovr": 95, "attrs": {"p_speed": 88, ...}, "avatar": "..."},
   "nhlratings": {"slug": "sidney-crosby", "ovr": 95, "attrs": {...}, "style": 6},
   "rating": {"source": "ea", "ovr": 95, "attrs": {...}, "style": 6},
   "photo": "https://assets.nhle.com/mugs/nhl/20262027/PIT/8471675.png", "contract": null}]}
```

Игры НХЛ — регулярка + плей-офф, как в базе NHL 13 (у Кросби к 2012 году 434 + 68 = 502),
`career` — до нынешнего сезона. Новичок — по правилу НХЛ (до 26 лет на 15.09, ни в одном
прошлом сезоне больше 25 игр, не два сезона по 6+).

Рейтинги сшиваются так: EA — по имени и клубу (даты рождения у EA нет; тёзки в одном клубе —
по амплуа и номеру), nhlratings.net — по фамилии и дате рождения. Источник рейтинга: EA (все
атрибуты) → nhlratings.net с атрибутами → только OVR → нет.

### lines: реальные звенья (DailyFaceoff)

Источник — страницы сочетаний DailyFaceoff
`https://www.dailyfaceoff.com/teams/{slug}/line-combinations` (slug — как у nhlratings.net:
`washington-capitals`, `utah-mammoth`; `common.TEAM_URL_SLUG`). `robots.txt` разрешает всё,
кроме `/api/` и `/cms/`: `fetch --only dfo` берёт его первым (тоже через кэш) и проверяет
`urllib.robotparser` каждую страницу; запросы — через `common.Http` (кэш
`roster-cache/dailyfaceoff/`, пауза ≥ 1 с, по одному), без входа и ключей. Условия
использования сайта не проверял. Страница — Next.js, данные — JSON `__NEXT_DATA__` →
`props.pageProps.combinations` (разбор — `sources.dfo_lines`): `updatedAt`, `sourceName` и
`source` (кто составил — журналист клуба со ссылкой на пост или «Last Game (дата)», состав
последнего матча), `players[]` — запись на каждое место:

| `groupIdentifier` | Что | Места (`positionIdentifier`) |
|---|---|---|
| `f1`…`f4` | тройки | `lw`, `c`, `rw` |
| `d1`…`d3` | пары | `ld`, `rd` |
| `d4` | седьмой защитник (клуб играет 11 + 7, в `f4` тогда двое) | `ld` или `rd` |
| `g` | вратари | `g1` (основной), `g2` |
| `pp1`, `pp2` | большинство, 5 полевых | `sk1`…`sk5` без амплуа: `sk1`–`sk3` — первый ряд, `sk4`–`sk5` — «синяя линия» (на 64 пятёрках 7.10.2026 в первом ряду всегда нападающие, сзади один-два защитника) |
| `pk1`, `pk2` | меньшинство, 4 полевых | `sk1`, `sk2` — нападающие, `sk3`, `sk4` — защитники |
| `ir` | травмированные | `injuryStatus`: `out`, `dtd`, `ir` |

Игрок повторяется в каждой своей группе: имя, номер (у новичков бывает null), статус травмы.

**Сопоставление** с players.json (`lines_real.find`) — только внутри своего клуба, вратарь —
с вратарём: 1) имя и фамилия (`common.norm`); 2) та же фамилия и имя в другой форме
(`build.same_first`: Zack — Zachary, Nicholas — Nick) или тот же номер; 3) тот же номер и
похожая фамилия; 4) та же фамилия и первая буква имени при амплуа как в звене (Jacob — Jake
Middleton). У тёзок на каждом шаге решают номер, потом амплуа («Elias Nils Pettersson» #25 из
пары — защитник «Ванкувера», а не нападающий #40). Суффиксы Jr./Sr./II/III не учитываются.
Кто не нашёлся — в `unmatched` с причиной (в составе другого клуба конвейера или нет в
составах НХЛ), его место — null; кто нашёлся не по точному имени — в `fuzzy`.

```json
{"source": "dailyfaceoff.com/teams/{slug}/line-combinations", "generated": "...", "missing": [],
 "teams": {"WSH": {"updated": "2026-10-06T15:36:43.017Z", "source": "Sammi Silber", "source_url": "https://x.com/…",
   "f": [[lw, c, rw], … 4], "d": [[ld, rd], … 3], "extra_d": [], "g": [g1, g2],
   "pp": [[sk1 … sk5], [ … ]], "pk": [[sk1 … sk4], [ … ]],
   "injured": [{"name": "Rasmus Sandin", "injury": "out", "nhl_id": …}],
   "unmatched": [{"name": …, "num": …, "groups": ["d1", "pk1"], "why": …}],
   "fuzzy": [{"name": "Jacob Middleton", "player": "Jake Middleton", "how": …}], "empty": ["f4 rw"]}}}
```

(вместо игроков — `nhl_id` или null). **В базу** (write → `lines.build_real`; у клуба, где
источник дал меньше 12 игроков клуба в тройки, пары и ворота, и при `write --rating-lines` —
прежний `lines.build` по рейтингу):

| Места NHL 13 | Откуда |
|---|---|
| `l1…l4 lw/c/rw`, `l1…l3 ld/rd`, `g1`/`g2` | тройки, пары, вратари источника как есть; одеты (`rosterstatus` 1) эти 20 |
| `pp1`, `pp2`: `lw`, `c`, `rw`, `ld`, `rd` | PP1/PP2: первый ряд → `lw`/`c`/`rw` (центр — кто центр в тройке, потом центр по амплуа, потом лучшее вбрасывание; крайние — по своим сторонам), «синяя линия» → `ld`/`rd` по хвату; нападающий на «синей линии» — как в исходной базе (Овечкин в `pp1ld` 2012 года) |
| `pp4_1`, `pp4_2` (4 на 3) | центр, лучший в атаке крайний и «синяя линия» своей пятёрки PP |
| `pk4_1`, `pk4_2`: `lw`, `c`, `ld`, `rd` | PK1/PK2: нападающие → `c` (как в PP) и `lw`, защитники → `ld`/`rd` по хвату |
| `pk3_1`, `pk3_2` (3 на 5) | центр и пара своей четвёрки PK |
| `ot_*`, `s1`–`s5`, `x1`/`x2` | по рейтингу из одетых, как в `lines.build`: овертайм — центры 1–3-й троек, лучшие в атаке из остальных нападающих и пары; буллиты — лучшие по обводке и кистевому; лишние — лучшие по OVR |

Пропуски — по рейтингу:
- место в тройке, паре или воротах без игрока клуба (не сопоставлен, повтор, чужое амплуа:
  защитник в тройке, нападающий в паре, вратарь не у ворот) — лучший по OVR из неодетых своего
  амплуа (на месте центра — сначала центр); здоровые — раньше травмированных (`ir` источника) и
  тех, кого нет в `/roster/current`;
- седьмой защитник (`d4`) не одевается: в NHL 13 одеты 12 нападающих и 6 защитников, амплуа по
  местам — как у всех 30 клубов исходной базы (в тройках только нападающие, в парах и в заднем
  ряду меньшинства — только защитники, на «синей линии» большинства — любой полевой); пустое
  место в 4-й тройке — нападающему по рейтингу;
- игрок PP/PK, который не одет или не того амплуа для своего ряда, — лучший в атаке (PP) или
  обороне (PK) из одетых, кого в этой пятёрке нет: сначала не из другой пятёрки, в первый ряд
  — нападающий, назад — защитник.

`write.json` → `lines_info`: по клубу источник, дата, кто составил, `filled` (что достроено) и
`dropped` (кто из источника не поставлен и почему). `report-lines.md` — по каждому клубу 4
тройки, 3 пары, вратари, PP1/PP2, PK1/PK2 с именами и OVR из выходной базы (`*` — достроено),
несопоставленные, достроенные, найденные не по точному имени, травмированные в звене; заодно
сверка базы с `write.json`.

### match: сопоставление с базой

Вратарь — только с вратарём (у них своя таблица атрибутов), полевой — с полевым:

1. `artid` = ID EA (сквозной с NHL 13: Кросби 1082, Макиннон 9179), если EA его знает и
   ID < 16384, при похожей фамилии и годе ±1 — или точной дате рождения (во входной базе
   Кросби переименован в «Megarohas» проверкой мода; имя возвращается из API);
2. фамилия + дата рождения (у близнецов решает имя);
3. имя и фамилия + почти та же дата: тот же год и месяц или день (у Берроуза в базе месяц
   на один меньше), либо месяц и день при годе ±1 — тёзка с другой датой (юниор Jake Evans
   1995 г. р.) не считается;
4. дата рождения + похожая фамилия (≥ 0,8) + первая буква имени (Audy-Marchessault).

Логика 2–4 — по образцу `matching.py` puckpeak (MIT). Одну строку не отдают двоим.

## Устройство базы (что выяснено)

| Таблица | Ключ | Связь |
|---|---|---|
| `exhibitionplayerbiotable` (5412) | `game_id` (14 бит, по нему отсортирована) | био и контракт |
| `exhibitionskaterai` (4875) / `exhibitiongoalieai` (537) | `game_id` | атрибуты; 4875 + 537 = 5412 |
| `exhibitionplayers` (5874) | `index` — «связь», отсортирована | `playerid` = `game_id`; по связи на каждое появление игрока в составах (у Кросби 5: PIT, Канада, Легенды, Team Wickenheiser, PIT Зимней классики); `index` ≥ 16000 с `table` = 1 — 180 слотов создаваемых игроков |
| `exhibitionrostertable` (5446) | `key` = команда × 40 + место (места 0…n−1) | `playerindex` = связь, у каждой записи своя; внутри команды записи по возрастанию `playerindex`; `team` — с нуля |
| `exhibitionfreeagents` (183) | — | `playerindex` = связи свободных агентов (в составах не используются) |

`game_id` в био и `playerindex` в составе — разные числа: составы ссылаются на связь, связь —
на `game_id`. В каждом клубе НХЛ исходной базы ровно 71 однобитное место звеньев с одним
владельцем, одеты 20 (= `rosterstatus` 1 = держат место), буквы: одна C (`captain` 1) и две A
(2) или три A. Игрок состоит не больше чем в одном клубе (НХЛ, АХЛ, Европа, юниоры), и `team`
в био = этот клуб + 1; сборные (128–148), Матч звёзд (218/219 после nhl32), проспекты
(209/210), легенды и Team Ruggiero/Wickenheiser (211–213), Зимняя классика (214–217) —
дополнительные записи тех же людей. У 309 игроков сборных без клуба (Япония, Беларусь,
Франция…) `team` = их особая команда + 1, контракта нет. 41 реальный игрок исходной базы —
без команды и записей (Яшин, Выборны): `team` = 0, такое состояние игра терпит.

## write: что меняется в базе

**Строки игроков.** Сопоставленный обновляется на месте — лицо, портрет и голос комментатора
остаются его. Новый занимает строку «донора» того же класса (вратарь — вратаря, полевой —
полевого; амплуа полевого меняется свободно). Доноры, старшие первыми: ушедшие из НХЛ игроки
2012 года, свободные агенты 2012 года, игроки без команды; клубы АХЛ/Европы/юниоров — только
если этих не хватит. Не берутся: игроки сборных, Матча звёзд, проспектов, легенд, Зимней
классики (иначе в этих составах появился бы чужой человек), пустые слоты создаваемых игроков.
Строки в таблицы не вставляются (таблицы отсортированы по ключу), строка био не переходит из
полевых во вратари.

У донора стирается прежний владелец: `artid` — новый, `hasportrait` 0 (силуэт), `audioid` 0,
типовая голова (`headid` 10000+ с самым частым цветом кожи, выбор по хэшу имени), черты
(`trait*`) 0, контракт и драфт — заново, карьерная статистика (`stockcareer*`) удаляется.

**artid новых.** Поле 14 бит, портреты на диске — до p9802, поэтому свой номер берётся из
9803–16383: ID EA, если он туда попадает (Кучеров 10071, Марнер 10848, Айкел 12816…), иначе
наименьший свободный, не занятый ID EA других игроков. Соответствие NHL ID → artid —
`game/work/roster/artid-registry.json`: повторный прогон даёт те же номера (портреты
следующего этапа будут называться по ним).

**Биография** — из API: имя (у сопоставленного прежнее написание, если отличается только
диакритикой: «Tomáš Hertl»; буквы, которых нет в именах базы — а значит, может не быть и в
шрифте, — без знаков), дата и место рождения, `state`/`intlcountry`, рост, вес, хват, амплуа,
номер, команда и права, драфт (клуб драфта — нынешний клуб франшизы: ATL → WPG, ARI → UTA,
QUE → COL), дебют, игры, новичок; `juniorteam` 0 / `juniorleague` 1, как у ветеранов базы.

**Контракт — заглушка** до этапа контрактов: сумма по OVR (0,9–10 млн $, новичку до 24 лет —
не больше 0,95 млн), срок по возрасту (3/4/2/1 года), `yearufa` = 2026 + срок,
`yearfirstsigned` — год после драфта или дебюта, `yearwaivereligible` — +3…5 лет (160+ игр в
НХЛ — уже). Игрок НХЛ без контракта мог бы уронить «Управление командой» (правило из
puckpeak), поэтому заглушка есть у всех.

**Рейтинги** (`ratings.py`):
- атрибуты EA и nhlratings.net — один в один (хранится значение − 36), Angles → `g_positioning`;
- недостающие поля — по «форме»: у сопоставленного — его атрибуты из базы, у нового — медианная
  форма игроков NHL 27 того же стиля (если их ≥ 5) или амплуа, сдвинутая к уровню известных;
- только OVR — форма сдвигается, пока среднее атрибутов + поправка амплуа не даст OVR
  (поправка — медиана «OVR − среднее атрибутов» у игроков EA, как `overall_offset` в puckpeak);
- нет ничего — OVR = 25-й перцентиль амплуа среди игроков НХЛ 2026/27 ± молодость ± 1
  (постоянный по имени) — по смыслу `estimate.py` puckpeak, без разрывов лиг (все из НХЛ);
- `p_overall`/`g_overall` = OVR NHL 27; `g_consistency` (в NHL 27 его нет) не трогается: в
  базе это не рейтинг, а 0–2 (у 383 из 537 вратарей — 1);
- стиль: nhlratings.net → прежний того же класса (F/D) → по результативности (очки за игру,
  доля голов, штраф, вес; карьера в НХЛ, у новичков — последний сезон в другой лиге с
  поправкой) → «центроид» формы атрибутов исходной базы; тенденции ИИ (`off_defbias`,
  `pass_carrybias`, `shoot_passbias`, `p_fighting`) — медианы стиля в исходной базе.

**Составы.** `exhibitionrostertable` пересобирается целиком: составы 32 клубов НХЛ, у
остальных команд записи прежние; key = команда × 40 + место, внутри команды — по возрастанию
`playerindex` (как в исходной базе; заодно исправляется порядок, сбитый ранней версией nhl32).
Номера — из API (повтор — у лучшего по OVR, остальным прежний или наименьший свободный).
Звенья — реальные сочетания DailyFaceoff (`lines.build_real`, раздел lines выше): тройки,
пары, вратари, PP, PK — из источника, пропуски, овертайм, буллиты, лишние — по рейтингу. У
клуба без них — `lines.build` (перенос `legacy_roster/lines.py` из puckpeak, MIT): 12
нападающих в четырёх тройках, 6 защитников (правый хват — справа), 2 вратаря по рейтингу,
большинство и меньшинство по атаке/обороне, овертайм, буллиты, лишние полевые — все 71
место. Буквы — из Wikipedia (C и две A; при «Vacant» — три A; больше двух A — оставляются
опытнейшие), недостающие — опытнейшим по играм в НХЛ.

**Ушедшие из НХЛ игроки 2012 года.** Место каждого, кто перешёл в НХЛ из клуба
АХЛ/Европы/юниоров (Макиннон из «Галифакса», Барков из «Таппары»…), занимает ушедший из НХЛ
того же амплуа — с номером, звеньями, буквой и условиями места прежнего (контракт, права,
юниорский клуб — по исходной базе), так что размеры и звенья этих команд не меняются.
Остальные — без клуба и контракта; `team` = 0, а у кого есть запись в сборной, легендах и
т. п. — эта команда + 1 (так в исходной базе у всех 309 игроков сборных без клуба); их записи
в особых командах не тронуты. Свободные агенты, отданные донорами, удаляются из
`exhibitionfreeagents`.

**Проверки** перед записью (`Writer.verify`): CRC; key по порядку; у каждой записи своя связь,
связь существует; свободный агент не в составе; игрок не больше чем в одном клубе и `team` =
клуб + 1; у каждого клуба НХЛ 71 место по одному владельцу, 20 одетых = `rosterstatus`, буквы
C + 2A или 3A, номера без повторов, вратари — только в `g1`/`g2` (у звеньев из источника и
остальные амплуа по местам — `lines.slot_kind`); каждый игрок API — ровно в своём клубе, в НХЛ
никого лишнего. `tools/tdb.py verify` на выходе — OK.

## Ограничения и известные проблемы

- **Сиэтл и Вегас** — строки 30/31 (бывшие заготовки Custom Team, `tools/nhl32.py`: названия,
  цвета, арены, логотипы 98/99; форма пока — копии Tappara/TPS), **Юта** — слот Phoenix (22).
- **Контракты** — заглушка (выше). **Портреты** новых — силуэты, **голос** — без фамилии,
  **лицо** — типовая голова.
- **Карьерная статистика** сопоставленных — по 2011/12, сезонов 2012/13–2025/26 нет.
- **Сборные, Матч звёзд, проспекты, легенды, Зимняя классика** — составы 2012 года (там
  остаются и ушедшие игроки); АХЛ, Европа, юниоры — тоже (стареющие на 14 лет), только места
  ушедших в НХЛ заняты ушедшими из НХЛ.
- **Травмированные** добавлены эвристикой (search.d3 + 40 игр/топ-300 EA); `/roster/current`
  их не показывает, статуса травмы в API нет. Со звеньями DailyFaceoff в основу попадает
  только тот, кого источник ставит в звено; при достройке по рейтингу они — последние. Но
  источник бывает непоследователен: 9 игроков 7.10.2026 стоят и в звене, и в списке
  травмированных (Марчанд, Раст, Дебраск — `dtd`/`out`/`ir`) — они в звене, как у источника
  (список — в report-lines.md).
- **Звенья DailyFaceoff** меняются каждый день, у части клубов это «Last Game» — состав
  последнего матча; обновить — `fetch --only dfo --refresh`. В межсезонье страницы показывают
  звенья прошлого сезона — этап lines предупреждает о странице старше 30 дней. Клуб, который
  играет 11 нападающих + 7 защитников, получает 12 + 6 (седьмой защитник не одет). Игрок
  источника, которого нет в составе клуба по API НХЛ (Severson), пропускается.
- **Рейтинги**: у nhlratings.net атрибуты только у части игроков, у остальных — достроены из
  OVR; `p_overall` берётся у NHL 27, а не пересчитывается формулой NHL 13 (по исходной базе
  OVR — почти линейная функция атрибутов: R² 0,998 у центров, 0,97 у крайних и защитников,
  0,96 у вратарей; пересчитывает ли игра OVR на экране — проверить).
- Буквы и номера на сегодня (7.10.2026) — составы меняются каждый день; прогон с
  `fetch --refresh` обновит кэш.
- Во входной базе остались следы проверки мода: у Кросби фамилия «Megarohas» (сопоставляется
  по artid и дате рождения, имя возвращается из API), у PIT `shortname` «Megarohas» и
  `fullname` «Megarohas Penguins» (поля команды; названия в интерфейсе — из локализации,
  [modding.md](modding.md); конвейер команды не трогает, в установленной копии
  `game/work/roster/nhlng.db` они возвращены вручную).
- Результат прогона 7.10.2026: 798 игроков, 146 сопоставлено (74 по artid), 652 новых (443 в
  строках ушедших из НХЛ, 174 — свободных агентов 2012 года, 35 — игроков без команды), без
  места 0; рейтинги: EA 298, nhlratings.net с атрибутами 91, только OVR 353, оценка 56;
  `exhibitionrostertable` 5446 → 5463 записей, свободных агентов 183 → 9. Повторный `write`
  с тем же кэшем даёт ту же базу байт в байт.
- Прогон со звеньями 7.10.2026 (`fetch --only dfo`, затем `all --offline --work roster-lines` →
  `game/work/roster-lines/`): всё то же, звенья из источника у 32 клубов; от базы с
  рейтинговыми звеньями отличается только `exhibitionrostertable` (места звеньев и
  `rosterstatus`); `write --rating-lines` даёт базу прежнего конвейера байт в байт
  (установленная копия от неё отличается только возвращёнными вручную именами PIT).
