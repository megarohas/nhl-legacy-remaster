# Лаунчер NHL Legacy (nhl-legacy-port/launcher)

12.10.2026. Окно настроек перед запуском порта: графика, экран, управление, сезон и финансы, кнопки «Играть»,
«Сбросить» и «Обновить ростеры». Свой exe на C++/Win32 (`nhllegacy_launcher.exe`, ~420 КБ, статический CRT, без DLL и установки) —
кладётся рядом с `nhllegacy.exe`, запуск двойным щелчком. Работает с любой сборкой Release (свой SDK), начиная с exe a1cb8f74.
Поля имени игрока с 03.11.2026 нет: в игре всегда `User` (раздел «Имя игрока»).

## Как работает

- Читает `nhllegacy.toml` рядом (только чтение) и поверх — свой `nhllegacy_launcher.toml`.
- «Играть» сохраняет `nhllegacy_launcher.toml` и запускает `nhllegacy.exe --имя=значение …`. Аргументы
  командной строки сильнее `nhllegacy.toml` ([graphics-settings.md](graphics-settings.md), «Источники и
  приоритет», механизм 1 из «(в) Как устроить лаунчер»), сам `nhllegacy.toml` не меняется.
- «Сбросить» — значения как в `nhllegacy.toml` (как без лаунчера). Крестик окна тоже сохраняет выбор.
- Если `nhllegacy.exe` уже запущен, вторую копию не запускает. Без `nhllegacy.exe` рядом «Играть» недоступна.
- Пустое значение игре не передаётся: разбор аргументов SDK принял бы за него следующий аргумент.
- Подсказка к настройке — в панели внизу, при наведении мыши или фокусе.
- Запуск `nhllegacy.exe` напрямую (без лаунчера) идёт только по `nhllegacy.toml`.
- Кнопка «Save to config» в окне F4 игры впишет переданные аргументы в `nhllegacy.toml` (так было и до
  лаунчера).

## Язык (с 0.11.2, 15.10.2026)

- Два языка окна — английский (по умолчанию) и русский, выбор в шапке справа. Смена — сразу, без перезапуска:
  элементы пересоздаются с новыми подписями, выбранные значения сохраняются.
- Выбор хранится в `nhllegacy_launcher.toml` ключом `launcher_language = "en"` / `"ru"`. Игре он не передаётся
  (его нет среди аргументов `--имя=значение`), язык самой игры не меняется.
- Все подписи, подсказки и сообщения — парами `T(L"English", L"Русский")` в коде, подсказки — таблицы
  `kHintsEn` / `kHintsRu`. В английском десятичная точка в финансах (76.9), в русском — запятая; вводить можно
  любую.

## Всегда включено (с 31.10.2026)

Без этих настроек никто играть не будет (решение пользователя 31.10.2026), поэтому в окне их нет. Лаунчер передаёт игре

## Имя игрока

**С 03.11.2026 поля нет** (пользователь: «убрать настройку имени пользователя, пусть будет всегда User»). Лаунчер имя не
показывает, не пишет в `nhllegacy_launcher.toml` и не передаёт игре, поэтому игра берёт умолчание SDK — `User`. Группа справа
называется «Ростеры», в ней одна кнопка «Обновить ростеры».

- Лаунчер 0.14.0–0.14.1 писал имя в свой файл строкой `nhl_user_name` под заголовком `# Player` / `# Игрок`. При запуске новый
  лаунчер убирает эти строки (`DropUserNameLine`), остальной файл не трогает; `--shot` файл не меняет. В `nhllegacy.toml` лаунчер
  никогда не писал и сейчас не пишет.
- В exe cvar `nhl_user_name` остался ([legacy-port.md](legacy-port.md), «Имя пользователя»): если вписать его в `nhllegacy.toml`
  руками, игра его покажет. Лаунчер его не перекрывает: пустое значение аргументом не передаётся.
- Сейвы от имени не зависят: в ROSTER, PROFILE, DYNASTY, BEAPRO, HOCKEYCARD и BUILDYOURAI имени нет, папки сейвов лежат по XUID.

Проверено 03.11.2026 на копии файлов установки (`game/work/port-check/lt`): строка `nhl_user_name = "megarohas"` и заголовок
`# Player` ушли, остальные строки байт в байт прежние; `--print-command` без `nhl_user_name`; снимки окна на обоих языках.

Как было с 02.11 по 03.11: поле «Имя игрока» до 15 байт UTF-8 (русская буква — два), допустимы латиница, кириллица с Ё, цифры,
пробел и `- _ . ' ! ? + & @ #`. Где имя видно в игре: PROFILE MANAGEMENT, списки SAVE / LOAD / DELETE, нижняя строка меню.

## Обновить ростеры

Кнопка в группе «Ростеры»: выбрать файл, проверить, добавить в игру. Нужна, чтобы не повторять на другом ПК всю работу
над составами: ростер с основного ПК переносится одним файлом. Код проверки — `nhl-legacy-port/launcher/roster_import.h`,
без Python и внешних библиотек, лаунчер остаётся одним exe.

- Игра запущена: кнопка отказывает и просит закрыть игру.
- Файл не прошёл проверку: лаунчер показывает причину на языке окна, в сейвах ничего не меняется.
- Файл прошёл: появляется новая папка `ROSTER <время>` и заголовок к ней. Прежние ростеры и PROFILE не меняются.

Какой файл брать: `…\userdata\B13EBABEBABEBABE\454109EC\00000001\ROSTER <дата>\ROSTER <дата>` с другого ПК, самый свежий, или файл
`ROSTER ДД.ММ.ГГГГ`, который делает [tools/legacy_data/roster_update.py](roster-update.md). В ростере только таблицы базы. Файлы форм, голов и
портретов он с собой не несёт, они ставятся вместе с данными игры.

### Имя в меню

С 02.11.2026 (версии после 0.14.0). Если в имени файла есть дата `ДД.ММ.ГГГГ`, ростер в меню называется `ROSTER ДД.ММ.ГГГГ`, иначе, как у игры,
`ROSTER1`. Код — `DisplayNameFor` в `roster_import.h`: день 1–31, месяц 1–12, год 2000–2099, вокруг даты не цифры, поэтому `ROSTER 20261024125927`
датой не считается. Прежний лаунчер такой файл тоже примет, но имя будет `ROSTER1`.

- В файле ростера места под дату нет, она живёт в имени файла, потом в заголовке (`…\Headers\00000001\<папка>.header`, смещение 8). Переименовал
  файл без даты — в меню `ROSTER1`.
- Игра показывает имя в LOAD, SAVE и DELETE: строка таблицы и крупная надпись над ней. `ROSTER 02.11.2026` занимает меньше половины столбца Name.
- Папка остаётся `ROSTER <время>`: Last Modified и выбор новейшего идут по ней, а не по имени.
- SAVE поверх такой строки: игра открывает клавиатуру с этим именем, после Done пишет новую папку и заголовок с тем же именем (проверено в игре
  02.11.2026). Имя там можно поменять, но на клавиатуре нет точки.

### Запуск без окна

```bat
nhllegacy_launcher.exe --check-roster ФАЙЛ    :: только проверка, сейвы не трогает
nhllegacy_launcher.exe --import-roster ФАЙЛ   :: проверка и добавление
```

`--lang=en|ru` — язык сообщения. Лаунчер — оконная программа, поэтому `cmd` кода возврата не дождётся: `start /wait` в
`cmd`, `Start-Process -Wait -PassThru` в PowerShell; из bash и Python всё работает как обычно. Сообщение уходит в stdout
вызывающего, если он его передал, иначе в его консоль.

| Код | Что значит |
|---|---|
| 0 | всё хорошо: `OK` или `OK: ROSTER <время>` |
| 1 | не указан файл |
| 2 | файл не прочитался |
| 3 | это не сейв NHL Legacy (мусор, пакет Xbox 360, файл больше 32 МБ) |
| 4 | это сейв другого вида: франшиза, Be a Pro, профиль, карточки, онлайн-ростер |
| 5 | ростер повреждён: длина, суммы, сжатые данные, база |
| 6 | ростер цел, но не подходит к базе этой игры, игра назовёт его «damaged» |
| 7 | игра запущена, ничего не записано |
| 8 | нет базы игры `userdata\cache\guest\db\nhlng.db`, не с чем сверять |
| 9 | не удалось записать, ничего не изменено |

Папка данных — `user_data_root` из настроек, как у порта; пусто — `userdata` рядом с exe.

### Как устроен сейв

`…\454109EC\00000001\<имя>\<имя>` — файл сейва, `…\454109EC\Headers\00000001\<имя>.header` — его заголовок. Заголовок
— `XCONTENT_AGGREGATE_DATA` SDK, 0x148 байт: устройство 1, тип 1, имя в меню UTF-16 BE, имя папки, XUID, 454109EC.

Заголовок даёт только имя в меню. SDK (`ContentManager::ListContent`) перечисляет папки, и без заголовка сейв тоже грузится, но в
списках вместо `ROSTER1` стоит имя папки: проверено в игре. Лаунчер пишет заголовок такой же, как игра, с именем из раздела «Имя в меню».

В файле ростера нет имени пользователя и XUID: ни в обёртке, ни в базе, ни строкой, ни числом. Поэтому файл переносится между
ПК как есть, а XUID в папках один на всех ПК (`B13EBABEBABEBABE`, зашит в SDK).

### Как игра выбирает ростер

При запуске сценарий загрузки (`saveloadhelpers.big`) просит `AutoLoadMultipleGroupsFlow` с группой `ROSTERS`. Игра собирает список
сейвов группы (83253260, сравнение 83248B30): автосейвы первыми, дальше время из имени файла по убыванию, и грузит первый. В меню
порядок тот же: CUSTOMIZE → SAVE/LOAD/DELETE → LOAD → ROSTERS, столбец Last Modified — это время из имени папки, а не файла.
Имя папки — «ROSTER» и время UTC, как пишет игра (`%s %lld%s`, 83248F80). Лаунчер берёт текущее время, а если на ПК уже есть ростер
новее (часы разошлись), на секунду позже него. Поэтому после добавления грузится именно он.

Сохранение поверх строки в SAVE игра делает так: новая папка с новым временем, старая удаляется. Прежние ростеры в других строках
остаются, поэтому у пользователя их 12 с одним именем `ROSTER1`.

### Как игра проверяет ростер

Разбор кода, числа сверены на всех сейвах пользователя.

1. При запуске (82A07E58) таблицы базы получают места: `таблица 0x820574E0` в образе игры задаёт число для 35 таблиц, и
   если живых строк в базе не больше него, мест становится столько (827B9110). Если строк больше, остаётся то, что вышло при
   загрузке базы: строки + `maxinsert` из `nhlng-meta.xml`. У остальных четырёх таблиц группы — строки + `maxinsert`.
2. Менеджер сейвов считает размер группы `rosters` в памяти (827B8AA8, 82BB6D68): все 39 таблиц с их местами. Это и есть размер
   блока в файле, у ростера он равен разжатой базе + 4.
3. Сейв читается ровно на ожидаемую длину: размер группы + 0x1C (8324D128). Проверка 8324D1F0: подпись в первых 16 байтах,
   версия 0x14, CRC-32 в 0x10 по `[0x1C..ожидаемая длина)`, потом сумма блока 0x28 (82BBA660). Файл другого размера не сходится
   по CRC, это и есть окно «ROSTER1 appears to be damaged»: `SL_FILE_CORRUPT`, `Retry` возвращает к нему же, `Cancel` — на заставку.
4. Дальше игра разжимает базу и читает таблицы (82BB6F98, 827AE940), но результат не проверяет. Поэтому при верных суммах файла
   ошибка внутри сжатых данных или базы окна не вызывает.

По одному числу мест игра таблицы не сверяет, только общий размер (образец `bad_max_swap`). Лаунчер строже: сверяет каждую таблицу.
Такой файл игра сделать не может, а молча принятый сломанный ростер хуже отказа.

Отсюда прежние наблюдения ([kit-prune.md](kit-prune.md), [kitport.md](kitport.md)): 749 — число из кода, 60 — `maxinsert` таблицы
форм. Правило там записано как `max(749, строк + 60)`, точнее так: 749, если строк не больше 749, иначе строки + 60. У
`stockteamequipmenttable` числа мест 6000 и `maxinsert` нет, поэтому при 6292 строках мест 6292, а сейв с местом 6045 на базе с
6050 строками — «damaged».

### Что проверяет лаунчер

| Шаг | Проверка | Код |
|---|---|---|
| Вид файла | подпись `RosterFile` в первых 16 байтах; другие подписи называются по имени | 3, 4 |
| Обёртка | версия 4, блок 1/1, длина файла = 0x2C + область, сумма 0x10 (CRC-32 по `[0x1C..конец]`), сумма 0x28 (BZIP2 по области) | 5 |
| Сжатие | длина потока, заголовок zlib, нули после потока, inflate, Adler-32 | 5 |
| База | длина, хвост `DBDBDBDB`, разметка таблиц, все суммы TDB (CRC-32/MPEG-2), списки удалённых записей | 5 |
| Таблицы | все 39 таблиц группы, длина записи и поля как в `nhlng.db` | 6 |
| Места | `max` каждой таблицы по правилу выше: строки из `nhlng.db`, `maxinsert` из `nhlng-meta.xml` рядом с ней | 6 |
| Размер | вся база занимает столько, сколько ждёт игра | 6 |

Числа мест из кода игры записаны в `kRosterTables`. Они не поменяются, пока не поменяется сам `default.xex`.

### Что не проверяется

- Смысл данных. Игра его при загрузке тоже не проверяет: ростер с верными суммами и нелепыми ссылками между таблицами пройдёт.
- Файлы форм, голов и портретов. Если на другом ПК данные старее, а места таблиц совпали, ростер пройдёт, но сошлётся на то,
  чего там нет: будет пустая форма или чужая голова. Лаунчер сравнивает устройство таблиц, а не их содержимое.
- Сейв с приставки. Пакет `CON` лаунчер не принимает, внутренний файл надо сначала достать `tools/stfs.py`.
- Другой `default.xex`. Числа мест записаны из образа диска без обновлений, с другим exe правило надо сверять заново.
- Занятость игры определяется по имени процесса `nhllegacy.exe`, поэтому любая запущенная копия блокирует запись.

### Запись

Сначала файл и заголовок пишутся под временными именами, файл читается обратно и сравнивается. Потом заголовок получает своё
имя, последней переименовывается папка: SDK перечисляет папки, поэтому половину ростера игра увидеть не может. Временная папка
`…\454109EC\import.tmp` лежит рядом с `00000001`, а не внутри, иначе брошенную после сбоя папку игра показала бы как сейв.

### Образцы для проверки

`python tools/roster_samples.py make OUT ROSTER [--dynasty F] [--profile F] [--old F]` пишет хороший файл с меткой и все виды
испорченных, `check OUT LAUNCHER.exe` прогоняет их через `--check-roster` и сверяет коды, `plant SAMPLE USERDATA` кладёт
образец в копию сейвов мимо лаунчера, чтобы посмотреть реакцию игры. Папку `nhl-legacy-port/userdata` он не принимает.

### Проверено

Образцы — `tools/roster_samples.py`, файл кладётся в копию сейвов новее всех, чтобы игра взяла именно его (`nhl_save_trace`

Всё, что игра называет damaged, лаунчер не пропускает. Обратное неверно: последние пять файлов игра принимает молча, это испорченные
или ручные файлы, настоящий сейв таким не бывает.

Ещё проверено:

- из 13 ростеров с одним именем игра каждый раз брала самый новый по имени папки, в том числе только что добавленный;
- все 12 ростеров пользователя: суммы и сжатие сходятся у всех, подходит один новейший, остальные 11 отличаются числом мест, как и
  должно быть после смены формы и экипировки;
- чистая установка, папки сейвов нет: лаунчер создал её, игра завела новый PROFILE и открыла добавленный ростер, окна нет;
- папка `ROSTER …` без заголовка: грузится, в меню имя папки;
- два добавления в одну секунду, остаток `import.tmp` от сбоя, занятый путь заголовков, относительный и пустой `user_data_root`, нет
  базы, игра запущена: коды 0, 0, 9, 0, 8, 7, в папках сейвов ничего лишнего;
- `--print-command` с пустым именем: аргумента `nhl_user_name` нет, игра показывает `User`, настройки после него на месте.

Не проверялось: нажатие самой кнопки в окне и диалог выбора файла, там тот же код, что у `--import-roster`.

## Чего нет и почему

- частоты кадров и настоящего `vsync` порта: скорость игры привязана к гостевым 60 Гц, `vsync = false` её
  ускоряет; вместо него — «без разрывов» (флаги вывода кадра);
- произвольных размеров окна (только 16:9 из списка): `window_width`/`window_height` меняют и видеорежим гостя;
- ×3 и окна, кроме 1280×720, в игре не проверены — это опции для замеров по просьбе пользователя (12.10.2026);
- служебных `readback_resolve`, `nhl_composite_readback`, `nhl_fence_wait` и диагностики (`nhl_*trace`,
  `nhl_virtual_pad` …).

**В игре ещё не проверены:** FSR 1 / CAS, «без разрывов кадра», вибрация. Остальное — те же cvar'ы, что уже
стоят в `nhllegacy.toml` или проверялись агентами ([legacy-port.md](legacy-port.md)).

## Сборка

```bat
S:\Claude\megarohas_nhl13\nhl-legacy-port\launcher\build.cmd
```

MSVC из VS 2022 BuildTools, один файл `nhllegacy_launcher.cpp` → `nhl-legacy-port/out/launcher/nhllegacy_launcher.exe`
(не в git). Манифест Common Controls 6 — `#pragma comment(linker, …)` + `/MANIFEST:EMBED`, DPI — Per-Monitor V2
из кода; `.rc` иконки `build.cmd` пишет сам при сборке (в git его нет).

Снимок окна без показа пользователю (окно за пределами экрана, без активации, PrintWindow → PNG):
`nhllegacy_launcher.exe --shot=путь.png [--shot-hint=N] [--lang=en|ru] [--shot-relang=en|ru]` (N — номер
подсказки, 0 = «Рендер»; `--lang` — язык поверх сохранённого, `--shot-relang` — снимок после смены языка в окне).
Стенд — копия лаунчера в `nhl-legacy-port/out/launcher/test/` рядом с копией `nhllegacy.toml`. Собрать в другую папку, не трогая
`out/launcher`: `set NHL_LAUNCHER_OUT=<папка>` перед `build.cmd`.
`--print-command` печатает командную строку, с которой «Играть» запустит игру. Файл `launcher/roster_import.h` подключается к
`nhllegacy_launcher.cpp`, сборка та же.
