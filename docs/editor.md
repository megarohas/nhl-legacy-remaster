# Редактор игры: `nhllegacy_editor.exe` (`tools/editor`)

С 05.11.2026 (версия 0.18.1, доработки — 0.18.2). Одна программа рядом с игрой: открывает ассеты игры по разделам в понятном виде, показывает
картинкой (сетку — в 3D, песню — плеером), выгружает в PNG / OBJ / MP3, после правки в графическом редакторе загружает
новую версию обратно в формат игры. Там же — составы: карточка игрока, перевод в другой клуб, новый игрок, запись
новым ростером. Запрос пользователя: «объединить сделанный набор инструментов в один гейм-редактор, чтобы людям было
удобно менять внутренности игры, которые можно менять без изменения кода».

## Запуск

- **Из лаунчера:** кнопка «Редактор…» внизу, рядом со «Сбросить» ([launcher.md](launcher.md)). Язык — как у лаунчера.
- **Сам:** `nhllegacy_editor.exe` в папке игры (рядом с `nhllegacy.exe`), двойной щелчок. Ключи: `--lang=ru|en`,
  `--install ПАПКА` (другая папка игры), `--port N`, `--no-window` (только сервер, адрес — в выводе).
- **Из репозитория:** `python tools/editor --install nhl-legacy-port/out/build/win-amd64-release` (нужен Pillow; venv
  сборки — `game/work/editor/venv`).

Окно — Microsoft Edge (или Chrome) в режиме приложения: своё окно без вкладок и адресной строки, профиль браузера —
`cache\editor\browser` в папке игры. Закрыли окно — редактор завершился. Второй запуск открывает окно уже работающего.

## Почему так устроено

- **Python + наши модули в одном exe** (PyInstaller, один файл ~18 МБ). Форматы игры уже разобраны в `tools/`: RW4
  (`teamart.py`, `rw4mesh.py`), картинки меню BIGF/XPR2 (`playerhead.py`), архивы `.big` (`big.py`, `lzx.py`), база и
  сейвы с CRC (`tdb.py`), звук (`music.py`), составы (`roster/`, `legacy_data/roster_merge.py`). Редактор их не
  копирует, а вызывает: одна правда на формат. Python на ПК пользователя не нужен, ставить ничего не нужно.
- **Интерфейс — HTML в окне Edge**, а не Qt/Tk. Edge есть в каждой Windows 10/11, лишних библиотек нет. Таблицы
  составов, просмотр картинок с увеличением, 3D (WebGL) и плеер MP3 — средствами браузера. pywebview отпал: ему нужен
  pythonnet, под Python 3.14 он не проверен. Qt добавил бы к exe 60–100 МБ, Tk — без 3D и звука.
- **DXT через Pillow.** Кодеки на чистом Python у `teamart`/`kitpaint` точные, но медленные: свитер 1024² с мипами —
  минуты. Pillow (свободная лицензия MIT-CMU) жмёт и разжимает DXT1/3/5 и DXN (BC5) на C за доли секунды. Раскладка
  Xenos, мипы и упакованный хвост — `teamart.Layout`, как у всех инструментов.
- **Сервер только на `127.0.0.1`**: с других компьютеров к редактору не подключиться.

В exe нет файлов EA: только код `tools/`, интерфейс `tools/editor/web` и значок лаунчера. Оригиналы игра и редактор
читают с диска пользователя (`game\*.big`).

## Что откуда и куда

| Что | Где |
|---|---|
| читает | `content\my` → части `content` по `order.txt` → архивы диска `game\*.big` (так же ищет игра, [legacy-port.md](legacy-port.md) «Папка content») |
| пишет ассеты | **только `content\my\<путь игры>`**: файл там главнее нашего контента и архивов; части `content` и диск не трогаются |
| «Вернуть как было» | файл уходит из `content\my` в `cache\editor\backup\<время>\content\my\…` |
| перед записью поверх своей же правки | прежняя версия — в `cache\editor\backup\<время>\` |
| пишет составы | **новый** ростер `saves\rosters\ROSTER <время UTC>` с именем в меню `ROSTER ДД.ММ.ГГГГ`; прежние ростеры не трогаются |
| имена клубов, форм, игроков | новейший ROSTER (его грузит игра), без ростера — база `content\…\db\nhlng.db` |
| журнал | `cache\editor\editor.log`: запуск, каждая запись и откат |
| выбор пользователя | `saves\settings\nhllegacy_editor.json`: язык, последние папки выгрузки и импорта |

Пока запущена игра **из этой же папки**, редактор ничего не пишет: кнопки записи серые, в шапке «Игра запущена —
запись выключена». Игра из другой папки (стенд, вторая копия) запись не останавливает: у неё свои `content` и `saves`.
Проверка — по процессам `nhllegacy.exe` и пути их exe (Toolhelp32, без окна консоли).

## Картинки: выгрузка и импорт

- **«Выгрузить PNG»** — одна текстура в выбранный файл. **«Выгрузить всё в папку»** — все текстуры ассета в
  `<папка>\<клуб форма>\*.png` и `asset.json` (откуда каждая картинка и её контрольная сумма). Имена PNG — по растру:
  `jersey_2_14_5_cm.png` (свитер, цвет), `font_…_cm.png` (шрифт номеров), `name_…_cm.png` (карта номеров),
  `pant_…`, `sock_…`; у картинок меню — папка и имя файла (`teamlogos_t14.png`).
- **«Импортировать»** — выбрать картинку (PNG, JPG, BMP, TGA, WebP) или перетащить её на карточку текстуры.
  **«Импортировать папку»** — папку выгрузки: берутся только изменённые картинки (контрольная сумма из `asset.json` не
  сошлась), нетронутые не пережимаются; картинки не этого ассета перечисляются в отчёте.
- **Что делает импорт** (`tools/editor/tex.py`): размер и формат текстуры, имена растров, заголовки — как были, меняются
  только пиксели этой текстуры. Другой размер картинки подгоняется (Lanczos) с отметкой в отчёте. Мипы — вся цепочка:
  цвет — уменьшение с премножением альфы, нормали (DXN) — среднее X/Y; DXT5 с прозрачностью в RW4 (шрифты) — цвет под
  прозрачным от соседей (иначе тёмная кайма у краёв глифов, как объяснено в `kitpaint.py`); картинки меню (BIGF) — под
  прозрачным чёрный, как у EA (файл меньше). DXT1 с 1-битной альфой (`font_sm`) — кодек `kitpaint`.
- **Нормали (рельеф)** выгружаются как RGB: R = X, G = Y, B = восстановленная Z. При импорте берутся R и G.
- **Портреты**: самый большой портрет EA — 34 672 байта; больше — в отчёте предупреждение (`playerhead.MAX_ORIGINAL`).
- **Превью формы в меню пересобирается само** (с 0.18.2, `tools/editor/fepreview.py`): импорт свитера (`jersey_*_cm`)
  переносит в превью `jersey_S_A_F.big` разницу свитеров по модели позы EA (`tools/fepose.py`: пиксель превью p
  показывает точку развёртки uv(p) со светом gain(p), P' = P + gain·(T'(uv) − T(uv))). Неизменённое в свитере (воротник,
  щит, нашивки) остаётся в превью как было, перекрашенное перекрашивается с тем же светом — у форм Edge и NHL 27
  (снимок `game/work/editor/shots/08-fe.png`). Галочка «пересобирать превью при импорте свитера» выключает это;
  «Пересобрать превью в меню по свитеру» — заново от превью «как было»; превью можно и заменить своей картинкой.
  Модель позы выводится из арта EA, в git и в exe её нет: редактор ищет её как `content\uniforms\editor\fepose.bin`
  (кладётся при установке редактора, `game/work/legacy-data/fepose/pose.bin` — `tools/fepose.py fit`); нет модели —
  в отчёте «превью не пересобрано».
- **Новая форма на основе этой…** (`tools/editor/kitnew.py`) — копия формы под новым номером варианта той же длины
  (`2_14_5` → `2_14_4`): файлы комплекта с переписанными на месте именами растров — в `content\my`; строка
  `stockteamjerseys` (копия исходной: вариант, превью, следующий `jerseyindex`, не по умолчанию, подпись — дом, выезд,
  третья или винтаж с ключом `Vintage_S_A_V` в строках) — **в базу** (`content\my\db`, `draft_roster.db` из неё) **и в
  новый ростер** (сейв хранит формы сам; мест в таблице форм ростера `max(749, строк + 60)`, строка ложится в запас,
  размер сейва прежний). Шлем новой формы — общие строки клуба `stockteamequipmenttable` с вариантом −1: новых строк
  там не заводится, их число игра сверяет с ростером. Потом текстуры новой формы правятся как обычно.

## Модели (сетки)

«Выгрузить OBJ» — сетка в OBJ (`rw4mesh.export_obj`: метры, Y вверх, UV и нормали). Файл из нескольких подсеток (голова,
реквизит) — по OBJ на подсетку `<имя>_sub<N>.obj`. «Импортировать OBJ» — поправленный OBJ обратно (`rw4mesh.apply_obj`):
меняются только позиции точек, нормали и касательные поворачиваются вслед, индексы, UV, кости и веса — байт в байт.
Поэтому в Blender нельзя добавлять, удалять и сливать вершины, менять их порядок и превращать треугольники в
многоугольники: редактор откажет с причиной. 3D-окно: мышь — вращать, колесо — ближе/дальше. «Развёртка» — UV-сетка
поверх первой текстуры ассета.

## Музыка

Банк `audio/music` (`tools/music.py`, [music.md](music.md)): поток EALayer3 — это гранулы MP3, поэтому «Выгрузить MP3» —
без потерь и без ffmpeg. «Заменить…»: MP3 44,1 кГц стерео от LAME кладётся как есть (без перекодирования); другой файл
(WAV, FLAC, OGG, MP3 другой частоты) перекодируется ffmpeg — `ffmpeg.exe` рядом с редактором или в PATH, без него —
отказ с подсказкой. Новый банк (`music_samples.sbr`, `.sbs` ~290 МБ, `music_musicboxdata.bin`) пишется в
`content\my\audio\music`. **«Добавить песню…»** — новый слот EA Trax (следующий номер, до trax21: `music.py`
`Bank.add_trax` — новый id в `.sbr`, запись в `.bin`, id в список MenuTunes дерева выбора `music_graffitidata.bin`,
его редактор тогда тоже пишет). Обложка нового слота — `fe/ion/artassets/eatrax/e<N>.big` (у игры есть до e21),
меняется картинкой в «Обложки EA Trax». Проверка банка — `music.py --game legacy check content\my`.

## Тексты меню и шрифты

- **Тексты** (`tools/editor/texts.py`): все строки `fe/loc/nhl_<язык>.db` (25 958 у английского) — поиск по ключу и
  тексту, правка в таблице, «Записать правки». Правка, которая влезает в прежнее место строки, пишется на место; длиннее
  — новой строкой в конец пула (`locdb.LocDb.put`: другие ключи той же строки не меняются); нового ключа — запись по
  порядку hashid. Символ, которого нет в дереве Хаффмана файла, не записать — редактор скажет какой. Перед записью —
  `LocDb.check`, CRC — `Tdb.fix`. Файл — `content\my\fe\loc\NHL_ENG_US.db` (имя как у нашего контента).
- **Шрифты**: интерфейс игры рисует буквы TrueType на лету — атласа букв нет ([fe-fonts.md](fe-fonts.md)), поэтому
  «картинкой» показывается образец текста, а замена — своим TTF/OTF через `tools/fefont.py build`: «под метрики игры»
  (высота прописных и вертикальные метрики как у оригинала EA, набор символов тот же, недостающие — от оригинала) или
  «как есть» (`--keep`, TrueType того же unitsPerEm). Оригинал для метрик редактор берёт из архива диска.
  Результат — `content\my\fe\ion\fonts\<имя файла игры>`. Номера и фамилии на свитере — не эти шрифты, а текстура
  «Шрифт номеров» формы.

## Составы

Сверху — **что правим**: ростер (по умолчанию новейший; список — имя в меню и время папки) или **базу игры**
(последний пункт). Ростер игра грузит при запуске поверх базы — правка видна сразу. База — основа для новой франшизы,
нового профиля и SET DEFAULT ROSTERS; сохранённые ростеры от правки базы не меняются (поэтому в окне большая пометка,
что именно правится). Правки копятся в памяти (строка «Несохранённые правки»), **«Сохранить новым ростером»** /
**«Сохранить базу»** пишет всё разом, **«Отменить правки»** — забыть.

- **База** (`Session(…, '@db')`): та, что берёт игра (`content\my\db`, иначе `content\database\db`). Таблицы составов и
  свободных агентов переписываются ровно по записям (`Tdb.resize`: `max = current`, как у наших баз), CRC — `Tdb.fix`;
  пишутся `content\my\db\nhlng.db` и `draft_roster.db` из неё (`legacy_data/draft_roster.py`, старт «NHL Entry Draft»),
  прежние — копией в `cache\editor\backup`. Затем **новейший ростер сверяется с новой базой** лаунчером: игра сравнивает
  места таблиц сейва с базой, и если правка базы сломала бы сохранённые ростеры («damaged»), база возвращается как была.

- **Карточка игрока**: основное (имя, фамилия — латиницей без диакритики, как шрифт игры; номер; амплуа; хват; дата
  рождения; рост в дюймах, вес в фунтах; место рождения; буква C/A в этом клубе), стиль, все атрибуты 36–99 ползунками
  по группам, потенциал, внешность (голова, тон кожи, глаза, фото), экипировка (клюшка, загиб, обмотка, шлем, визор,
  краги, коньки, заправка…; у вратаря — щитки, блин, ловушка, маска), контракт и карьера (зарплата в $, годы,
  двусторонний, UFA, драфт, игры), **все поля как в базе** — для знающих таблицы. OVR — по формуле игры
  (`roster/ovrformula.py`), пересчитывается после «Применить»; поле `c_overall` ставится тем же числом (игра его не
  читает). Номер, занятый в клубе, не даёт: «номер 71 уже у …». Буква C у второго игрока снимается с первого.
  Полевого во вратаря и обратно не превратить: атрибуты в разных таблицах.
- **Перевод** (клуб → клуб, в свободные агенты и обратно; сборные, Матч звёзд, проспекты — нет): как у конвейера
  (`roster/write.py free_vacancy`). Места уходящего в звеньях, «одет» и буква достаются запасному того же амплуа с
  лучшим OVR; запасного нет — звенья клуба собираются заново по рейтингу (`roster/lines.py build`), буква — самому
  опытному. В новом клубе игрок в запасе, номер прежний или ближайший свободный, контракт едет с ним; в клуб НХЛ без
  контракта — минимальный на год (850 000 $, как `roster_update.py`). В свободные агенты — контракт снимается.
  Больше 40 игроков в клубе нельзя.
- **Новый игрок** занимает пустой слот создаваемых игроков (связи 16000+ с `table` = 1, у вратаря — вратарский слот;
  так делает и CREATE PLAYER игры) и встаёт в запас выбранного клуба. Атрибуты — ровные под заданный OVR, дальше —
  в карточке. Имя, дата рождения 22 года назад, рост 6'1", вес 195 фунтов — правятся в карточке. Проверено в игре:
  поставленный в первое звено MIN «Newguy Editorplayer» — в стартовом составе (`N. EDITORPLAY… #16 C`) и на
  вбрасывании в матче.
- **«Поменять местами в звеньях с …»** — два игрока клуба обмениваются местами всех 71 позиции и «одет» (буквы —
  как были; вратарь — только с вратарём), как «поменять» в EDIT LINES. **«Звенья по рейтингу»** — все звенья клуба
  заново (`roster/lines.py build`: 4 тройки, 3 пары, спецбригады, 2 вратаря, 20 одетых).
- **Названия вместо кодов**: страна и место рождения (провинции Канады и штаты США) — по шкале `roster/codes.py`;
  клюшка, краги, шлем, коньки, вратарская — по каталогам редактора игры (`default.xex`, таблицы
  `tools/unlockables.py CATALOGS`: номер записи = значение поля игрока) с названиями из строк игры (наши переименования
  клюшек тоже). Каталог разжимается из `default.xex` один раз в фоне (~25 с, `tools/xex.py`), в кэше
  `cache\editor\catalogs.json` — только номера и названия.
- **Новый клуб…** — свой клуб на свободном слоте Custom Team (строки `exhibitionteams` с `table` = 1, лига 13 «Свои
  команды» — те же, что у CREATE TEAM игры): название, сокращение, цвета, `active` = 1. Игроков — переводом (нужно
  2 вратаря и 18 полевых), потом «Звенья по рейтингу». Форма и логотип такого клуба — конструктора игры
  (`customteamjerseys`, `czlogo`): рисуются в игре, CUSTOMIZE → Creation Zone → Edit Team. Клуб в своей лиге играет
  выставочные матчи; войти в НХЛ/АХЛ или другую лигу с календарём без кода нельзя: число клубов лиг зашито в коде
  (НХЛ и АХЛ на 32 сделаны врезками порта, [legacy-port.md](legacy-port.md) «НХЛ на 32»), а логотипы, арена и форма
  «как у настоящих» требуют `table` = 0, своих `artid`/`teamartid`, строк форм и экипировки — это путь
  `tools/nhl32.py` / `tools/utah`, не редактора.
- **Запись**: записи состава и свободных агентов переписываются как у игры (`roster_merge.write_table`: [0, current) —
  записи, запас — 0xDB), места таблиц (`max`) и размер файла не меняются — поэтому игра не скажет «damaged». Перед
  записью: суммы базы и обёртки, места каждой таблицы как у исходного ростера, размер, затем
  `nhllegacy_launcher.exe --check-roster` (строгая проверка лаунчера, [launcher.md](launcher.md)). Не прошло — не
  пишется ничего. Папка — `ROSTER <время UTC>`, не раньше новейшего + 1 с, поэтому игра загрузит именно её.
- **«Выгрузить файл ростера»** — копия открытого ростера в файл `ROSTER ДД.ММ.ГГГГ` (дата в имени — имя в меню на другом
  ПК). **«Загрузить файл ростера…»** — то же, что «Обновить ростеры» в лаунчере (`--import-roster`).

## Сборка

```bash
bash tools/editor/build.sh       # → nhl-legacy-port/out/editor/nhllegacy_editor.exe, ~20 с
```

Окружение — `game/work/editor/venv` (создаётся само: Python 3.14, `pip install pyinstaller pillow`). Иконка —
`nhl-legacy-port/launcher/icon/nhllegacy.ico` (`tools/make_icon.py`), версия в свойствах файла и в окне — `VERSION`.
`scripts/make_dist.sh` (и поэтому `tools/device_release.sh`) кладёт exe в папку релиза рядом с лаунчером.

Код: `tools/editor/` — `app.py` (сервер, выгрузка/импорт), `gamefs.py` (поиск файлов по слоям и архивам, запись в my,
игра запущена?), `tex.py` (текстуры), `catalog.py` (разделы и имена), `gamedb.py` (имена из ростера и базы),
`rosters.py`, `meshes.py`, `audio.py`, `winui.py` (диалоги Windows через ctypes), `web/` (интерфейс). Ссылка
`…/?lang=ru#open=<ассет>` открывает ассет сразу (`kit:30:2_100_2_2`, `photo:<game_id>`, `rosters&team=30&gid=4166`) —
так сделаны снимки ниже (Edge без окна, `--headless --screenshot`).

## Ограничения

- Новая форма — копией существующей (тот же стиль, клуб, номер варианта той же длины, ≤ 32 форм у клуба); новый
  стиль или номер арта другой длины — `tools/kitport`, `nhl24.py alloc`.
- Ролики меню (Apt) без картинок XPR2 показываются только как файл.
- Клуб в лиге с календарём (НХЛ, АХЛ, Европа) — только кодом и конвейером (выше, «Новый клуб»).
- Сетка: только сдвиг точек, новую геометрию не загрузить (это ограничение формата импорта `rw4mesh`).
- Вратарская экипировка и маски у вратаря при переводе — как были; командный набор вратаря — `goalie_gear.py`.
- Маски вратарей, тон кожи, цвет глаз в карточке — числами (каталога с названиями у игры нет).

## Грабли

- Лаунчер до 0.18.1 сверял ростер с `userdata\cache\guest\db`, на чистой папке 0.17.0+ (ноутбук) — код 8 «нет базы».
  С 0.18.1 — с базой, которую берёт игра: `content\my\db`, потом части `content`.
- Сетки голов: 5 подсеток на два объявления вершин не по порядку; прежний `rw4mesh.Mesh(sub=k)` брал объявление по
  номеру и падал на подсетках 1, 3, 4.
- PyInstaller `--windowed`: ошибка при запуске показывается окном Windows; журнал — `cache\editor\editor.log`.
- Окно Edge в режиме приложения: без `--disable-background-mode` браузер со своим профилем может остаться жить после
  закрытия окна, а свёрнутое окно через 5 минут замедляет таймеры до раза в минуту. Поэтому браузер запускается без
  фонового режима и без замедления таймеров, а редактор выходит, когда процесс браузера закончился и страница 5 с не
  пингует (или 3 минуты тишины при живом браузере).
- `PrintWindow` у окна Edge даёт белый кадр (композиция на GPU): снимки интерфейса — Edge без окна (`--headless
  --screenshot`, ссылка `#open=…`).
