# Конвейер составов: рейтинги по статистике, свободные агенты, тон кожи, лиги, фото не из НХЛ

Дополнение к [roster-pipeline.md](roster-pipeline.md) (8.10.2026). Всё новое — флагами и
отдельными модулями `tools/roster/`; прогон без флагов даёт прежнюю базу байт в байт (проверено:
`all --offline` для `nhl32-custom` и `--ahl32` для `nhl32-ahl32` — побайтно равны копиям в
`game/work/backup-before-roster-expansion/`).

```bash
python tools/roster fetch --only fa,liiga                 # данные новых частей (кэш roster-cache/)
python tools/roster all --offline --stats-ratings --fa --skin --league liiga \
       --db-in game/work/nhl32-custom/nhlng.db --work roster-custom
python tools/roster photos --work roster-custom           # фото не из НХЛ → кадр НХЛ (сеть, ~3 с на игрока)
                                                          # и сборка p<artid>.big → game/work/photos-other/roster-custom/
python tools/photos.py build --work game/work/roster-custom   # или как раньше — всё в photos-all (docs/player-photos.md)
```

| Флаг / этап | Модуль | Что делает | Отчёт |
|---|---|---|---|
| `--stats-ratings` (build) | `statsrating.py` | OVR по статистике трёх сезонов с NHL-эквивалентами лиг | `report-ratings.md` |
| `--fa` (fetch, build, write) | `fa.py` | реальные свободные агенты → `exhibitionfreeagents` | раздел в `report.md` |
| `--skin` (write) | `skin.py` | типовая голова под тон кожи на официальном фото | `skin-sheet.html` |
| `--league liiga` (fetch, build, write) | `league.py` | клубы SM-liiga (74–87) — нынешними составами Liiga | `report.md`, `report-ratings.md` |
| `photos` (отдельный этап) | `photos_other.py` | портреты лиг и NHL latest → кадр портретов НХЛ | `photos-sheet.html` |

Попутно: адреса Wikipedia в `fetch.py` и `ahl.py` — `/wiki/<статья>?action=raw` вместо
`/w/index.php?…` (robots.txt Wikipedia закрывает `/w/` для всех роботов, `/wiki/` открыт; кэш тот же).

## 1. Рейтинги по статистике (`--stats-ratings`)

**Источник** — карточка `api-web.nhle.com/v1/player/{id}/landing`, поле `seasonTotals`: каждый
сезон каждого клуба в любой лиге (НХЛ, АХЛ, КХЛ, SHL, Liiga, NL, DEL, Extraliga, NCAA, OHL/WHL/QMJHL,
USHL, MHL, J20…; у вратарей — % отражённых). Это и есть централизованный бесплатный источник: он
есть у всех, кого знает НХЛ (игроки, задрафтованные, проспекты, игроки АХЛ с ID НХЛ), уже лежит в
кэше и повторно не скачивается. У кого ID НХЛ нет (игроки лиг из `--league`), — статистика сайта
лиги в том же виде. EliteProspects (платный API) не используется.

**Производительность P** (полевые): регулярные чемпионаты 2023/24, 2024/25, 2025/26 (турниры
сборных, кубки и плей-офф — нет), очки за игру × NHLe лиги, среднее по играм с весами сезонов
0,35 / 0,6 / 1,0, сжатие к уровню запасного (20 взвешенных игр с P0 = 0,22 у нападающих, 0,12 у
защитников). **Опыт E** = игры в НХЛ за три сезона / 150 (не больше 1).

**NHLe** (очки в НХЛ на очко в лиге; `statsrating.NHLE`) — консенсус опубликованных таблиц и
своей проверки:

|---|---|---|---|---|---|

| SHL | 0,62 | 0,64 | — | 0,78; Turtoro ≈0,57 | 0,64 (19), SEL до 2013 — 0,74 (9) |

Прочие: Allsvenskan, VHL, Словакия 0,30; ICEHL 0,33; ECHL, Чехия-2 0,22; Mestis 0,18; SL, DEL2,
Норвегия, Дания, Франция, Беларусь 0,20; MHL 0,13; J20 Nationell, U20 SM-sarja 0,11; BCHL 0,10;
NAHL, AJHL 0,08; OJHL и др. 0,07; DNL 0,05. Старые названия лиг в карточках (Sweden, Finland,
Russia, Swiss, H-East, WCHA, USDP…) — `statsrating.ALIAS`. «Своя проверка» — переходы «лига → НХЛ
в следующем сезоне» (≥ 20 игр в лиге, ≥ 30 в НХЛ) у игроков нынешних составов, отношение очков за игру
(как у Desjardins; смещено выживаемостью — остались те, кто прижился). Сетевые оценки (Turtoro,
hockeystats) у юниоров вдвое ниже прямых: они меряют лигу, а не тех, кто из неё сразу перешёл; общий
масштаб NHLe модель всё равно калибрует по рейтингам EA (ниже), важны отношения лиг. Источники:
[hockeystats.com/methodology/nhle](https://hockeystats.com/methodology/nhle),
[Rethinking NHLe](https://thibaudchatel.substack.com/p/rethinking-nhle),
[Revisiting NHLe part 2](https://thibaudchatel.substack.com/p/revisiting-nhle-part-2),
[An argument for NHLe](https://flamesnation.ca/news/an-argument-for-nhle).

**Модель OVR** — наименьшие квадраты по всем игрокам составов с рейтингом NHL 27 (EA и
nhlratings.net; у nhlratings.net и EA OVR совпадает: медиана разницы 0, |разница| ≤ 1 у 115 из 161
нападающего; у вратарей хуже — вес их nhlratings.net 0,7):

| Амплуа | Формула | Коэффициенты (8.10.2026) | Игроков | Средняя ошибка | Из них < 40 игр НХЛ |
|---|---|---|---|---|---|
| нападающие | a + b·P + c·P² + d·E + e·E·P | 67,94; 21,76; 1,78; 8,95; −8,97 | 443 | 1,3 | 28 игроков, 1,9 |
| защитники | то же | 69,63; 22,74; −6,67; 7,95; −0,03 | 235 | 1,8 | 19, 1,7 |
| вратари | a + b·E + c·sv + d·E·sv (sv — % отражённых выше лиги, пункты, × переносимость лиги) | 78,03; 8,37; −0,02; 3,53 | 64 | 2,4 | 6, 4,1 |

Член d·E — «скидка новичку»: при той же результативности EA ставит новичку меньше, чем ветерану
НХЛ (E = 0: P 0,5 → 79; E = 1: P 0,5 → 84). Модель вратарей держится почти только на опыте в НХЛ
(% отражённых в рейтинге EA почти не виден) — поэтому у вратарей и смешивание слабее.

**Как сочетается с имеющимися** (`statsrating.apply`):
- EA (топ-300, все атрибуты) и nhlratings.net с атрибутами — как есть;
- «только OVR» (nhlratings.net, EA): 100+ игр в НХЛ за три сезона — как есть; иначе
  `nr + w·(оценка − nr)`, w = 0,5·уверенность (вратари 0,25·уверенность);
- рейтинга нет — `уверенность·оценка + (1 − уверенность)·прежняя оценка` (прежняя — 25-й
  перцентиль амплуа ± возраст, у АХЛ — уровень АХЛ, у клубов лиг — уровень лиги в базе).
Уверенность = игры / (игры + 25) (взвешенные, лиги с NHLe ≥ 0,2; вратари — / (игры + 30)).
Атрибуты достраиваются из OVR как раньше (`ratings.Model.attributes`: форма стиля/амплуа + сдвиг к
OVR); OVR игры по атрибутам (формула NHL 13, восстановленная регрессией по исходной базе: R² 0,998 у
центров, 0,975 у крайних, 0,969 у защитников, 0,960 у вратарей) совпадает с записанным `p_overall`
(у Канцерова 77,8 при 78).

**Результат** (обычный режим, `report-ratings.md`): изменено 123 игрока — 56 без рейтинга и 67
малоопытных «только OVR»; EA, nhlratings.net с атрибутами и 212 опытных — без изменений. Примеры:

## 2. Свободные агенты (`--fa`)

**Кандидаты** — все, кто играл в регулярке НХЛ 2024/25 или 2025/26 (stats REST `bios` за оба
сезона, поле `currentTeamAbbrev`), а сейчас клуба нет и в составах их нет: 169. **Проверки**:
1. карточка landing — нет клуба; нет строк сезона 2026/27 в другой лиге (КХЛ, Европа, АХЛ — сезоны
   там начались); прошлый сезон не только в Европе/КХЛ; `isActive` не годится — у всех без
   контракта НХЛ он false;
2. Wikipedia — раздел «Last games» статей «2024–25 NHL season» и «2025–26 NHL season» (известные
   завершившие карьеру: Копитар, Тэйвз, Куик, Флёри, Пачиоретти…) и карточка игрока
   (`{{Infobox ice hockey player}}`): `career_end` заполнен — завершил карьеру; `team = Free agent` —
   подтверждение; другой клуб — подписан;
3. не старше 40 лет, не меньше 10 игр в НХЛ за два сезона.

**Итог 8.10.2026**: 39 свободных агентов (37 подтверждены `team = Free agent` в Wikipedia, у 2 статьи
нет): Тарасенко, Друэн, Курашев, Эвандер Кейн, Перрон, ван Римсдайк, Нюквист, Рейлли Смит, Энрике,
Дадонов, Пирсон, Саад, Дамба, Ледди, Петри, Лайне, Мразек, Георгиев, Раймер… Отсеяно 130: в 2026/27
уже играют в другой лиге — 82, завершили карьеру — 23, меньше 10 игр — 17, клуб по Wikipedia — 3,
прошлый сезон только в Европе/КХЛ — 3, старше 40 — 2 (весь список с причинами — в `report.md`).
Ручные поправки — `game/work/roster/fa-overrides.json`: `{"exclude": {"<NHL ID>": "причина"},
"include": {"<NHL ID>": "причина"}}`.

**В базе** — как 183 свободных агента исходной: `team` 0, `proteam` 0, контракта нет
(`contractstatus`, сумма, срок — 0), `yearufa` = 126 (2026); связь — в `exhibitionfreeagents`
(по возрастанию, как в исходной), в составах их нет (проверка `verify`). 22 из 39 узнаны в базе 2012

## 3. Тон кожи (`--skin`)

**Правило**: тон определяется **только** по видимому цвету кожи лица на официальном портрете
(`roster-cache/photos/20262027/<id>.png`); имя, страна, гражданство, место рождения нигде не
используются. Нет фото — как раньше (голова самого частого тона базы по хэшу имени). Поправки —
`game/work/roster/skin-overrides.json` (`"<NHL ID>": {"skin": 1|2|3|4|6|9|10}` или `{"head":
<headid>}`), проверка — `skin-sheet.html` в папке конвейера: портрет рядом с иконкой выбранной
головы игры, замер, отметка «проверить».

**Шкала игры.** `skincolor` (4 бита) у каждой типовой головы (`headid` 10000+, 173 головы в базе)
постоянный: 1 (70 голов, светлые), 2 (42, светлые и смуглые), 3 (33, от светлых до
оливково-коричневых), 4 (17, оливковые), 6 (6, светло-коричневые: 10090–10093, 10148, 10181), 9
(3, коричневые: 10094–10096), 10 (2, тёмные: 10097, 10099); 5, 7, 8 не встречаются. Как голова
выглядит, видно по иконке `fe/ion/artassets/createplayer/head/head<id>.big` (`k_8_8_8_8` 256×128,
тайлинг Xenos, 8in32 — декодер `skin.decode_icon`; PNG — `roster-cache/skin/icons/`). Сканы EA
(`headid` < 10000, 269 голов) не трогаются. Раньше всем 652 новым игрокам доставалась голова тона 1.

**Замер** (`skin.photo_tone`): прямоугольник лица (лоб — глаза — щёки до рта; по макушке, центру и
ширине головы из альфа-канала), пиксели, похожие на кожу (CIELAB: L* 12–92, насыщенность ≥ 7, тон
12°–85°: без серых и чёрных волос, бороды, белков, зубов), средняя половина по светлоте; тон —
**ITA°** = atan((L* − 50) / b*) (Chardon 1991; > 55 очень светлая, 41–55 светлая, 28–41 средняя,
10–28 смуглая, −30…10 коричневая, < −30 тёмная). Русые и каштановые волосы по цвету похожи на
смуглую кожу: если нижняя половина прямоугольника (щёки, нос) после поправки на съёмку светлее всего
прямоугольника на 12°+ и сама светлая (≥ 35°), лоб закрыт волосами или тенью — тон берётся по ней
(с поправкой на обычную разницу половин: −2,74 L*, −0,38 b*, медианы по 837 фото НХЛ) и ставится
«проверить» (8.10.2026 так у 27 портретов, например Тейдж Томпсон, Алекс Бамп, финн Вяаряля: без
этого — коричневая голова у светлокожих).

**Поправка на свет съёмки.** Медианы ITA портретов клубов расходятся от 21,5° (FLA) до 63,4° (BOS)
— это свет и баланс белого съёмки, а не составы. Поэтому L* и b* сдвигаются на разницу «эталон
съёмки − общий эталон» (эталон — 60-й перцентиль L* и 40-й b* всех фото той же съёмки: папка адреса
фото, сезон/клуб; меньше 8 фото — эталон клуба 2026/27 или без поправки).

**Тон игры** по ITA после поправки (x): ≥ 42 → 1; 30–42 → 2; 21–30 → 3/4; −10…21 → 6, но при
розоватом тоне (угол цвета < 45° — румянец/загар светлой кожи) → 3/4; −20…−10 → 9; < −20 → 10.
Голова внутри класса — из 5 ближайших по ITA иконки к «цели» (ITA фото в шкале иконок: прямая через
медианы фото и иконок класса 1, наклон ≈ 1,55 — по сопоставленным игрокам с тёмными головами EA), по
хэшу имени. По одним иконкам класс не выбрать: у оливковой головы в тёмном рендере (10178) и
светло-коричневой (10181) ITA иконки одинаковые (около −3°). **Проверить** — x в 10–30° (там рядом
смуглые фото светлокожих при тёплом свете и коричневая кожа) или розоватый тон при x < 26°.
Сопоставленным игрокам голова EA оставляется; заменяется, только если класс по фото дальше чем на 2
ступени (1 · 2 · 3/4 · 6 · 9 · 10) и замер уверенный — 8.10.2026 это один игрок.

**Итог 8.10.2026** (обычный режим): новых по фото 652 (из них «проверить» 31), без фото — 0 (6
портретов «latest» докачал этап `photos`); у новых теперь тон 1 — 519, 2 — 107, 3 — 8, 4 — 5, 6 — 11,
10 — 2 (было 652 × тон 1); у сопоставленных голова EA заменена одна (Назем Кадри: голова 10181 тона 6,
по фото — светлый). Со всеми флагами (`roster-expanded`, ещё Liiga и свободные агенты): новых по фото
1038 (проверить 42), без фото 8. Оставшиеся спорные — на границе 6 и 3/4 (смуглые светлокожие → 6,
коричневая кожа → 3/4), все с отметкой «проверить». Проверка метода
глазами на 160 самых тёмных по замеру портретах: все заметно смуглые/коричневые/тёмные — среди первых
23 (с поправкой на съёмку; без неё — нет), среди них 9 светлокожих при тёплом свете; на 80–160 — только
светлые. Ограничения: портреты — студийные, но свет разный; бороды и тени дают ±5°; классы 1–4 в
игре не упорядочены по тону строго (EA раздавала их не только по тону), поэтому граница 1/2/3/4 —
условная, грубые ошибки (светлый ↔ коричневый) — в зоне «проверить».

## 5. Фото не из НХЛ (`python tools/roster photos`)

**Источники**: NHL `assets.nhle.com/mugs/nhl/latest/<id>.png` — у игроков с ID НХЛ, у кого по адресу
из карточки фото нет (АХЛ, проспекты); портреты лиг (Liiga `pictureUrl`). Пауза ≥ 1 с, кэш
`roster-cache/photos/<источник>/…`, «нет фото» запоминается (`.none`). У всех найденных официальных
портретов лиг (Liiga, SHL, hokej.cz, DEL) фон уже прозрачный (вырезка) — удалять фон не нужно.
Фото АХЛ (`assets.leaguestat.com/ahl/240x240/{id}.jpg`, JPEG на сером фоне) — ID только через фид
HockeyTech с ключом, в статьях Wikipedia игроков HSK/CV `{{AHL profile}}` нет; JPEG стандартная
библиотека не читает (перевести в PNG можно .NET `System.Drawing` из PowerShell), фон пришлось бы
вырезать заливкой от краёв — не делал, раз источника без ключа нет. Wikimedia Commons — снимки с
матчей под CC BY/BY-SA (атрибуция, проверка каждого файла), для портретов малопригодны.

**Кадр** (`photos_other.to_nhl_frame`): по альфа-каналу — макушка, «шея» (самая узкая строка между
головой и плечами) и центр головы; масштаб — среднее геометрическое «макушка — шея» и ширины головы
к медианам портретов НХЛ (60 фото: макушка 72, «макушка — шея» 129, центр 167,5, ширина 106,5);
холст 336×336 с макушкой и центром как у НХЛ. Результат — `photos/20262027/<nhl_id>.png` (рядом с
фото НХЛ: `tools/photos.py build` собирает его как обычное), список — `photos/20262027/_other.json`.
Этап сразу собирает оба размера `p<artid>.big` (как `photos.py build`, DXT5, шаблон EA) в
`game/work/photos-other/<папка конвейера>/fe/…` — не в `photos-all`, которую ставят `install-*.sh`: у
новых игроков (свободные агенты, Liiga) artid записаны в `artid-registry.json` своей папки и в другой
папке могут быть другими. `hasportrait` 1 таким игрокам ставит, как обычно, `tools/photos.py db` после
`photos.py build` в той же папке. Лист `photos-sheet.html`: исходник → кадр НХЛ → сцена большого
портрета игры (`playerhead.compose`; сцена — у первых 80, у остальных — исходник и кадр).
