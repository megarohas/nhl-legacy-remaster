# Редактор команд (Create a Team / Edit Team): как устроен и как дать ему любые команды

Разбор 08.10.2026 по диску без TU2: скрипты меню (Apt из `boot.big` / `cache.big`; свой дизассемблер —
`game/work/team-editor/scripts/aptdis.py`), восстановленный код порта (`port/generated/default`), исходная
база `game/extracted/big/cache/db/nhlng.db` и рабочая копия `game/work/nhl32-ahl32/nhlng.db` (только чтение).
**Порт, база, `game/userdata` не менялись; в игре ничего не проверялось.**

Пометки: **[код]** — прочитано в коде или скриптах; **[пред.]** — вывод по косвенным признакам, проверить.
Адреса — PPC-образ (`sub_XXXXXXXX` в `port/generated/default`).

## Коротко

- Список в «Edit Team» ограничивает **только скрипт меню**: `cp4_editplayer.big` берёт лигу
  `League.eFilter.FILTER_CREATE_TEAM` (лига 13) и показывает её команды. Код игры (`SetActiveTeam`) загружает
  в редактор **любую** команду: строку `exhibitionteams`, состав, цвета экипировки (у обычной — из
  `stockteamequipmenttable`). **[код]**
- Но **сохранение** (`SubmitTeam` → `sub_8283F468`) написано под Custom Team. У обычной команды оно:
  переделает её арену в общую «EA SPORTS Arena» (модель 255, звук 255, линия 0, город = город команды);
  сменит лицо тренера (`coachheadid = 30000 + номер % 20`); перестроит звенья. А выбор логотипа запишет в
  `artid` номер логотипа конструктора (20001+), и у команды пропадут логотипы, центр льда, шайба и все
  текстуры формы. **[код]**
- Сами настройки формы (рисунок, шрифт, шорты, гетры) сохранятся в поля `exhibitionteams`, но обычная
  команда (`table = 0`) рисуется из `stockteamjerseys` и готовых текстур, так что игра их **не заметит**.
  Цвета и комплекты пишутся `update`-ом в `customteamequipmenttable` и `customteamjerseys`, а там есть строки
  только для 218–247. Для обычной команды они **никуда не попадут**. **[код]**
- Матч выбирает «форму конструктора» функцией `sub_8328CFB8`: глобальный флаг или поле +94 = `table`. Её
  вызывают 18 мест: форма, шорты, гетры, номера, шлем, центр льда. Значит, путь конструктора можно включить
  **только для формы**, а лёд, шайбу, логотипы, арену и названия оставить родными (вариант Б). **[код]**
- **Рекомендация — «форма-донор» (вариант Б).** Форму рисуют во встроенном редакторе на свободной Custom
  Team (сейчас 222–247). Порт надевает её на выбранную обычную команду: врезки только в отрисовку, редактор и
  сохранение не трогаются, база не меняется. Порядок: Б1 — отрисовка (2–3 дня + 1 день на франшизу),
  Б2 — свой герб на груди (2–3 дня), Б3 — чтобы в «Edit Team» выбиралась сама «Питтсбург», а донор
  подставлялся незаметно (3–5 дней).
- Запасной путь без правок порта (вариант Г): по дизайну донора `tools/czkit.py` запекает текстуры
  обычной формы команды под её же именами в `cache:`.

## 1. Как устроен редактор

| `boot.big` `fe/ion/main.big` | перечисления (`game/work/team-editor/apt/main_enums.json`) |

Как идёт работа:

1. **Create Team:** если `ION_NhlCreateTeam.CanCreateNewTeam()`, то
   `gSLM.EnterModeCheck(…, SaveLoad.eSaveGroupType.ROSTERS)`, хаб и `ION_NhlCreateTeam.CreateTeam()`. Иначе
   всплывает `TXT_MAXIMUM_LIMIT_OF_CREATED_TEAMS`.
2. **Edit Team** (`cp4_editplayer`, `screenType = EDIT_TEAM`):
   ```
   league = ION_League.GetIDs(League.eFilter.FILTER_CREATE_TEAM, SORT_NONE, SORT_UNSORTED)[0]
   teams  = ION_Team.GetIDs(league, Team.eFilter.FILTER_UNFILTERED, SORT_NONE, SORT_UNSORTED)
   ```
   Шапка с переключателем лиг скрыта (`mcHeader._visible = false`). В режиме Edit Player та же `getTeams`
   берёт лигу из `mcLeagueToggle`, поэтому там доступны все лиги. Затем
   `ION_NhlCreateTeam.SetActiveTeam(TEAM_ID)` и хаб с тремя вкладками: `CT_TEAM_ROSTER`,
   `CT_UNIFORM_SUBMENU`, `CT_TEAM_INFO`.
3. **Сохранение:** `SubmitTeam()` возвращает `RESULT_SUCCESS` либо `RESULT_FAILURE` с текстом ошибки. Затем
   сохраняется группа `ROSTERS`, то есть файл составов.

Значения перечислений: `Team.eFilter` — 0 `UNFILTERED`, 1 `CUSTOM_TEAMS`, 2 `FREE_AGENTS`, 3 `DYNASTY`, …,
14 `FRANCHISE`. `League.eFilter.FILTER_CREATE_TEAM` = 1. `CreateTeam.eSetting`: 0 `INFO_NAME`, 1 `INFO_CITY`,
2 `INFO_ORIGIN`, 3 `INFO_ABBREVIATION`, 4 `UNIFORM_LOGOS`, 5 `…_LOGOS_COLOURS`, 6 `UNIFORM_JERSEYS`,
7 `…_JERSEY_COLOUR`, 8 `UNIFORM_SOCKS`, 9 `…_SOCKS_COLOUR`, 10 `…_GLOVES_COLOUR`, 11 `UNIFORM_PANTS`,
12 `…_PANTS_COLOUR`, 13 `UNIFORM_FONT`, 14 `…_FONT_COLOUR`, 15 `…_HELMET_COLOUR`, 16 `…_TRAPPER_COLOUR`,
17 `…_BLOCKER_COLOUR`, 18 `…_PADS_COLOUR`, 19 `…_PREVIEW_OPTIONS`.

### 1.3. Модель данных редактора [код]

`sub_827A8880()` возвращает `[0x83981B68]`, объект `CustomDataBrain` (12 байт, таблица `0x82038930`). Его

слотов). Блок данных лежит по указателю +4 мозга:

| Смещение | Что |

| +200 | запись арены (`exhibitionarena`) |
| +744 | копия первых 744 байт на момент загрузки (`sub_82823BE0`) — для «Отменить» |
| +3180 | состав: число игроков в +3181, номера с +3182 |
| +6424 | записи игроков по 456 байт; позиция в +121 (4 — вратарь) |
| +24664 / +24668 | число вратарей и полевых |
| +24700 | 1 — открыта существующая команда, 0 — новая |

Настройка редактора → номер поля модели (`sub_829642D0`): 0 → 0 (`fullname`, +18), 1 → 3 (`shortname`,

### 1.4. Открытие и новая команда [код]

- **`SetActiveTeam(id)`** (`sub_82984700`): режим зоны 12 (13 — для `id = −5`; [пред.] форма онлайн-клуба).
  Мозг, слот +40 (`sub_827A8F68`), вызывает `sub_82849218(data, id)`: состав (`sub_82820438`), игроков,
  строку `exhibitionteams[id]` и цвета экипировки дом/выезд (`sub_8282F530`). Цвета берёт кэш `sub_8280DE78`:
  у `table = 1` — `customteamequipmenttable` (во франшизе — `leaguecustomteamequipmenttable`), иначе —
  `stockteamequipmenttable`; если у команды строк нет, подставляются общие (`team = −1`). Проверки, что
  команда — Custom Team, **нет**.
- **Новая команда** (`sub_8298D598`, мозг +36 → `sub_827A8F08` → `sub_82849180`): свободная строка — первая с
  `active == 0` (`sub_828FB5A8`: `SELECT index FROM exhibitionteams WHERE active == 0`). Если таких нет,
  берётся 218 и возвращается ошибка. Затем строка читается как шаблон, и `sub_828449C8` ставит значения
  по умолчанию. `table` и лига не проверяются. Сейчас неактивны только заготовки: 222–247 в режиме
  `--ahl32` и 220–247 без него (`table = 1`, лига 13). **Если когда-нибудь обнулить `active` у обычной
  строки, «Create Team» займёт её.**

### 1.6. Где хранятся созданные команды

- Прямо в базе: строки `exhibitionteams` 218–247 (`table = 1`, лига 13, `artid` 20001+L, арена 168),
  `customteamjerseys` (60 строк, `teamartid` 20054), `customteamequipmenttable` (660 строк),
  `custompalettetable`. У этих таблиц группа сохранения `rosters`, они только обновляются (вставки нет) и
  пишутся списком отличий (`difflistproperty="ENABLED"`). Значит, созданные команды живут **в файле
  составов**. Отдельного файла «Custom Teams» нет. **[код + nhlng-meta.xml]**
- **Франшиза:** при создании лиги `sub_82905418` копирует строку команды в `leagueteams`. Если у строки
  `table = 1`, вместе с ней копируются `customteamequipmenttable` → `leaguecustomteamequipmenttable` и
  `customteamjerseys` → `leaguecustomteamjerseys` (`INSERT … SELECT where team == index`). Дальше франшиза
  живёт своей копией: правки в редакторе на неё не влияют. Из франшизы редактор команд недоступен: в меню
  режимов есть только Edit Player. Как Custom Team попадает в лигу — видимо, заменой команды в сезоне или
  плей-офф (`dm3_substituteteam`, `FILTER_SERIES_SUB`). **[код; путь попадания — пред.]**

## 2. Где отсекаются обычные команды

- **Только в скриптах:** ветка ET в `getTeams` (`cp4_editplayer`) и `isCustomTeamsEmpty`
  (`mainmenuitems`), обе через лигу `FILTER_CREATE_TEAM`. В коде отбор идёт по номеру лиги 13 в
  `GetIDs` и по `active == 0` для новой команды.
- В коде есть зашитые границы слотов 217/218 (связь с Custom Team подтверждена):
  - `sub_82849180` — запасная строка 218;
  - `sub_82880318` @828811F8 — в состоянии зоны 141 [пред.: форма онлайн-клуба] лига 13 отдаётся как строки
    218…N−1 подряд, то есть сюда попадут и наши 218–221;
  - `sub_827CD550`, `sub_827CD9A0`, `sub_82884720` — имена `CustomTeamX` (номер − 217);
  - `sub_829847C8` — телеметрия.

  Похожие на связанные, но не разобранные: `sub_828773C0` (`GetRandomTeam`, `li 218`),
  `sub_827AFD78`, `sub_82814FB0` @828153A0. Остальные ~70 совпадений 217/218, судя по всему, не про команды.

## 3. Что будет, если дать редактору обычную команду

1. **Откроется** — код универсальный. Риски открытия [пред.]:
   - выбор логотипа ищет `artid` в списке 20001+ и у обычной команды ничего не найдёт;
   - превью формы в зоне рисуется путём конструктора, а логотип там считается как `L = +12 − 20001` — для
     `artid` < 20001 он отрицательный (файла `logoct_-19977_…` нет: пустая текстура или падение);
   - защита: на время редактирования подменять `artid` в модели на 20001+L, а при записи возвращать.
2. **Сохранится с порчей** — см. таблицу 1.5: арена, тренер, звенья, логотипы (если тронуть логотип),
   аббревиатура. Цвета и комплекты потеряются.
3. **Как нарисует игра:**
   - при `table = 0` — как раньше: `stockteamjerseys` и текстуры по `artid`. Поля формы игнорируются, кроме
     `artid`;
   - если вручную поставить `table = 1`, команда целиком станет Custom Team:
     - форма, центр льда (`composite_centerlogo`) и шайба (255) — от конструктора;
     - логотипы интерфейса — от логотипа конструктора;
     - названия — из полей базы (`"%s %s"`), а не из локализации;
     - цвета — из `customteamequipmenttable`, где для неё нет строк.

  - +94 ← `table`.

  Рисунок свитера у конструктора выбирается **по стороне**: хозяева — +22, гости — +24 (`sub_8330DEB0` /
  `sub_8330DF00` → таблицы `0x83938C38` / `0x83938C80`). Выбранный в меню комплект (третий, ретро) на этом
  пути не участвует.
- **Цвета зон:** хранилище `sub_827DA9E0` (`[0x83982C9C]`), чтение `sub_827D5488`: запись 32 байта, индекс
  `base[вид + 3200] + сторона·200 + вариант`; на сторону — 6400 байт. Заполняется
  `sub_8280B710(сторона, номер команды)` → `sub_827D6DF0` → кэш `sub_8280DE78(номер)`, который выбирает
  custom- или stock-таблицу по `table` строки. Номер ≥ 20001 (особые команды, вероятно клубы)
  разрешается через `sub_828D6CD0(сторона)`.

  Сборка свитера просит виды через таблицу `0x8227AA44` = [7, 4, 8, 10, 9, 5, 6]: свитер — вид 8, логотип —
  вид 10 (4 — перчатки, 7 — шлем, как в `stockteamequipmenttable`). Остальное сопоставление видов 0…10 с
  настройками редактора — **уточнить**.
- **Логотипы конструктора:** статическая таблица `0x82043630` — 85 записей по 16 байт (`artid`, `L`, имя,
  число цветов). Рантайм-таблицы `0x83813820` и соседние читает `sub_827DD3C0(10, artid)`: число цветов
  логотипа, для неизвестного `artid` — 0.

## 6. Рекомендация и план

**Б (донор), по этапам.** Каждый этап отдельно полезен и откатывается выключением настройки.

### Б0. Подготовка (без кода)

1. В редакторе создать Custom Team-донора: свободны слоты 222–247 в `--ahl32` и 220–247 без него;
   для сохранения нужен состав 18 + 2 — это ограничение игры.
2. Нарисовать форму.
3. Запомнить номер слота.

### Б1. Отрисовка формы донора на обычной команде (exhibition-режимы)

- **Настройка порта:** таблица `обычная команда → донор`. Ключ — `artid`: он одинаков в
  `exhibitionteams` и `leagueteams`, поэтому подходит и для франшизы. Например,
  `team_uniform_donor = { 23 = 222 }`.
- **Врезка 1** — после заполнения записи команды для матча (конец `sub_82816178`, mid-asm врезка). Если
  команда в таблице: прочитать строку донора (`sub_829043C0` всегда читает `exhibitionteams`) и поставить
  +12 = `artid` донора, +22/+24/+34/+36/+38 — его поля. Поля +14, +164, +94 не трогать.
- **Врезка 2** — замена `sub_8328CFB8` (function override). Для мест формы из §4 (по `ctx.lr`) при
  команде из таблицы возвращать 1, иначе — как в оригинале. Центр льда (`83313934`) не включать; шлем —
  по настройке.
- **Врезка 3** — цвета. В `sub_8280B710` для команды из таблицы подставить номер донора (`artid` берётся
  по номеру команды): в exhibition донор читается штатно с `table = 1`, то есть из
  `customteamequipmenttable`. Заодно получат цвета донора шлем, перчатки и вратарская амуниция.
- **Codegen:** записи в toml-файле врезок, codegen ~10 мин, сборка.
- **Проверить в игре:**
  1. «Играть сейчас», команда из таблицы дома и в гостях.
  2. В логе: запросы `czjersey/czfont/czpant/czsock/czlogo`, но `centerlogo_<artid>` и `puck_<artid>`
     родные; не должно быть `NtCreateFile FAILED` на `logoct_-…`.
  3. Свитер, номера, фамилии, шорты, гетры, шлем, перчатки, вратарь.
  4. Повтор и пауза.
  5. Матч без таблицы — без изменений.
- **Открыто:** кто ещё читает +12 у обычной команды; запись в хранилище цветов при смене стороны.
- **Франшиза (+1 день):** там `sub_8280DE78` читает `leagueteams`, а донора (строки 222+) в лиге нет.
  Решение: снять цвета донора вне франшизы (при загрузке составов) и во франшизе записывать их прямо в
  хранилище — формула индекса в §4.

### Б2. Свой герб на груди (по желанию)

- Инструмент на Python (на основе `teamart.py` / `czkit.py`) собирает из логотипа команды набор логотипа
  конструктора с новым номером `L` ≥ 87:
  - `logoct_L_0_tm`, `_1_tm`, `logoct_L_dm`;
  - `logoct_L_T_nm` / `_sm` для кроев T ∈ {0, 1, 2, 4, 5};
  - картинку меню `createteam/logo/logo<20001+L>`.
- Врезка добавляет запись в рантайм-таблицу логотипов (`sub_827DD3C0`: число цветов).
- Проверить:
  - можно ли положить полноцветный герб в `dm` без перекраски зонами — тогда цвета герба сохранятся;
  - как при этом выглядит рельеф.
- В строке донора — `artid = 20001 + L` (через базу или врезку).

### Б3. Удобство: «Edit Team → Питтсбург»

1. Список «Edit Team» показывает настоящие команды. Два пути:
   - врезка в `CTeamIonAdapter::GetIDs` (`sub_82880318`) для лиги 13 при включённой настройке — без
     правки скриптов;
   - правка `cp4_editplayer.big` (включить шапку с лигами в режиме ET), файлом в `cache:`.
2. `SetActiveTeam(обычная)` → донор этой команды; при первом выборе он создаётся сам:
   - свободный слот `active == 0`;
   - имена, цвета экипировки, `active = 1`;
   - связь в таблице порта или в поле донора, например `rivalteam = номер + 1`.
3. Для доноров снять проверку состава (`sub_8283F468`: ошибки 1/2/4).
4. Доноров скрыть из «Custom» в «Играть сейчас» (`GetIDs` лиги 13).
5. Проверить в игре:
   - создание, повторное открытие, «Отменить»;
   - сохранение составов и повторная загрузка;
   - что у самой команды не изменились арена, тренер и звенья.

## 7. Франшиза, сейвы, онлайн: что может сломаться

- **Сейвы составов:** донор хранится штатно в файле составов (группа `rosters`). Таблица связей в
  настройке порта лежит вне сейва. Если загрузить другой файл составов, где донор пустой, форма станет
  формой пустого слота. Защита: врезки работают, только если донор `active = 1`.
- **Франшиза:** сейв франшизы хранит свою копию `leagueteams` и `leaguecustom*`. По варианту Б в сейв
  ничего не пишется, форма донора накладывается при отрисовке — сейвы франшизы не портятся. Без доработки
  Б1-франшизы во франшизе будет родная форма.
- **Вариант В** с новыми строками custom-таблиц меняет схему базы. Сейвы составов — списки отличий, и
  старые сейвы с новой базой надо проверять (как с режимами 32/`--ahl32`: «франшизы одного режима в другом
  не загружать»).
- **Онлайн:** в порте нет. Форма клуба (`CREATETEAM_ONLINE_JERSEY`, состояние 141) использует тот же
  редактор; на офлайн не влияет. Но в состоянии 141 лига 13 = строки 218…N−1 — наши 218–221 туда попадут.
- **Текущая раскладка:** 218/219 (Матч звёзд) и 220/221 (фарм-клубы в `--ahl32`) с `table = 0` и
  `active = 1` — «Create Team» их не займёт. Свободных слотов 26 (222–247) в `--ahl32` и 28 (220–247) без
  него; столько же может быть доноров вместе с обычными созданными командами.
