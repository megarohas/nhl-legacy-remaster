# Портреты из NHL 24 для игроков NHL Legacy без портрета

12.10.2026, агент photos. Инструменты: [tools/photos24.py](../tools/photos24.py) (этап `photos24` в
`tools/legacy_data/build-all.sh`) и [tools/fb/lfs.py](../tools/fb/lfs.py) (legacy-файлы NHL 24). Работа офлайн, по
дампу NHL 24 (PS4) и каталогу `game/work/nhl24/catalog`. Портреты и база NHL 24 — только для личного использования: всё
лежит в `game/` (вне git). Формат портретов Legacy — [player-photos.md](player-photos.md).

## База NHL 24: где лежит

Базы и прочие не-ebx файлы движка EA лежат как legacy-файлы. Их список — в манифесте сборщика
`globals/chunkfilecollector` (ebx 332 байта).

- В ebx по +0x60 лежит GUID чанка-манифеста (16 байт как есть).
- В манифесте по +0x0C — число записей. Записи идут с +0x68, по 0x38 байт: GUID чанка с данными, u64 смещение имени,
  два u64 места в сжатом потоке, u64 смещение в распакованном чанке, u64 размер.
- `gamemodes/database/t3db/nhl_game.db` (TDB, 13,7 МБ) и `nhl_game-meta.xml` лежат в одном чанке `ba0ebf21-…`.
  Ещё там же: `gamemodes/roster/{entry_draft,expansion_draft,initial_experience,threes_campaign}.db`.
- TDB у PS4 little-endian: бит k поля — в байте k // 8, с младшего бита. `tools/tdb.Tdb.get` читает big-endian, поэтому
  в `photos24.py` — подкласс `TdbLE`. Строки (`firstname`, `lastname`) читаются как есть.
- Месяц и день рождения в базе с нуля: у Кросби 87/7/6 — это 7 августа 1987.

```bash
cd tools && python -m fb.lfs list 't3db|roster/.*\.db'
cd tools && python -m fb.lfs get gamemodes/database/t3db/nhl_game.db OUT.db
```

В `exhibitionplayerbiotable` NHL 24 — 8134 игрока: имя, дата рождения, `artid`, `headid` (у сканов = `artid`, у
типовых голов — 60000+), `hairid`, `haircolorcode`, `eyebrowid`, `skincolor`.

## Сопоставление

Портрет нужен игроку, у которого в базе Legacy `hasportrait = 0` или нет файла `p<artid>.big` — ни в архиве игры, ни в
out. Принимается только однозначный кандидат, в таком порядке:

1. имя, фамилия и дата рождения. Имена сравниваются без диакритики и знаков; ø → o, æ → ae, ß → ss, ł → l;
2. фамилия и дата рождения;
3. имя и дата рождения, если фамилии похожи: одна содержит другую (двойные фамилии) или отличаются не больше чем на
   2 буквы;
4. ID EA. Подходит, если в исходной базе Legacy есть строка с тем же `artid` (≤ 12814) и той же фамилией. Тогда берётся
   `p<artid>` из NHL 24. Если этот ID есть и в базе NHL 24, фамилия там тоже должна совпасть.

Ещё проверки:
- у другой строки той же базы не должно быть того же `artid`;
- текстура и чанк должны быть в дампе;
- портрет не должен быть силуэтом: у заглушки разброс яркости под альфой 0, у фото — от 41.

## Кадр и сборка

Портрет NHL 24 переводится в кадр портретов НХЛ 336×336 (`roster.photos_other.to_nhl_frame`: макушка, шея и ширина
головы по альфе). Дальше путь тот же, что у фото НХЛ: `playerhead.compose` собирает большой и малый портрет по
шаблонам Legacy, папка выбирается по `artid` (≤ 60000 → `p8001_12000`). Плечи у NHL 24 обрезаны на 340-й строке.
После масштаба этот срез уходит ниже сцены EA (большие — 467×260, малые — 202×128), поэтому его не видно.

Кэш:
- `game/work/photos-nhl24/portraits/p<ID EA>.png` — как в NHL 24;
- `frame/` — в кадре НХЛ;
- `nhl24db/` и `nhl24-players.json` — база NHL 24.

Сборка лежит в `game/work/legacy-data/photos24/`:
- `cache/a<artid>-e<ID EA>/` — пара файлов, повторно не собирается;
- `<вариант>/fe/…` — дерево варианта;
- `match-<вариант>.json` — кто, как найден, статус;
- `applied-<вариант>.json` — что поставлено в out;
- `sheet-<вариант>.png` — лист примеров.

```bash
P=game/work/photos-nhl24/venv/Scripts/python.exe        # нужен numpy и Pillow (выгрузка текстур NHL 24)
$P tools/photos24.py match       # → photos24/match-out.json, match-out-ahl32.json (≈ 5 мин в первый раз)
$P tools/photos24.py build       # → photos24/cache, photos24/<вариант>/fe (≈ 5 мин на 514 пар, 6 процессов)
$P tools/photos24.py apply       # → out/fe и out-ahl32/fe, hasportrait = 1, draft_roster.db заново
$P tools/photos24.py report      # сводка по лигам
$P tools/photos24.py sheet --variant out-ahl32 --n 40
bash tools/legacy_data/build-all.sh photos24 nhl24 --ahl32    # то же этапом; затем накладка NHL 24
```

`apply` меняет в `exhibitionplayerbiotable` только `hasportrait`; это сверено со всеми таблицами на копии. Если файл в
`out/fe` перекрыл бы портрет другого игрока с тем же `artid` в накладке out-ahl32, такой портрет не кладётся и попадает
в отчёт как конфликт (12.10 конфликтов 0). Повторный запуск ничего не меняет: поставленные игроки уже с портретом.

**Порядок этапов.** `photos24` идёт после `ahl`/`useredits` и до `nhl24`. Базу накладки NHL 24 (`out-nhl24*`, она
и ставится пользователю с `--nhl24`) этап `nhl24` собирает из `out/db`, поэтому после `photos24` нужен `nhl24`.

**Сохранённый состав.** Игра при запуске грузит последний сейв ROSTER целиком, вместе с `hasportrait`
(см. `save_sync_ratings.py`). После установки базы флаг переносится и в этот сейв:
`photos24.py save СЕЙВ [--write]`. Правятся строки с тем же `game_id` и `artid`, у которых в базе `cache:`
`hasportrait = 1`. Копия сейва до правки сохраняется, после записи проверяется CRC.

## Что не вошло

- Портреты игроков, у которых уже есть фото 2015 года, не заменялись: задача была только про игроков без портрета.
- 402 игрока без портрета нет в NHL 24. Это вымышленные EASHL, игроки только в сборных, а также старые игроки Европы и
  CHL из базы 2015 года, ушедшие до 2023 года.
