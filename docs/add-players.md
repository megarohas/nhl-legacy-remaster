# Свои игроки в базе NHL Legacy: `tools/legacy_data/add_players.py`

Инструмент добавляет в базу NHL Legacy новых игроков (проспект, игрок, которого нет в составах, свой персонаж) и
правит уже добавленных. Игрок описывается спекой JSON. Работает на готовой базе набора (`out/db/nhlng.db`), обычно
этапом `players` сборки `tools/legacy_data/build-all.sh`. С 20.10.2026.

```bash
python tools/legacy_data/add_players.py example > game/work/legacy-data/add-players/my.json   # образец, поправить
bash tools/legacy_data/build-all.sh players                         # спеки из game/work/legacy-data/add-players/
python tools/legacy_data/add_players.py db БАЗА.db СПЕКА.json --dry-run          # проба без записи
python tools/legacy_data/add_players.py db БАЗА.db ПАПКА --report отчёт.json     # отчёт: строки, доноры, OVR, номера
```

Без спек этап ничего не делает. Папку спек можно сменить: `ADD_PLAYERS_DIR=папка`. Файлы, чьё имя начинается с `_`,
не читаются (удобно для черновиков).

## Спека

Файл — один игрок, список игроков или `{"players": [...]}`. Образец — [add_players.example.json](../tools/legacy_data/add_players.example.json).

| Поле | Обязательно | Что | Пример |
|---|---|---|---|
| `first`, `last` | да | имя (буквы вне шрифта игры — без диакритики) | `"Alex"`, `"Example"` |
| `birth` | да | дата рождения ГГГГ-ММ-ДД; вместе с именем — ключ игрока | `"2006-03-14"` |
| `pos` | да | `C`, `LW`, `RW`, `D`, `G` | `"RW"` |
| `ovr` | новому — да | OVR, который покажет игра (40–99) | `78` |
| `attributes` | нет | атрибуты как есть, 36–99; имена без приставки: `speed`, `wristaccuracy`… (у вратаря `gsh`, `positioning`…) | `{"speed": 86}` |
| `style` | нет | полевые: `grinder playmaker sniper power two-way enforcer`; защитники: `defensive offensive enforcer two-way`; вратари: `standup butterfly hybrid` | `"sniper"` |
| `team` | нет | аббревиатура НХЛ (`MTL`), название или аббревиатура клуба из базы (`Laval Rocket`, `LAV`), номер строки `exhibitionteams` или `FA`; нет — новому FA | `"MTL"` |
| `rights` | нет | у клуба не из НХЛ — клуб НХЛ с правами (иначе прав и контракта НХЛ нет) | `"MTL"` |
| `number` | нет | номер; занят в клубе — ближайший свободный | `93` |
| `lines` | нет | нет — в запасе; `{"replace": "Имя Фамилия"}` — его места в звеньях, спецбригадах и «одет» (он — в запас); `"rating"` — звенья клуба заново по рейтингу | `{"replace": "Josh Anderson"}` |
| `shoots` | нет | хват `L`/`R` (у вратаря — рука ловушки, как в API НХЛ) | `"L"` |
| `height` / `height_cm` | нет | рост: `"6-1"` (фут-дюйм) или сантиметры | `"6-1"` |
| `weight_lb` / `weight_kg` | нет | вес | `190` |
| `birth_city`, `birth_country`, `birth_state`, `nationality` | нет | место рождения, страна ISO-3 (`CAN`, `USA`, `SWE`, `RUS`…), провинция/штат, гражданство (нет — страна рождения) | `"RUS"` |
| `draft` | нет | `{"year", "round", "overall", "team"}` | `{"year": 2024, "round": 1, "overall": 5, "team": "MTL"}` |
| `nhl_gp`, `gp_last_season`, `pro_gp`, `debut`, `rookie` | нет | игры в НХЛ (карьера, прошлый сезон), профи, первый год дебютного сезона, новичок (нет — меньше 25 игр и не старше 26) | `60`, `2025` |
| `contract` | нет | `{"cap": 975000, "years": 3, "two_way": false}`; нет — заглушка конвейера по OVR и возрасту | |
| `head` | нет | типовая голова базы (60000–60210) и её тон кожи; нет — по имени | `60118` |
| `photo` | нет | PNG с прозрачным фоном (путь — от файла спеки): портрет NHL 336×336 — как есть, другой размер — по макушке и центру головы | `"photos/alex.png"` |

## Что делается

1. **Строка.** Игрок с тем же именем и датой рождения уже есть — правится он (см. ниже). Иначе берётся строка донора:
   игрок без клуба (нет записей составов и связи в пуле свободных агентов, не в сборных, легендах, Матче звёзд,
   Зимней классике), старшие первыми, вратарь — для вратаря. Пул свободных агентов не трогается: там игроки «на
   сегодня» этапа `ahl`. У донора стираются имя, портрет (`hasportrait` 0), голос комментатора (`audioid` 0), черты и
   карьерная статистика; `artid` — первый свободный от 12815.
2. **Биография и контракт** — тем же кодом, что у конвейера составов (`roster/write.py` `Writer.write_bio`, `contract`).
3. **Атрибуты** — под OVR игры (`roster/ovrformula.py`, формула worth2.brk): атрибуты из спеки — как есть, остальные —
   медианная форма игроков составов НХЛ того же амплуа и стиля, сдвинутая до OVR (как у этапа `ahl`). Потенциал — по
   возрасту, как у конвейера.
4. **Клуб.** Запись `exhibitionrostertable` в конец состава клуба (key подряд, прежние записи на своих местах), связь
   `exhibitionplayers` — своя у донора или новая; `FA` — связь в `exhibitionfreeagents`. Буквы капитанов не меняются.
5. **Портрет** (`photo`) — оба файла игры в `<набор>/fe/ion/artassets/playerheads*/p8001_12000/p<artid>.big`
   (`playerhead.compose`, как у `tools/photos.py`), `hasportrait` 1. Нет фото — после этапа `players` идут `photos24`
   и `heads`: если игрок есть в NHL 24, портрет и голова возьмутся оттуда.

**Правка того, кто уже есть** (повторный прогон или свой игрок, добавленный раньше, или игрок конвейера): меняются
только поля, которые есть в спеке. Драфт, игры, контракт этапа `contracts`, голова, портрет без этих полей в спеке —
как были. Нет `team` — клуб и записи составов как были. Есть `ovr`, `attributes` или `style` — атрибуты подгоняются
от его нынешних; нет — не трогаются. Потенциал и рост не меняются.

Перевод в другой клуб — только из запаса. Если игрок прежнего клуба одет, стоит в звеньях или с буквой, инструмент
останавливается: сначала уберите его из звеньев.

## Проверки

После записи в памяти, до сохранения файла:
- CRC базы, `key` подряд у каждого клуба, связи без повторов, нет свободных агентов в составах;
- у игрока спеки записи составов — только в его клубе, `team` = клуб + 1;
- у затронутых клубов места звеньев и число одетых — как были (у `"rating"` — каждое из 71 места у одного, одетых 20),
  буквы те же, новых повторов номеров нет, записей ≤ 40;
- OVR, который посчитает игра, = цель.

Хоть одна проблема — база не пишется, список — в выводе. Повторный прогон с теми же спеками ничего не меняет
(«база уже такая — без записи»). Проверено 20.10.2026 на копии `out`: новые полевой и вратарь, клуб АХЛ с правами,
`replace` и `rating`, перевод из FA, частичная правка игрока конвейера (у Cole Caufield с одним `ovr` поменялись
только атрибуты), портрет из PNG; ошибки входа — понятным текстом.

## Ограничения

- **Сохранённый состав (ROSTER).** Игра, у которой загружен сохранённый состав, берёт игроков из него, а не из базы.
  Новый игрок есть в новой франшизе со стартовых составов базы. В уже сохранённый ROSTER инструмент не пишет: у сейва
  свои запасные строки и удалённые записи (`tdb.Tdb.live_rows`), это следующий шаг.
- Только NHL Legacy (база `tools/nhl32.py --game legacy`). В сборные, легенды, Матч звёзд не ставит.
- Голова — типовая (или NHL 24 этапами `heads`/`scans24`); свою 3D-голову так не поставить.
- Доноров без клуба немного: в `out` 20.10.2026 — 58 полевых и 16 вратарей. Кончатся — инструмент остановится с
  сообщением (тогда нужен донор из запасных клубов Европы или юниоров, как у конвейера, — пока не сделано).
- Звенья `"rating"` пересобирают весь клуб — реальные сочетания DailyFaceoff у него пропадают. Чтобы изменить
  меньше, есть `replace`.
