# Чистка форм: какие оставить в игре

Локальная страница со всеми формами 32 клубов, которые сейчас в NHL Legacy. Галочка — форма остаётся, снятая
галочка — форма уйдёт. Инструмент — `tools/kitpicker/prune.py`, страница — `tools/kitpicker/prune_page/`.

На странице превью из архивов EA и формы NHL 24/27. Это личное: наружу не публиковать, в git не класть. Рабочая папка
`game/work/kit-prune/` в `.gitignore`, сервер слушает только `127.0.0.1`.

## Запуск

```bash
game/work/nhl24/venv/Scripts/python.exe tools/kitpicker/prune.py build
game/work/nhl24/venv/Scripts/python.exe tools/kitpicker/prune.py serve
game/work/nhl24/venv/Scripts/python.exe tools/kitpicker/prune.py show
```

| Команда | Что делает | Куда пишет |
|---|---|---|
| `build` | читает формы из базы игры, декодирует превью меню, копирует страницу | `game/work/kit-prune/`: `index.html`, `data.js`, `data.json`, `img/<клуб>/<форма>.png` |
| `serve [--port 8765]` | отдаёт страницу, принимает выбор | `game/work/kit-prune/selection.json` при каждом клике |
| `show` | печатает, что отмечено на удаление, по клубам | никуда |
| `apply` | дописывает выбор в список убранных форм, выбор уходит в `selection-<время>.json` | `tools/legacy_data/kit_removed.json` |

В приложении Claude сервер запускается конфигурацией `kit-prune` из `S:\Claude\.claude\launch.json` (порт 8726).

Без сервера страница тоже открывается как файл `game/work/kit-prune/index.html`. Выбор тогда живёт в браузере, а
кнопка «Сохранить файл» выгружает `selection.json` в «Загрузки».

`build` нужно повторить после любой установки, которая меняет формы: список берётся из базы на момент сборки.

## Откуда данные

- **Список форм** — `stockteamjerseys` в `nhl-legacy-port/userdata/cache/guest/db/nhlng.db`, клубы — `kitpicker/build.py`
  `CODES`, порядок внутри группы — `jerseyindex`, как в меню игры.
- **Подпись** — как в меню: `locstring` 0–5 — стандартные, 6 — ключ `Vintage_<style>_<art>_<variant>` в
  `fe/loc/NHL_ENG_US.db`.
- **Превью** — `fe/ion/artassets/jerseys/jersey_<style>_<art>_<fevariant>.big`, 256×256: сначала из `cache:`, иначе из
  архивов EA. У 62 форм adidas манекена нет и форма занимает весь кадр (x 12…243), у остальных форма в x 65…199. Поэтому
  на карточке обычные превью увеличены, а adidas показаны целиком.

## Группы

Группа определяет кнопку на странице и подпись карточки (`GROUPS`, `group_of` в `prune.py`).

| Группа | Как определяется | Форм на 31.10.2026 |
|---|---|---|
| NHL 27: по умолчанию | `edge_home`, `edge_away` в `nhl24_kits.json` | 64 |
| Наши: adidas из NHL 24 | `ad_home`, `ad_away` в реестре | 62 |
| Наши: NHL 24 | остальные формы реестра | 9 |
| Наши: первые формы | арт 100, 101, 104 вне реестра: первые формы SEA, VGK, UTA | 8 |
| EA: Home и Away | подписи `Home (EA)`, `Away (EA)` | 58 |
| EA: Alternate | подпись `Alternate` | 22 |
| EA: Classic и Stadium | в подписи `Classic` или `Stadium` | 21 |
| EA: прошлые сезоны | подпись с годом после 2006 | 24 |
| EA: 2006-07 | подпись `2006-07 …` | 73 |
| EA: ретро | подпись с годом до 2006 | 51 |

Всего 392 формы. Формы с `isdefault` снять нельзя: игра выбирает форму дома и в гостях по `isdefault` и `locstring`
0/1 (`docs/nhl24-uniforms.md`), и клуб без них останется без формы. Сервер тоже не принимает такие формы в выборе.

## Как убираются формы

Порядок после выбора на странице (игра закрыта, из `tools/`):

```bash
../game/work/nhl24/venv/Scripts/python.exe kitpicker/prune.py apply
../game/work/nhl24/venv/Scripts/python.exe -m kitport build --club MIN --kits home --stages overlay
../game/work/nhl24/venv/Scripts/python.exe -m kitport install --tag prune --yes
../game/work/nhl24/venv/Scripts/python.exe legacy_data/nhl24.py save "<новейший ROSTER>" --write
../game/work/nhl24/venv/Scripts/python.exe kitpicker/prune.py build
```

- `kit_removed.json` — список в git: клуб и `стиль_арт_вариант`. Он только копится, список можно править руками. Формы NHL 27
  с 02.11.2026 на стиле 2 ([kitport.md](kitport.md) §1.1), их номер в списке — `2_A_V`. Записи `0_A_V` — это формы EA и adidas,
  перевод их не касается: 178 убранных форм остаются убранными.
- `nhl24.py build` убирает строки из `stockteamjerseys` последним шагом сборки базы (`drop_kits`). Реестр
  `nhl24_kits.json` и номера в нём не меняются, поэтому `alloc` и порядок сборки работают как раньше.
- `nhl24.py save` убирает те же строки из сейва ROSTER, у него своя таблица, и ставит таблице место `max` как у игры
  (`kit_room`). Копия сейва — в `game/work/legacy-data/backup-saves/`.
- Вернуть форму: убрать её из `kit_removed.json`, повторить сборку и установку, таблицу в сейв перенести через
  `roster_merge.py` (строка вернётся в середину таблицы, `nhl24.py save` такой сейв не примет).
- Файлы формы (`rendering/…`, превью) остаются в накладке. Старые сейвы ROSTER ещё держат эти строки, и без файлов такая
  форма в них была бы пустой.

Почему так:

- **Форма — это клуб и номер, а не один номер.** У команд Winter Classic 216–219 свои строки с тем же артом и вариантом:
  NYR 2012 `1_19_3`, PHI 2012 `1_21_4`, PIT 2011 `1_23_3`, WSH 2011 `1_29_2`. Форма `1_21_4` у клуба 21 и у команды 217 — две
  строки. Режим Winter Classic с готовыми командами берёт строку команды, поэтому убранная у PHI форма ему не мешает.
- **`jerseyindex` клуба перенумеровывается подряд 0…N−1.** Игра берёт его и как значение (`82AEADD0`, перебор списка), и как
  позицию в списке (`82AEAD80`: `82F72000` — номер формы по умолчанию сразу идёт в чтение по позиции). С дырой в номерах
  форма по умолчанию стала бы чужой.
- **Скрыть строку через `islockable` нельзя.** Закрытая форма остаётся в карусели, только с картинкой замка
  (`82AEABE0`).
- **В Moments Live старые номера.** 52 сценария (`cache/scenario/scenario_*.big`, `scenario_gameteam_*.json`) хранят
  `fejerseyindex`, `jerseyart`, `jerseyvariant`. Ни одна из 104 форм сценариев не убрана. Свитер рисуется по арту и варианту,
  а `fejerseyindex` читается через `82AF88B0`: не нашлась строка — берётся `currentjersey`, то есть тот же вариант.
- Франшиза номеров форм не хранит: `leagueteams.jerseybackhome`, `jerseybackaway`, `jerseystyle` равны 0 у всех команд,
  `leaguecustomteamjerseys` пуста.
- **`max` таблицы форм в сейве должен совпасть с игрой.** Иначе «ROSTER1 appears to be damaged»: `Cancel` возвращает на
  заставку, `Retry` — к тому же окну, до меню игра не доходит. Правило — 749, если строк не больше 749, иначе строки + 60:

  | Строк в базе | `max` в сейве | Игра |
  |---|---|---|
  | 843 | 903 | принят |
  | 843 | 842 | отказ |
  | 665 | 665, 725, 903 | отказ |
  | 665 | 749 | принят, столько же пишет сама игра |

  Строки сами ни при чём: таблица форм сейва игры и наша совпали запись в запись. Переписать сейв нашим кодом без смены
  размера таблицы тоже можно, игра его принимает. 749 — число из кода игры, 60 — `maxinsert` схемы. Точное правило: 749, если
  строк не больше 749, иначе строки + 60 ([launcher.md](launcher.md), «Как игра проверяет ростер»). `kit_room` считает так же.
  `nhl24.py save` до 31.10 ставил `max` = строкам, поэтому после него пользователь видел то же окно.
- **У таблицы экипировки правило другое.** Числа из кода 6000, `maxinsert` нет, поэтому при строках больше 6000 мест столько
  же, сколько строк: 6452 после перевода на стиль 2. Старый ROSTER с 6292 местами на такой базе — «damaged».

## Проверено

- Страница: снятие по одной форме и группой, возврат группы, запись `selection.json`, загрузка выбора после
  перезагрузки, отказ сервера на незнакомую или закреплённую форму.
- В игре 31.10.2026 (копия userdata, окно без фокуса, виртуальный геймпад, `tools/padshot.ps1`; база и сейв без 178
  форм):
  - Winter Classic, готовый матч 2012: Рейнджерс и Флайерс в своих формах, матч идёт;
  - Moments Live, «Make the Stars see Blue»: у DAL в сценарии `fejerseyindex` 9, строк у клуба 8, у игроков верная форма
    2014–15, матч идёт;
  - Play Now, Select Jerseys: у PIT карусель из 8 форм, по умолчанию домашняя и выездная NHL 27;
  - сейв ROSTER грузится без окна «damaged»; `nhl24.py save` пишет его байт в байт как проверенный файл.
- Сверка 31.10.2026: `stockteamjerseys` и `stockteamequipmenttable` новейшего сейва `ROSTER 20261024125927` совпали с
  базой `cache:` запись в запись (843 и 6292). Значит, страница показывает то, что игра берёт из сейва.
- В сейвах `DYNASTY` этих таблиц нет, есть только `leaguecustomteamjerseys` созданных команд.

## Грабли

- Текст в `send_error` идёт в строку статуса HTTP: кириллица там обрывает соединение. Сообщения сервера — латиницей.
- Первые байты таблицы каталога (`@0x18`) — имя первой таблицы, а не код версии. Порядок таблиц в сейве игры другой, это не
  отличие.
- Старые ROSTER остаются с прежней таблицей форм. Грузить стоит только новейший.
- Сейв лежит в папке с тем же именем: `…/00000001/ROSTER <дата>/ROSTER <дата>`.
