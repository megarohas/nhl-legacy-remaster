# Новый ростер: трейды и звенья (`tools/legacy_data/roster_update.py`)

Один запуск: спека трейдов и свежие звенья → новая база и файл `ROSTER ДД.ММ.ГГГГ` на копии новейшего ростера пользователя.
Игра грузит игроков из сохранённого ROSTER, а не из базы ([launcher.md](launcher.md), «Как игра выбирает ростер»), поэтому
инструмент делает и то и другое: новая франшиза, `SET DEFAULT ROSTERS` и ростер не расходятся. С 02.11.2026.

```bash
python tools/legacy_data/roster_update.py example > game/work/roster-update/trades.txt   # образец, поправить
python tools/legacy_data/roster_update.py run --fetch-lines --dry-run     # скачать данные, всё посчитать, записать только отчёт
python tools/legacy_data/roster_update.py run                             # записать в game/work/roster-update/out
```

| Параметр | Что | По умолчанию |
|---|---|---|
| `--trades ФАЙЛ` | спека трейдов | `game/work/roster-update/trades.txt` |
| `--fetch-lines` | скачать заново звенья (33 запроса), списки клубов (32) и карточки спорных игроков (по 2 на игрока) | кэш |
| `--date ДД.ММ.ГГГГ` | дата данных вручную | самый свежий трейд и самая свежая страница звеньев |
| `--db БАЗА` | база, на которой сделан сейв; схема рядом | установленная `userdata/cache/guest/db/nhlng.db` |
| `--save ФАЙЛ` | сейв ROSTER | новейший по имени папки |
| `--out`, `--work` | куда писать, где лежит `new-players.json` | `game/work/roster-update/out`, `game/work/roster-update` |
| `--no-new` | не добавлять игроков, которых нет в базе | добавляет |
| `--launcher EXE` | чем проверять файл | `out/launcher`, потом `out/build/win-amd64-release` |
| `--dry-run` | база и сейв не пишутся, только отчёт | |

Сейвы и база пользователя только читаются. Установка — руками, команды в конце `report.md`.

## Спека трейдов

Текстовый файл, строка на сделку, новые сделки просто дописываются. У каждой стороны — то, что клуб **получает**, как на
трекерах трейдов: Хеллебайк играл за WPG и стоит у NJD.

```text
02.11.2026 | NSH: Shane Wright | SEA: Matthew Wood
23.10.2026 | WPG: Nico Daws, Dawson Mercer, Nick Bjugstad, pick 2029 R2 | NJD: Connor Hellebuyck
16.10.2026 | TOR: Aatu Raty [farm] | VAN: Brandon Buhr, Jacob Quillan
```

- Дата — `ДД.ММ.ГГГГ` или `ГГГГ-ММ-ДД`, клуб — аббревиатура НХЛ, сторон может быть больше двух. `#` в начале строки — комментарий.
- Тёзок различает номер: `Elias Pettersson #25`. Без номера инструмент остановится.
- Уровень сохраняется: игрок клуба НХЛ идёт в клуб НХЛ, игрок АХЛ — в фарм нового клуба, игрок Европы и юниоров остаётся на
  месте, меняются только права. `[farm]` и `[nhl]` задают уровень явно: Рати по новостям сразу ушёл в АХЛ.
- Строки применяются от старых к новым. Сделка, которая уже в базе, не меняет ничего, в отчёте — «уже в новом клубе».
- Если права в базе у третьего клуба, сделка проводится, а в отчёте это отмечено.
- Сторона может быть одна: это перевод без сделки, `29.10.2026 | CBJ: Carson Soucy [farm]`. Столбец `источник: …` попадает в отчёт. Так
  записывается то, чего данные ещё не знают: игрока отправили в АХЛ, а игр там пока нет.

## Выход

| Файл | Что |
|---|---|
| `out/ROSTER ДД.ММ.ГГГГ` | готовый ростер: для кнопки «Обновить ростеры» и `--import-roster` |
| `out/db/nhlng.db`, `nhlng-meta.xml`, `draft_roster.db` | база с теми же изменениями |
| `out/report.md`, `report.json` | трейды, новые игроки, переводы, буквы, номера, контракты, ведомости, сверка со списками НХЛ, все 32 клуба, команды установки |
| `new-players.json` (в `--work`) | спека [add_players.py](add-players.md) для новых игроков; её можно поправить, при следующем запуске она читается |

## Что делается

1. **Новые игроки.** Кого из сделок и звеньев нет в базе, тот ищется в NHL API и добавляется через `add_players.py` (ниже).
2. **Трейды.** Запись состава переезжает в новый клуб, `proteam` и `team` — новые, контракт едет с игроком.
3. **Вызовы по звеньям.** Игрок страницы, которого нет в клубе, переводится из фарма, пула свободных агентов или другого клуба.
   Страницы идут от новых к старым. Игрока из спеки устаревшая страница назад не вернёт, чужого игрока забирает только более
   свежая страница. Травмированные тоже в клубе НХЛ: они есть на странице.
4. **Сверка со списками НХЛ** (раздел ниже). Кто в списке клуба, тот в клубе; кто в клубе, но нет ни в списке, ни на странице, идёт туда, куда
   говорит его карточка НХЛ.
5. **Фарм без вратаря.** Если у клуба АХЛ после вызова остался один вратарь, запасной вратарь приходит из клуба АХЛ, где их больше
   всего. Права у него прежние. Без второго вратаря у клуба пустое место `g2`.
6. **Звенья НХЛ.** Все 32 клуба заново: `lines_real.team_lines` и `lines.build_real` ([roster-pipeline.md](roster-pipeline.md), раздел lines):
   4 тройки, 3 пары, большинство, меньшинство, вратари, одетые; овертайм, буллиты и лишние — по рейтингу. Места, которые источник
   не закрыл, достраиваются по рейтингу и видны в отчёте. Клуб, где страница дала меньше 12 своих игроков, — по рейтингу.
7. **Основной вратарь — сильнейший.** На странице первым стоит сыгравший последним: 02.11.2026 это Томкинс с OVR 64 при Джарри с 86.
   В игре `g1` — основной, поэтому из двух вратарей страницы он тот, у кого OVR выше.
8. **Клубы вне НХЛ**, чей состав изменился, — звенья заново по рейтингу (`lines.build`), как их собрал конвейер.
9. **Буквы.** Ушла буква — она достаётся самому опытному одетому полевому того же клуба. Остальные буквы не трогаются, в том
   числе у травмированных: так и в базе.
10. **Номера.** Клубы НХЛ — по спискам API (`/v1/roster/{клуб}/current`). Номера страниц звеньев бывают старыми, Dobson там № 8 при
   № 53 в клубе, а у братьев Фолиньо один номер на двоих. Кого в списке нет, остаётся со своим номером, занят — ближайший свободный.
11. **Контракты.** Пришедшему без контракта — со страниц контрактов `game/work/contracts/screens`. На них нет — минимальный на год,
    в отчёте это отмечено: у игры игрок клуба без контракта не держится.
12. **Экипировка вратарей.** У клубов, где сменился вратарь, — набор клуба (`goalie_gear.py`): иначе Хеллебайк играл бы в маске Виннипега.
13. **Проверки до записи.** key подряд, связи без повторов, свободных агентов нет в составах, `team` равен клубу, у каждого клуба
    71 место по одному владельцу, 20 одетых, амплуа по местам, буквы, номера без повторов, права и контракты клубов НХЛ, CRC. Хоть
    одна проблема — ничего не пишется, отчёт остаётся.
14. **База.** `draft_roster.db` — те же 10 таблиц из новой базы (старт франшизы «NHL Entry Draft»).
15. **Сейв.** Копия новейшего ROSTER, трёхстороннее слияние `roster_merge.py` ([legacy-data.md](legacy-data.md), «Перенос в сейв ROSTER»):
    O — база до, U — сейв, N — новая база. Правки пользователя в сейве остаются. Размер файла не меняется: места таблиц те же.
16. **Лаунчер.** `--check-roster` на временной папке с новой базой. Не принял — запуск падает.

Какие таблицы меняются: `exhibitionrostertable`, `exhibitionplayerbiotable`, `exhibitionfreeagents`, `exhibitiongoalieequipment`, у новых игроков
ещё `exhibitionskaterai`, `exhibitiongoalieai`, иногда `exhibitionplayers`. Только в базе, в сейвах таблиц нет: `stockcareerseasonplayerstats`,
`stockcareerplayoffplayerstats` (статистика прежних хозяев строк-доноров). Формы, экипировка клубов, головы, арены не трогаются.

## Новые игроки

Данные только из источников, в отчёте у каждого указано откуда:

| Что | Откуда |
|---|---|
| имя, дата и место рождения, амплуа, хват, рост, вес, драфт, игры | NHL API: поиск, потом `/v1/player/{id}/landing`, запрос на игрока с паузой |
| рейтинг | база NHL 27 (`game/work/nhl27/db`): все атрибуты и стиль, сверка по имени и дате рождения. OVR в игре считает формула, он может отличаться от EA на 1–3 |
| рейтинг, если в NHL 27 игрока нет | оценка по статистике как у игроков АХЛ (`ahl2026.FixedStats`: NHLe трёх сезонов, опыт в НХЛ); место среди игроков АХЛ того же класса, OVR — медиана 9 ближайших |
| контракт | страницы контрактов по ID НХЛ, иначе минимальный двусторонний на год |

Строка — донор `add_players.py`, голова типовая, портрета нет (силуэт). Портрет и голову добавят этапы `photos24`, `heads`, если
игрок есть в NHL 24 или 27. Кого нет в поиске НХЛ, тот в отчёте «Не найдены нигде», его место достраивается по рейтингу.

## Дата в имени

Дата — это дата данных: самый свежий трейд или самая свежая страница звеньев (`updatedAt`, UTC), а не время сборки файла.

- Файл называется `ROSTER 02.11.2026`, чтобы файлы отличались в проводнике.
- Лаунчер берёт дату из имени файла и пишет в заголовок сейва имя `ROSTER 02.11.2026` ([launcher.md](launcher.md), «Имя в меню»). В самом
  файле ростера места под дату нет, поэтому при переносе на другой ПК имя файла менять нельзя: дата пропадёт, в меню будет `ROSTER1`.
- В игре имя видно в LOAD, SAVE, DELETE. Папка остаётся `ROSTER <время>`: по ней игра выбирает новейший.
- Сохранение поверх в игре имя не теряет. Игра открывает клавиатуру с этим именем, его можно и поменять, но точки на клавиатуре нет.

## Пики

В отчёт попадают, в ростер нет. В ROSTER есть таблица `exhibitiondraftpick`, но это 2015–2020 годы на 30 клубов, а франшиза создаёт
пики сама: в сейве франшизы 2027–2032 у всех свои, чужих владельцев из этой таблицы там нет. Сверено 02.11.2026 на `DYNASTY 20261101161318`:
из 106 строк с другим владельцем ни одна не дошла, а 12 чужих пиков там — это сделки самой франшизы.

## Источники и правила

- **DailyFaceoff**, `line-combinations`: 32 страницы и `robots.txt`, пауза от 1 с, без входа, один проход. `robots.txt` разрешает всё,
  кроме `/api/` и `/cms/`. Условий использования на сайте не нашлось: `/terms-of-use`, `/terms-of-service`, `/terms`, `/terms-and-conditions`
  дают 404, в `privacy-policy` о них только упоминание и ни слова про автоматический доступ (проверено 02.11.2026). Использование
  личное, кэш в `game/work/`, в git не идёт. Если сайт откажет, инструмент не обходит это: запрос падает, страниц в кэше не будет.
- **NHL API**: списки клубов и карточки игроков, с паузой, кэш `game/work/roster-cache/nhl/`.
- **Страницы контрактов** — только локальные файлы пользователя. PuckPedia автоматически не скачивается.

## Сверка со списками НХЛ

Страница звеньев показывает заявку и травмированных, поэтому запасные и отправленные в фарм на ней не видны. Эту часть закрывают
`/v1/roster/{клуб}/current` и карточки игроков (`/v1/player/{id}/landing`), решение пользователя 02.11.2026: «актуализируй состав».

**Кто в списке клуба, но в базе в другом месте,** переводится в клуб. Игрока, которого нет в базе, инструмент добавляет, как и остальных новых.
Игрока из спеки список назад не тянет: спека могла выйти позже списка.

**Кто в клубе, но нет ни в списке, ни на странице,** того решает карточка: строки `seasonTotals` за нынешний сезон, регулярный чемпионат.

| Что в карточке | Куда |
|---|---|
| есть игры в АХЛ | клуб АХЛ по названию, иначе фарм его клуба. Игры в НХЛ рядом ничего не решают: `sequence` идёт по лигам, а не по времени, а из списка он уже выпал |
| игры в другой лиге, клуб которой есть в базе (Европа, юниоры) | этот клуб, права прежние |
| игры в лиге, которой нет в базе (КХЛ, NCAA) | остаётся, в отчёт |
| только ECHL | фарм: лиг ниже АХЛ в базе нет |
| `currentTeamAbbrev` — другой клуб НХЛ | этот клуб, запасным |
| только НХЛ или игр нет | ответа нет: остаётся, в отчёт |

Игрока ищет поиск НХЛ по имени, потом по фамилии, подтверждает дата рождения. Клуб с правами берётся из `currentTeamAbbrev`. Контракт едет с игроком.

Вчерашнего отправленного в АХЛ, у которого там ещё нет игр, карточка от травмированного не отличит. Такой игрок остаётся в разделе отчёта
«Остались в клубе без ответа». По новости клуба он записывается в спеку строкой с `[farm]` и источником, и следующий запуск сделает это сам.

Карточки лежат отдельно, в `nhl/landing-now/`: карточки конвейера в `nhl/landing/` не меняются, по ним считаны рейтинги.

## Совместить с другой работой над базой

Инструмент работает от базы и сейва, которые ему дали. Если базу или сейв поменял кто-то ещё (формы, экипировка), достаточно запустить его
снова на новой базе и новом сейве: кэш тот же, результат тот же, чужие таблицы слияние не трогает.

```bash
python tools/legacy_data/roster_update.py run --db ПАПКА/nhlng.db --save "ROSTER ПОСЛЕ ДРУГОЙ РАБОТЫ"
```

`build-all.sh` пересобирает составы из кэша конвейера и про трейды не знает: после полной пересборки инструмент запускается заново.

## Как проверить

```bash
python tools/tdb.py verify "game/work/roster-update/out/ROSTER 02.11.2026" --meta nhl-legacy-port/userdata/cache/guest/db/nhlng-meta.xml
python tools/tdb.py diff nhl-legacy-port/userdata/cache/guest/db/nhlng.db game/work/roster-update/out/db/nhlng.db --tables exhibitionrostertable --limit 5
```

В игре: CUSTOMIZE → ROSTER MANAGEMENT → EDIT LINES (`LB`/`RB` — клуб, `LT`/`RT` — вид звеньев, вратари — предпоследняя вкладка) и CUSTOMIZE →
SAVE/LOAD/DELETE → LOAD → ROSTERS. Проба на копии: `--import-roster` на стенде из копии userdata с новой базой ([launcher.md](launcher.md)).

## Грабли

- Базу и ростер ставить вместе: у старой базы нет новых игроков в `SET DEFAULT ROSTERS` и новой франшизе.
- Списки API не знают номера только что обменянного (`sweaterNumber` пуст): остаётся номер страницы или свой.
- Ведомости клубов считаются по всему составу НХЛ в базе, вместе с лечащимися и без удержаний и выкупов: часть клубов выше потолка 104 млн. Список — в отчёте.
- Если у клуба нет страницы или списка, его сверка пропускается: без данных составы не двигаются.
- У клуба АХЛ после вызовов может остаться 11 нападающих (02.11.2026: IOW, ONT). Звенья всё равно полные: недостающего играет защитник, в отчёте это
  отмечено. Запасного не берём: чужой вратарь нужен, потому что без него нет места `g2`, а нападающего заменяет защитник.
- Страницы и списки меняются каждый день: перед новым ростером `--fetch-lines`.
