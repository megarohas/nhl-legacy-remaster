# Свой порт NHL Legacy (legacy-port/)

Порт NHL Legacy Edition (Xbox 360, TitleID `454109EC`, 2015, база 2015/16) на нашем тулчейне —
ReXGlue SDK 0.10.0.24 (ночной и своя сборка `ref/rexglue-sdk-custom` с Vulkan и FSR/CAS), по
образцу порта NHL 13 (`port/`, `port-ffx/`). Начат 08.10.2026 по плану
[legacy-port-feasibility.md](legacy-port-feasibility.md) (вариант «В»). Цель — чтобы друзья
играли в Legacy с нашими изменениями: год, скорость, данные (составы, формы, шрифты…), а
дальше — франшиза на 32 команды.

## Устройство

`legacy-port/` — проект ReXGlue. В git: `CMakeLists.txt`, `CMakePresets.json`, `build.cmd`,
`nhllegacy_manifest.toml`, `nhllegacy_*.toml` (ручные функции, врезки), `nhllegacy.example.toml`,
`src/`, `scripts/`, `dist-template/`, `generated/rexglue.cmake`. Только локально: сгенерированный
код `generated/default/` (производное от кода игры), сборка `out/`, сейвы и кэш `userdata/`,
образы и разведка прототипа (`images/`, `xmatch-*`, `sites/`, `codegen/`, `analysis/` …).

| Файл | Что |
|---|---|
| `nhllegacy_manifest.toml` | диск `game/other/legacy/disc`, setjmp `0x830801C0` / longjmp `0x8307E1B0` |
| `nhllegacy_functions.toml` | 327 ручных функций: 306 — наш `tools/find_indirect_targets.py` по образу Legacy, 21 — адреса из списка nhl-legacy-recomp (их порт находил по падениям; нашим фильтром не находятся) |
| `src/nhllegacy_app.h` | хост: пути из `nhllegacy.toml` (без настроек — `game\` и `userdata\` рядом с exe), `cache:` → `userdata/cache/guest`, без окна достижений |
| `src/nhllegacy_crash.cpp`, `_watch.cpp`, `_snap.cpp`, `_debug.h` | отчёт о падении `nhllegacy_crash.txt`, слепки `dumps\`, стеки по флагу, сторож памяти — как в NHL 13 |
| `src/nhllegacy_input_lock.cpp` | обход гонки InputSystem SDK (XamInput* под мьютексом) |
| `src/nhllegacy_imports.cpp` | заглушки XUsbcam |
| `src/nhllegacy_fencewait.cpp` | ожидание забора D3D 827E2BC8 (в NHL 13 — 82663148) без холостого спина |
| `src/nhllegacy_composite.cpp` | resolve композиции экипировки 836214A8 / опрос забора 8361F3E0 (832B22A8 / 832B0250) — на время композиции `readback_resolve = full` |
| `src/nhllegacy_dbtrace.cpp` | трассировка обращений к таблицам базы (флаг `nhllegacy_dbtrace.on` рядом с exe): 827B6FA8 / 827B4818 |

Отличия от NHL 13 по данным диска: `cache:` проверяется для каждого файла раньше архивов
(`cache:\db\nhlng.db`, `cache:\fe\…`) — моды-данные кладутся в `userdata/cache/guest`
без перепаковки. Папка данных — своя (`legacy-port/userdata`), не `game/userdata` NHL 13.

## Сборка

```bat
:: Release — свой SDK (D3D12 + Vulkan, FSR 1 / CAS): out\build\win-amd64-release\nhllegacy.exe
S:\Claude\megarohas_nhl13\legacy-port\build.cmd
:: RelWithDebInfo — ночной SDK (только D3D12), с символами в отчёте о падении
S:\Claude\megarohas_nhl13\legacy-port\build.cmd win-amd64-relwithdebinfo
```

Сборка сама запускает кодоген (`rexglue codegen nhllegacy_manifest.toml`), если менялись
манифест или `*.toml` врезок: ~18 мин при пониженном приоритете (анализ однопоточный), затем
компиляция 368 файлов ~5 мин. Вручную кодоген не запускать: сборка всё равно прогонит его заново
(отпечаток входов в `codegen.stamp` у ручного и встроенного запуска не сходится).

**Новое дерево с нуля** (без `generated/default`, например `git archive HEAD legacy-port`): `generated/rexglue.cmake`
подключает `generated/default/sources.cmake`, только если он уже есть при configure — иначе цели
`nhllegacy_recomp` нет и код игры в первую сборку не попадает. Порядок: configure →
`cmake --build out/build/win-amd64-release --target nhllegacy_codegen` → `build.cmd` (он сам делает configure
заново и собирает всё). Так собрана сборка №5 (09.10, `legacy-port/out/agent/clean_build.cmd`, дерево
`legacy-port-clean` = `main` 464c4ef, 12 потоков, обычный приоритет): кодоген 725 файлов за 12 мин 45 с, затем
385 шагов за 3 мин 15 с, 0 ошибок. Раскладка функций по файлам у нового дерева своя (см. sdk-build.md, «Грабли»,
п. 5), код тот же: размер exe совпал с прежним до байта.

### Проверки в игре без фокуса (09.10.2026)

Пользователь пожаловался: тестовая игра шла на весь экран и при каждой его попытке переключиться на своё окно
забирала фокус обратно (`gameshot.ps1` перед каждой клавишей выводил окно игры вперёд: `AttachThreadInput`, F24,
`BringWindowToTop`, `SetForegroundWindow`). С 19:59 тесты были на паузе, переделано:

- `tools/gameshot.ps1` окно игры **не выводит вперёд никогда** — вызовов `SetForegroundWindow`/`BringWindowToTop`/
  `AttachThreadInput`/`ShowWindow` в нём больше нет. Клавиши уходят, только если окно игры **уже активно**; нет —
  ответ `WAIT_FOCUS`, клавиша не отправляется (`-FocusWaitSec N` — подождать, не забирая фокус); активность
  проверяется перед каждой клавишей и сразу после неё.
- Игра запускается **в окне 960×540** логических (`--fullscreen=false --window_width/--window_height`, у SDK по
  умолчанию `fullscreen = true`), **без активации**: `SDL_WINDOW_ACTIVATE_WHEN_SHOWN=0` и
  `SDL_WINDOW_ACTIVATE_WHEN_RAISED=0` в окружении дочернего процесса (SDL показывает окно `SW_SHOWNA`). `-Fullscreen` —
  прежнее поведение, только по прямой просьбе пользователя.
- Снимки — `PrintWindow` (фокус не нужен, окно может лежать под другими); `-Fit 1280x720` приводит снимок к одному
  размеру при любом окне. Свёрнутое окно не снимается (`MINIMIZED`) и не разворачивается.
- **Ввод без клавиатуры вообще** — виртуальный геймпад порта, перенесён из NHL 13 (`port/src/nhl13_pad.cpp`,
  bfcd833): `src/nhllegacy_pad.cpp`, cvar `nhl_virtual_pad` (по умолчанию выкл.), врезки в
  `src/nhllegacy_input_lock.cpp` (после `XamInputGetState`, перед `XamInputGetKeystrokeEx`). Порт читает
  `nhllegacy_pad.txt` рядом с exe — строки «номер кнопки удержание_мс пауза_мс» (`A B X Y LB RB LT RT START BACK UP
  DOWN LEFT RIGHT LS RS`, сочетания через `+`) — и «жмёт» их пользователю 0 своего процесса; журнал
  `nhllegacy_pad.log`. В отличие от NHL 13 добавлены **стики до упора**: `LSL LSR LSU LSD` (левый) и `RSL RSR RSU RSD`
  (правый) — X_INPUT_STATE +8…+14 и события `VK_PAD_LTHUMB_*`/`RTHUMB_*`: без них не выбрать сторону и форму в «Играть

## Год (season_year)

Как в NHL 13 ([year-and-date.md](year-and-date.md)): `season_year` в `nhllegacy.toml` — первый год
сезона (2026 = 2026/27), 2015 — как на диске; франшизу грузить с тем же годом, с которым создана.

`src/nhllegacy_year.cpp`: результат `li`/`subfic`/`addi +Y` больше на `season_year − 2015`, `addi −Y`
(«номер сезона = год − 2015») — меньше, сравнения пересчитываются против `Y + сдвиг`.

| | мест |
|---|---:|
| `li`/`subfic`/`cmpwi`/`cmplwi` с 2014–2016 и `addi ±2014…2016` | 314 |
| сдвигаются | 259: 212 перенесённых врезок NHL 13 (число ровно +3) и 47 разобранных вручную |
| KEEP (не год лиги) | 55: адреса `lis+addi` 22, стек/кадр `addi rD, r1, 2016` 24, смещение +2016 в структуре 4, онлайн 3 («год продукта» 2016 в путях запросов, пара ±2015 в «SetPlayerStat»), факт «Phoenix до 2014» 1, маска RGB565 0x07E0 1 |
| EXTRA (производные) | 16: года рождения 1965/2000 (редактор), 1996/1995 («Стань профи»), 1986 и год драфта 2006 (созданный игрок), 2033 (год драфта сгенерированного), «недавний драфт» 2004, FeLeague 1994, пики драфта 115/121/2021 (год − 1900) |
| врезок | 275 (сравнения: 1965, 2004, 2014, 2015) |

Года 2011–2013 в коде Legacy (32 места) — не год лиги: те же совпадения, что в KEEP NHL 13, адреса,
константы ГСЧ. Попутно найдено для NHL 13 (не исправлено, порт NHL 13 не трогали): пики драфта
`82807734 li 112`, `8281E87C addi 118`, `8281EA3C addi 2018` не в EXTRA — при `season_year ≠ 2012` пики

## Счётчик AI-объекта +630 и очередь команд на 32 (09.10.2026)

**Симптом** (сейвы BE A GM5 за Сиэтл по ходу двух сезонов, блок AI-объекта в хвосте DYNASTY): счётчик +630 (i16, от
+632 = 154 вниз) — 98 (30.11.2026) → 8 (25.04.2027) → 8 (23.06) → **4891** (31.08) → **−2416** (1.11.2027); процент
+641 = 100·(+630)/(+632) — 63 → 5 → … → 100 → **224**. Процент 829742B0 отдаёт в 8297B450: по таблице из 7 диапазонов
«фаза сезона» для решений AI-GM — при 224 ни один диапазон не подходит, фаза 0. Падений нет, но AI с июля 2-го сезона
решает по неверной фазе, и так до конца франшизы: счётчик убывает только пока > 0, а init 829555B8 в начале сезона
ставит 154, и порча повторяется.

**Причина.** Байты +600+i — очередь команд AI-объекта: 82955F80 «перемешать» (+600[i] = i для i < +668, потом 20 обменов
двух случайных мест, 8297B8A0) и 82956028 «следующий» (у всех i < +668 байт −1, кто дошёл до 255 — тот; никого — перемешать
и снова). Обе идут по +600+i сами, без `add p, блок, i` перед доступом, поэтому сканер мест для `nhl_aigm32` их не нашёл. При
+668 = 32 байты 30/31 — это +630/+631, то есть сам счётчик. −2416 = 0xF690 — ровно 10 вызовов «следующего» после сброса на
154 = 0x009A: старший байт 0x00−10, младший 0x9A−10. 4891 = 0x131B — значения очереди 19/27 после перемешивания.

**Исправление** (`src/nhllegacy_aigm.cpp`, при `nhl_aigm32` и 32 командах): подмены `sub_82955F80` / `sub_82956028` делают
то же, но байты команд 30/31 держат в своём буфере (side+40/41, как остальные места +600[i]); случайные числа — та же
8297B8A0 игры. Ремонт при загрузке (Template): счётчик > 154 → 154, < 0 → 0 (лог `repaired counter +630 -2416 -> 0`);
init нового сезона всё равно ставит 154. Без `nhl_aigm32` — оригиналы, как было.
