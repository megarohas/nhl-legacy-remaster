# АХЛ на 32 клуба во франшизе: что менять в коде (08.10.2026)

Разбор только по сгенерированному коду и образу (`default.bin`), без запуска игры; сделанное в порту — «Код порта»
(в игре ещё не проверено). Список мест —
[`docs/ahl32_sites.json`](ahl32_sites.json) (формат `team32_sites.json` + `when: "ahl32"`), генератор —
[`tools/team_hooks.py`](../tools/team_hooks.py) (умеет `ahl32`, см. конец). Условие: cvar `nhl_ahl_teams = 32`, только
вместе с `nhl_teams = 32`; ниже `Nhl13Ahl32()`.

Целевая раскладка: НХЛ 0…31; АХЛ 32…63 (teamid 32…61 → номер = teamid, **220 → 62, 221 → 63**); проспекты 64/65
(teamid 209/210); CHL 66…125 (teamid 149…208); всего **126**. Дерево АХЛ: узел 17 — 43 48 55 58 220 221, узел 13 —
35 37 42 47 57 60 (Charlotte), конференции 16 + 16.

## Коротко

- Правкой константы закрывается мало: **11 мест «профи 60 → 64»** (в team32 это 62) и **1 цикл по клубам АХЛ**
  (828CF3C4, 30 → 32). Остальное — код порта: структура АХЛ, дописывание 220/221 при создании, перенос массива
  объектов АХЛ `league+772[30]`, перевод teamid ↔ номер для 220/221.
- Номера проспектов и CHL в коде не зашиты: проспекты — в состояниях 55/56, CHL — через первый номер лиги (состояние
  21). Сдвиг на +2 проходит сам.
- **Предел 126.** 126 команд — ровно столько, сколько помещается: номер 126 служебный (заглушка), массивы по номеру
  на 126, поле `team` статистики игроков — `[−1…126]`. **Сборных Матча звёзд при ahl32 быть не может** (при
  nhl_teams = 32 порт создаёт их после юниоров, номера 124/125) — при ahl32 их нет, и Матч звёзд выключен через
  состояние лиги 52 = 0 (свой путь игры, см. «Матч звёзд»); в базе — без строки Матча звёзд.
- Календарь АХЛ на все сезоны берётся из `ahlschedule` (генератора 6 × 5 у АХЛ нет) — нужен `ahlschedule` на 32 клуба.
- Таблицы: отметки x/y/z/e (8292A8B8) общие для НХЛ и АХЛ. Правки team32 «15 → 16» портили отметки АХЛ 15 + 15;
  теперь они действуют только у таблицы НХЛ, у АХЛ — при ahl32 (16 + 16).

## Как устроена АХЛ во франшизе

- **Состав и дерево** задаёт конструктор 82809848 (фабрика 82819268, лига 1): список r5 ← teamid 32…61 (цикл
  828098A4…828098BC, `cmpwi r31,61`), дерево «9 → конференции 10, 11 → узлы 14 15 17 | 12 13 16» (6 вызовов
  `bl 0x828FE278`: 82809904, 8280994C, 82809994, 828099F4, 82809A3C, 82809A84; массив r1+80 на 8 номеров),
  затем в дереве teamid → порядковый (828FE1D8(корень, t, t − 32), 82809AC0…82809ADC; только если корень ≠ 0).
- **Номера** выдаются по порядку записи строк `leagueteams` (82905418) в порядке списков лиг: группа 0 — НХЛ, АХЛ;
  после неё проспекты (828D4268, если группа 0); группа 1 — OHL, QMJHL, WHL. Первый номер лиги — состояние 21.
  828C0250 после записи переписывает список АХЛ как «число команд НХЛ + i» (828C04CC), 828CD4E8 на быстром пути — как
  «первый номер + i» (828CDF80, `li 30` → врезка 32).
- **Дерево франшизы** строится при создании (828F8808 → 828F72C8 → 828D41F8 → 828CAA90 → фабрика → 8289A950): значения
  сдвигаются на «первый номер − наименьшее» (82900DB0), т. е. порядковые 0…31 АХЛ → 32…63. Поэтому 220/221 в дереве
  нужно перевести в порядковые 30/31 (иначе сдвиг 0 и в дереве останутся 220/221). Других прямых вызовов фабрики,
  кроме меню (827C2BA8, 82911A48 вне франшизы — только НХЛ) и 828B68F0, нет. 828B68F0 — не режим «Плей-офф», как
  было написано раньше, а сетка плей-офф лиги (828B7A80 при создании франшизы): фабрика с видом 2/3 → 828173A0 /
  82809C88, до 82809848 (вид 0/1/4/5) не доходит. При загрузке франшизы дерево, видимо, берётся из сейва (не
  проверено).
- **Списки при создании** приходят из меню: меню (827C2BA8) строит АХЛ на 30 — значит 220/221, как и НХЛ 30/31,
  дописываются перед записью команд. Список дерева, который фабрика заполняет в 828CAA90, временный (r1+160).
- **Объект лиги** (828A7EB8): +16 список `{n; items[60]; flags[60]}`, +500 дерево, +520[30] фарм-клубы (НХЛ),
  +644[30] teamid (НХЛ), **+772[30] объекты клубов АХЛ** (у объекта лиги АХЛ; по 3244 б; 8289B0E8), +892 пул игроков АХЛ
  (записи по 6 б, байт +3 — порядковый АХЛ), +896 буфер 24960 б.
- **Сведения о команде** (200 б): +8 teamid, +190 `ahlaffiliate` — знаковый байт (extsb), значение после декодирования
  (`rangelow −1`): у `exhibitionteams` — teamid, у `leagueteams` — номер.

## 3. Проспекты, CHL, всего команд

- Проспекты: 828D4268 создаёт teamid 209/210 и пишет номера в состояния 55/56; читают 827DFEB8, 828DC460, 828DC570.
  Зашитых 62/63 нет — станут 64/65 сами.
- CHL: 827E06B0 = «первый teamid лиги − первый номер (состояние 21)»; вызовы — 828D9B18 (при создании переводит
  teamid юниоров в `leagueplayerbiotable`) и 8290D548 (лиги 8/9/10). 828CDC94…828CDCC0 — лига юниоров по teamid.
  Сдвиг +2 учтётся сам. Зашитых 64/84/102/124 нет.
- **126 — предел.** 126 команд (0…125) — ровно столько, сколько держит код:
  - номер 126 — заглушка: 828CEB5C (лига-заглушка в режиме 5, все команды = 126), 8289BBB0/8289BBD0;
  - массивы по номеру на 126: 828ECDD0 (r1+816 u32[126], куча 504 б, цикл `cmpwi r31,126` @828ED418),
    82910540/82910678 (r1+80 [126]), 82933910 (r1+352 [126]), 82925900 (r1+1764, 126 записей по 24 б);

  Значит при ahl32 **сборных быть не должно**: при nhl_teams = 32 порт создаёт их последними (sub_8289A868
  откладывается, sub_828E7AC0 вызывает после юниоров) — номера стали бы 126/127. При ahl32 sub_8289A868 их не

  выключается целиком — см. «Матч звёзд» ниже.

## Матч звёзд: откуда «матч с датой 0/0» и как его выключить

В c7efd3d записано: без строки Матча звёзд в `nhlschedule` «игра ставила матч с датой 0/0 и после перерыва теряла
дату франшизы». По коду цепочка такая:

- При создании франшизы 828A8060 пишет в **состояние лиги 52** поле +600 настроек лиги (у НХЛ 2 — «Матч звёзд со
  сборными»; то же поле 8289A868 проверяет перед созданием сборных).
- Каждый сезон 828B5A50 (из 828ED5E8) ставит события календаря франшизы (82820E00). Если состояние 52 ≠ 0 и есть
  дата типа 6 (828B5368: 82A549A0(год + 1, 0, 26), тип 7 — (год + 1, 0, 25), конец января; в онлайн-франшизе дат
  нет), — событие **5** за день до даты типа 7 и событие **6** за день до даты типа 6. Диспетчер 828EE300: 5 →
  82906DF0 (выбор сборных), 6 → 827A7788 (экран/сообщение 31).
- 82906DF0 → 82905278 (составы сборных) → 82900A70 → **82900AD0**: ищет Матч звёзд в календаре — 828E0D88 (запрос к
  `leaguescheduletable`: `home` или `away` = сборная A, плюс `status`/`month`) → 828D2B60 (первая найденная
  запись, 44 б: +4 `index`, +8 `month`, +12 `day`, +16 `home`, +20 `away`, +28 `status`, +32 `round`, +36/+40
  `league`) → подставляет сборные в +16/+20 → **828EA718: `UPDATE leaguescheduletable SET month, day, home, away,
  status, round, league WHERE index = запись.index`**.
- Если в календаре Матча звёзд нет, 828D2B60 ничего не копирует, а запись на стеке (r1+112) инициализирована только
  указателем таблицы: `index`, `month`, `day` — мусор стека. UPDATE переписывает какую-то игру (по-видимому, с
  `index` 0) на «сборная A — сборная B» с датой из мусора — это и есть «матч 0/0». Дальше игра считает её Матчем
  звёзд (828EDD58 — тип игры 3 по командам 53/54); как именно после перерыва теряется дата франшизы, по коду не
  прослежено (вероятно, дата берётся из этой игры).

Свой путь «без Матча звёзд» у игры есть — **состояние 52 = 0**: 828B5A50 не ставит события 5/6, 82880318 не
показывает сборные в списках, 828B5368 тип 6 (вне режимов 4/5/10) даёт 0. Без сборных так и надо: состояния 53/54
пустые (−16) — так же, как в онлайн-франшизе (8289A868 пишет −16, 828B5368 даёт 0 для типов 6/7). Остальные
пользователи 827DFE00 −16 переносят: сравнивают с командой (827BE6E8, 828EDD58), удаляют по команде (82806568 в
828F1548), сравнивают без знака (82915550 — тогда проходят все команды, как и при сборных 124/125 у team32).

Сделано в порту при ahl32: сборные не создаются (`sub_8289A868`), `lwz r5,600(r29)` @828A80A8 → 0
(`Nhl13AllStarGame`). Событий 5/6 нет, 82906DF0/82900AD0 не вызываются, перерыва нет.

**База** (`tools/nhl32.py --ahl32`): строку Матча звёзд в `nhlschedule` и `favoriteteamschedule` не добавлять
(`add_allstar` сейчас вызывается всегда). Без неё загрузчик 827B2300 не встретит игру «хозяева ≥ числа команд» и не
подставит сборные −16 (827B28C4…827B28F4); номера 0…31 помещаются в 5 бит, расширять `home`/`away` до 6 не нужно
(но и не вредно).

Не сделано: генератор календаря НХЛ со второго сезона (82859E48, пока на 6 × 5 — для НХЛ 32 не готов вообще)
вставляет Матч звёзд в день «даты типа 6» (82859DC8, команды 827DFE00 → −16 в 82859FB8/82859FCC). При состоянии
52 = 0 вне режимов 4/5/10 дата 0 — во что она раскладывается (82A54A70) и совпадёт ли с пустым днём сетки, не
проверено. Когда генератор будут переделывать на 32, без сборных вставку Матча звёзд надо пропускать.

## 4. teamid ↔ номер для АХЛ

Код ходит в базу по teamid из сведений (+8) — `leagueteams` хранит teamid (8 бит), названия, `artid`, `arenaid`, цвета,
соперников, `ahlaffiliate`, группы; формы, экипировка, тактика, составы, stock-статистика берутся по teamid. Чтение
`exhibitionteams` по номеру франшизы не найдено: 8290A8B8 во франшизе идёт в `leagueteams` (8290A670), прямые
829043C0 во франшизе — только при создании и по teamid (828C0250, 828CD4E8, 828D4268, 8289A868, 828A8338, 828DF880).
Арифметика, которая сломается на 220/221:

| Где | Сейчас | При ahl32 |
|---|---|---|
| 82809848 | дерево: teamid − 32 | 220 → 30, 221 → 31 (обёртка) |
| 828CDC30 | права игрока АХЛ без клуба НХЛ: teamid − 2 (+2 врезкой) | r16 — номер текущей команды |
| 828A8338 | фарм-клуб = s8(teamid) − 2 (+2 в обёртке) | (v & 0xFF) → номер: 220 → 62, 221 → 63; то же для 30/31 |
| 828A6080 | номер по teamid: обычно запрос к `leagueteams`; в онлайн-франшизе перебор 0…59, «нет» = 60 (порт: 61) | перебор всех номеров, «нет» = 64 |
| 827C0D00 | вне франшизы: «клуб АХЛ» = teamid 32…61, сравнение extsb | + 220/221, сравнение по & 0xFF |
| 8280F02C, 8283DEAC | контекст команды (82847640 → 82846B78) вне франшизы: extsb `ahlaffiliate` | & 0xFF |
| 827E06B0 | номер ↔ teamid по лиге | для АХЛ не вызывается (только CHL) |

Вне франшизы `exhibitionteams.ahlaffiliate` у Сиэтла/Вегаса = 220/221 — больше 127, в знаковом байте сведений
становится −36/−35. Во франшизе (`leagueteams`, номер ≤ 63) знак не мешает. 8289AAA0 (фарм-клубы из `leagueteams`) и
82905418 (запись `ahlaffiliate`) — без изменений.

Не трогаем: ачивки 82758EC0 (teamid 32…61 → «АХЛ − 32», новые клубы просто не считаются), 827A5460 (диапазоны teamid
лиг для настроек команд), 8290B618 (stock-статистика teamid ≤ 61), импорт игроков 828DF880/828DF6F0 (teamid
62…127, 209/210).

## 5. Календарь АХЛ

- **Первый сезон** (828FE9D0 → 827B2300, селектор 0): НХЛ из `nhlschedule` и АХЛ из `ahlschedule`
  (827B2B54/827B2B8C: home/away + 32) сливаются по датам (8285F5E8) прямо в `leaguetempscheduletable`. Порядковые
  30/31 → 62/63 — работает, если в `ahlschedule` 32 клуба: порядковый = teamid − 32, CVF = 30, HSK = 31 (5 бит).
- **Со второго сезона** (828DE2C8): для лиги с типом ≠ 0 8286AD88 идёт не в генератор 82859E48 (6 × 5 — только НХЛ),
  а в 827AF770 — снова `ahlschedule` + первый номер лиги (состояние 21) — и 8285F248. Если загрузка из базы
  (828DE2C8 с флагом), 827B2C58 переводит лигу 1 в селектор 2 — то же «+ первый номер». Своего генератора у АХЛ нет.
- Предсезонка (828DB828) — только у НХЛ (828DE57C). Матч звёзд в календаре АХЛ не проверяется.
- Ёмкость: буфер 1600 игр (kScheduleCapacity) ≥ 32 × 76 / 2 = 1216 (если 80 игр, как в правилах +140, — 1280);
  `leaguescheduletable` maxinsert 4000 ≥ 1344 + 64 + 1280; `leaguetempscheduletable` 3200 ≥ 1344 + 1216.

## Генератор

`tools/team_hooks.py` принимает несколько списков: `python team_hooks.py docs/team32_sites.json docs/ahl32_sites.json`.
У места (или у всего файла) — поле `when`: `team32` (по умолчанию) или `ahl32`. Один адрес из обоих списков — одна
врезка: при `Nhl13Ahl32()` — число ahl32, иначе при `Nhl13ThirtyTwo()` — team32 (`Nhl13CmpS_62_a64`, `Nhl13Li_248_a256`);
только ahl32 — `Nhl13CmpS_a32`. Поле `gate` у места team32 — своё условие вместо `Nhl13ThirtyTwo()`: `"Имя(rN)"` —
`bool Имя(PPCRegister&)` из `src/nhl13_teams.cpp`, регистр rN — последний параметр врезки (`Nhl13Li_16_StandingsWide`).
Без мест ahl32 и `gate` вывод совпадает с прежним байт в байт (проверено). `--out-dir DIR` пишет оба файла в DIR (для
сверки), `--report` показывает и поле `needs`. Поля `done`/`manual`/`already`/`skipped` генератор не читает.
