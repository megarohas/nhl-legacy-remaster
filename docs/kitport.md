# Перенос форм из новых EA NHL в NHL Legacy: руководство и инструмент `kitport`

20.10.2026. Сводит всё, что выяснилось при переносе форм NHL 24 (PS4) в NHL Legacy (09–20.10), в одно место.
Документ для того, кто будет переносить формы снова: из NHL 24 другим клубам, из NHL 27 (PS5) или другого источника.

- **Инструмент** — `tools/kitport/`: одна точка входа для сборки, установки, отката и проверки
  (`cd tools && python -m kitport --help`).
- **Подробности** по датам и замечаниям пользователя — [nhl24-uniforms.md](nhl24-uniforms.md). Там же журнал
  установок §15.1.
- **Устройство форм Legacy** и как игра выбирает форму — [uniforms.md](uniforms.md).
- **Чтение дампа Frostbite** и первое знакомство с новым дампом — [frostbite-sources.md](frostbite-sources.md).
- **Ассеты EA** (текстуры, сетки, базы NHL 24 и Legacy) — только для личного использования. Они лежат в `game/`
  вне git, в репозитории только код и описания.

## 0. Быстрый старт: правка формы

Окружение — venv `game/work/nhl24/venv`, запуск из `tools/`:

```bash
cd tools
P=../game/work/nhl24/venv/Scripts/python.exe
$P -m kitport doctor                       # всё ли на месте: пакеты, распаковки, cache:, игра
$P -m kitport snapshot --tag before        # «было» — до правки
#   …правка параметра в tools/fb/edge_kit.py (каталог — $P -m kitport params, раздел 6)…
$P -m kitport build --club MIN --kits away,home   # kit → slot → pack → overlay (логи — edgekit/logs/)
$P -m kitport compare --clubs MIN          # сколько текселей и где изменилось (уже готовые клубы — как раньше?)
$P -m kitport sheet                        # лист «было | стало» → game/work/nhl24/compare/kitport/
$P -m kitport diff                         # какие файлы поменяются в игре
$P -m kitport install --tag edge12         # игра закрыта: копия заменяемого, установка, сверка
#   …строку из вывода install дописать в журнал nhl24-uniforms.md §15.1, коммит…
$P -m kitport rollback user-20261020-edge12   # если не понравилось
```

| Команда | Что делает |
|---|---|
| `doctor` | python и пакеты, `bash`, рабочие папки, распаковки NHL 24 и Legacy, шрифт надписи, `cache:`, флаги установки, запущена ли игра, ветка git |
| `status` | сколько файлов сборки отличается от игры, пак `pack-edge` и прежние версии, последние копии, слоты, журнал |
| `snapshot` | копия файлов слота форм (`edgekit/slot/kits/<КЛУБ>_<форма>`) — «было» для `sheet` и `compare` |
| `compare [--clubs MIN] [--before DIR]` | слот против снимка: по текстуре доля изменённых текселей (порог 8 из 255), рамка изменений в долях развёртки, картинка «было \| стало \| разница ×4» в `<снимок>/diff/`. После правки общего кода — проверить, что готовые клубы не поменялись там, где не должны |
| `build` | стадии подхода C: `kit`, `slot`, `pack` (прежний пак → `pack-edge-vN`), `overlay` (`build-all.sh nhl24`); `--meshes` — и сетки. Выезд всегда собирается раньше дома |
| `diff` | сборка `legacy-data/out*` в порядке наложения против `cache:` |
| `install --tag T` | игра закрыта → копия заменяемого в `backup-cache/user-<дата>-T` (с `manifest.json`), установщик с флагами прошлой установки, сверка, заготовка строки журнала |
| `rollback DIR` | вернуть файлы из `backup-cache/DIR`, новые (по манифесту) — убрать |
| `sheet` | лист: надпись сзади (цвет и рельеф, повёрнуто как на спине), перед с зонами буквы капитана, плечи, вся развёртка — по строке «было / стало» на форму |
| `check [--clubs MIN,NJD]` | лист проверки форм слота: ворот спереди и в 3/4, рельеф без цвета спереди и сзади, контур зон номеров на рукаве, шрифт на цвете свитера, превью меню; у ворота без шнуровки — замер щита (верх, низ, сколько до кромки любого цвета). Лист — `compare/kitport/check-<дата>.png` |
| `present [--clubs TBL] [--kits home,away] [--name … --number … --letter C]` | лист «ставим или правим» на каждую форму слота (§8.1): наша форма на Edge и оригинал источника теми же видами, «одетый» свитер (фамилия, номер, буква), игрок целиком (свитер, шорты, гетры), каска, наклейка, шрифт. Листы — `compare/kitport/present-<КЛУБ>_<форма>-<дата>.png` |
| `uvmap [--plain]` | схема развёртки свитера: части тела, высоты, зоны карты номеров (рис. ниже) |
| `params` | ключевые параметры формы: значение сейчас, единицы, почему такое |
| `survey [--source nhl27] [--clubs …]` | обзор форм клубов источника на сетке NHL 24: перед, плечо, ворот крупно — разбор клубов по типам (§12), листы в `game/work/<источник>/kit-survey/` (`survey_N.png` — все клубы; с `--clubs` — свой лист `survey_<клубы>.png`) |
| `profile --club BOS [--write] [--write-palette]` | генератор профиля клуба из NHL 27 (§12.3, §12.6): комплекты источника, образцы Legacy, ворот и кокетка по текстуре, герб из частей, рельеф нашивок в основе, реклама на груди, щит, номера в реестре (с перенумерацией не поставленных), каска и краги из базы NHL 27, палитра — предложение. Каждое решение — «уверен» / «проверить» с причиной, сравнение с уже записанным. Без `--write` ничего не пишет; без `--write` можно несколько клубов (`--club NJD,TBL`). `default` не ставит никогда |

## 1. Три подхода к свитеру

| | A. Гибрид на Edge | B. Сетка adidas в слоте стиля 0 | C. Edge с передом ворота NHL 24 |
|---|---|---|---|
| Когда | 09–12.10 | 15–16.10 | 19–20.10, **текущий** |
| Сетка | Edge Legacy стиля 1 как есть | сетка NHL 24, подогнанная к Edge, вместо сеток стиля 0 | изогнутая копия Edge (перед ворота поднят к краю NHL 24) вместо сеток стиля 0 |
| Текстура | перенос NHL 24 через 3D + нашивки декалями по правилам `kit_rules.toml` | своя развёртка NHL 24 | перенос по гладким координатам, ворот, кокетка, вставка — свои «маляры», рельеф и блеск заново |
| Модули | `fb.kit_hybrid`, `kit_batch`, `pilot`, `kit_fix`, `sleeve` | `fb.jersey_mesh` | `fb.edge_kit` (на базе `pilot.cmd_build`) |
| Охват | пакет на 32 клуба (дом, выезд, третья) | 62 формы «Home/Away (adidas)» | только MIN (дом и выезд) |
| Минусы | круглый ворот adidas на V Edge — щит и ворот «не садятся»; шнуровка — правилом | плечи и талия по adidas, шея — много правок (v1–v6) | всё, что зависит от клуба, пока прописано под MIN (§5.3) |

Подход B′ (`fb.jersey_hybrid`, 18.10) — Edge плюс кусок сетки adidas у ворота. Отброшен: волны и лесенки рисунка.

Поле `style` в базе — 1 бит. Значит, своих сеток может быть только две: стиль 0 и стиль 1. Подходы B и C занимают
слот стиля 0 вместо ретро-сеток. Формы стиля 0 других клубов на новых сетках «поплывут» — пользователь принял
(19.10).

## 2. Форма NHL Legacy изнутри (от источника не зависит)

### 2.1. Сетки

- **Имя** — `rendering/jersey/jersey_G_S_C_T_P_L.rx2` (60 файлов, `nocacherender.big`):
  - G — 0 полевой, 1 вратарь;
  - S — стиль: 0 (ретро, мешковатый) или 1 (Reebok Edge);
  - C — у полевых 2, у вратаря — рука ловушки 0/1;
  - T — заправка `jerseytuck`: 0 навыпуск, 1 слева (+x), 2 справа (−x), 3 весь;
  - P — наплечники: 0 (плечо 1,691 м), 1 (1,708 м);
  - L — детализация: `_2` ближняя, `_0` средняя, `_3` дальняя. Таблица игры: LOD 0/1/2 → `_3`/`_0`/`_2`.
- **Вершин** у стиля 1: `_2` — 2055, `_0` — 440, `_3` — 155. Стиль 0 `_2` — 1896, вратарь стиля 1 — 1947.
- **Одна сетка на стиль для всех клубов.** Вырезы («тонкий длинный», «клин» у PIT) — это рисунок V-вставки в
  текстуре, геометрии у них нет.
- **Шнуровка** `jerseytie_G_S_L` (208 вершин) — включается полем `hastie`. Новым формам `hastie` 0.
- **«Рубашка»** `shirt_G_G_L` — тёмная горловина под V-вырезом. У полевых одна на все стили. Её развёртка — в углу
  текстуры свитера (u 0,08…0,18, v 0,85…0,90).
- **Затенение (AO)** — `rendering/jersey/texlib_S_999.rx2`, растры `jersey_S_G_T_am` 256² DXT1. `texlib_1_999` — в
  `renderboot.big`.
- **Вершина — 32 байта:** позиция, нормаль, касательная вдоль +u (у NHL 24 — вдоль −u), UV, 4 кости с весами (сумма
  255). Треугольники — полосы с разрывом 0xFFFF. Пересборка — `rw4mesh.Mesh.rebuilt`.
- **Кости и веса** брать с сетки в `cache:` пользователя, а не из архива: там стоит мод края спины NHL 10
  (`tools/jersey10.py`).
- **Кости:** 48/79 ключица, 49/80 плечо (0,21 м от оси), 50/81 поворот плеча, 51/82 локоть, 52–54/83–85 предплечье и
  кисть.

### 2.2. Развёртка (1024²)

Схема — `cd tools && python -m kitport uvmap --plain` → `game/work/nhl24/compare/kitport/uvmap-MIN_away.png` (картинку
в репозиторий не кладём: публичный GitHub принимает только текст, а развёртка снята с сетки EA). Цвет — часть тела по 3D-точке, белые линии — высота над льдом через 10 см,
жёлтое — зоны карты номеров MIN_away.

- **Раскладка.** Спина сверху, грудь снизу по центру, рукава — по краям, плечи у ворота.
- **Направления.** u → вправо, v → вниз. На спине и рукавах +v смотрит вверх по свитеру, на груди — вниз. Надпись
  сзади на развёртке лежит вверх ногами.
- **Рукава:**
  - левый манжет у u = 0, правый у u = 1;
  - строки рукава — v 0,28–0,73;
  - у Edge рукав — u 0…0,234 (дальше пройма), шов проймы — таблица `edge_kit.ARMHOLE_UV`.
- **Опорные точки (u, v):**

  | Что | Где | Откуда |
  |---|---|---|
  | щит NHL у всех 53 EA-форм | центр (0,5; 0,595) | `kit_rules.toml` `[patch.neck_shield] legacy_uv` |
  | Reebok сзади у EA | центр (0,5; 0,4085), ширина 0,064 (1,648 м); у нас — (0,5; 0,4183), 1,663 м | `[brand]`, `edge_kit.REEBOK_BACK_UV` |
  | низ герба у EA | медиана v 0,826, у 90 % не ниже 0,85 | `kit_fix survey` |
  | зазор «герб — зона буквы» у EA | медиана 0,02 | там же |
  | реглан | спина v 0,3916 (≈1,616 м), грудь v 0,561 (≈1,65 м), верх плеча ≈ 0,48 | `edge_kit.RAGLAN_V` |
  | пустой угол атласа (нет треугольников и зон) | (0,006…0,252; 0,006…0,274) — сюда `edge_kit` кладёт остров переда ворота | `edge_kit.ISL_BOX` |
  | развёртка шнуровки | 0,82…0,95 × 0,79…0,95 | — |

- **Плотность.** Edge — 659 px/м (≈1,5 мм на тексель у груди, 2,4–3 мм у переда ворота). NHL 24 — 1216 px/м на
  2048² (≈0,8 мм). Остров переда ворота — 1,31 мм.

### 2.3. Текстуры одного комплекта

Комплект — 5 файлов, плюс наклейка на шлем по флагу. `S` — стиль, `A` — `teamartid`, `V` — вариант, `F` — `fevariant`.

| Файл в `cache:` | Растры | Размер, формат |
|---|---|---|
| `rendering/jersey/texlib_S_A_V.rx2` | `jersey_S_A_V_cm`, `_sm`, `_0_nm`; `font_S_A_V_cm`, `_nm`, `_sm` | свитер 1024²: DXT1 / DXT1 / DXN; шрифт 512²: DXT5 / DXN / DXT1 (1-бит альфа) |
| `rendering/jersey/name_S_A_V_cm.rx2` | карта номеров | 256², 8888 линейно |
| `rendering/pant/texlib_S_A_V.rx2` | `pant_cm/_nm/_sm` | 512² / 512² / 256²: DXT1 / DXN / DXT1 |
| `rendering/sock/sock_S_A_V_cm.rx2` | гетры | 1024×512 DXT1 (нормали и блеск — общие `sock_S_*`) |
| `fe/ion/artassets/jerseys/jersey_S_A_F.big` | превью в меню | BIGF/XPR2, 256², 8888 с тайлингом |
| `rendering/logo/texlib_A_S_V.rx2` (сначала арт!) | наклейка на шлем `logo_A_S_V_0` | 256×128 DXT5; только при `helmetlogo` 1 |

- **Имена растров внутри файла обязательны.** Игра ищет `jersey_%i_%i_%i_cm.Raster` и т. п. Новый номер
  переписывается на месте, только той же длины. Номер другой длины собирается из контейнера EA подходящей длины:
  - трёхзначный арт → `1_131_0`;
  - двузначный вариант → `1_10_0`;
  - наклейки по длине «A_1_V»: 5 → `texlib_0_1_0`, 6 → `texlib_10_1_0`, 7 → `texlib_127_1_0`.
- **Мипы** — вся цепочка, хвост ≤ 16 текселей упакован по правилам Xenos. Иначе издалека виден шаблон.
- **Несжатый RW4 в `cache:` игра принимает.**
- **Блеск ткани.** У EA медиана `jersey_sm` ≈ 16 из 255, у основных форм MIN — 16–18. Чистая карта Edge T=4 —
  медиана 30, в неё «запечены» V-вырез с молнией, реглан и Reebok: в игре это видно бликами старых швов.

### 2.4. Карта номеров `name_*_cm` (256²)

- **Кодировка:** «жёлтое» (R, G > 128), номер зоны — в синем канале, 255 — фон.
- **Зоны:**
  - 0 — фамилия;
  - 1 — номер на спине;
  - 2 и 3 — номера на рукавах (u ≈ 0,25 и 0,75);
  - **5 — буква капитана или ассистента**;
  - 7 — второе место буквы (у EA буквы стоят у ворота с двух сторон).
  - Зоны 4 и 6 не встречались.
- **У каждого комплекта EA свои прямоугольники.** Игра берёт их из карты, глифы — из атласа шрифта комплекта.
  Пример: у `1_14_3` зоны 5/7 на 0,023 по v ниже, чем у `1_14_4` → `edge_kit.LETTER_ZONES_FROM`.
- **Как игра раскладывает буквы фамилии** (разрядка, дуга) — не разбиралось.

### 2.5. Атлас шрифта (512², одинаков у всех EA)

- **Области:** буквы (0,0)-(512,98); большие цифры с C/A (0,98)-(512,368); малые цифры (0,368)-(512,512).
- **Строки по y:** A–O 1–48, P–Z 49–98, 0–4 115–238, 5–9 242–367, C 83–190, A 195–302, малые цифры 379–438 и
  450–512. Центры клеток — `jersey_mesh.FONT_SLOTS`.
- **У NHL 24 атлас 1024² — та же раскладка ×2.** Перенос: уменьшение с премультипликацией альфы (`fb.fonts`).

### 2.6. Превью в меню

- **Имя:** `fe/ion/artassets/jerseys/jersey_S_A_F.big`, из полей +16 `style`, +8 `teamartid`, +20 `fevariant`.
- **Поза EA.** У всех превью стиля 1 один манекен. Модель позы — `game/work/legacy-data/fepose/pose.bin`
  (`tools/fepose.py fit --game legacy`), снята с развёртки Edge с её V-вырезом.

### 2.7. База и сейвы

- **`stockteamjerseys`:**
  - поля: `teamid`, `teamartid` (по нему называются файлы), `style`, `variant`, `fevariant`, `jerseyindex`,
    `isdefault`, `islightcolor`, `hastie`, `helmetlogo`, `helmetnumbers`, `islockable`;
  - `locstring`: 0 дом, 1 выезд, 2 третья, 3–5 — 2006/07, 6 — подпись из ключа `Vintage_S_A_V` в
    `fe/loc/NHL_ENG_US.db` (без ключа подписи нет);
  - `jerseyindex`, `variant`, `fevariant` — по 5 бит, до 32 форм на клуб; `jerseyindex` подряд 0…N−1.
- **Форма по умолчанию** — среди строк с `isdefault` ≠ 0 та, у которой `locstring` 0 / 1. Новым дому и выезду —
  `locstring` 0/1, прежним — 6 с подписью «(EA)».
- **Шлем** — `stockteamequipmenttable`. Поля с `rangelow` −1: в базе значение +1 (шлем — `equipment` 7, в базе 8).
  Ключ поиска: (era = `style` формы, variant, equipment 7, бренд каски). Модель — `nhl24.py add_helmets`.
- **Новые строки** — только в конец таблиц (`phase` в манифесте). Номера — реестр `tools/legacy_data/nhl24_kits.json`:
  `nhl24.py alloc`, затем `order`.
- **Сейв ROSTER хранит формы сам.** После установки — `nhl24.py save "<ROSTER>" --write` (копия — в
  `backup-saves/`). В DYNASTY таблицы форм нет. Таблица экипировки в сейве ограничена: 6045 записей, при 6050 —
  «ROSTER damaged».

## 3. Источник NHL 24 (PS4): что брали

- **Дамп** `game/other/nhl24/Data` (Frostbite Gen4b). Каталог и выгрузка — `tools/fb/`, см.
  [frostbite-sources.md](frostbite-sources.md).
- **Сетки свитера:** `content/character/skater/player/jersey/<крой>/components/player_jersey_<крой>_<заправка>_<размер>_lod0…2_mesh`.
  - Крои: adidas (с 2017, круглый ворот), rbk (Edge 2007–17, V), nineties.
  - У всех 24 полевых сеток одна топология: 3160 вершин, 5962 треугольника.
  - Рамка: x ±0,51 м, y 0,93–1,72 м, метры, Y вверх, +Z — грудь.
  - Вратарь — 3348 вершин.
- **Текстуры** — `content/character/skater/league/nhl/<клуб>/<крой>/<комплект>/`:
  - `jersey_*_color` 2048² BC1 sRGB — готовый свитер со всеми нашивками;
  - `_normal` BC5, `_coeff` BC1;
  - `pant_*` 2048², `sock_*_color` 1024²;
  - `font_*` 1024² — атлас EA ×2;
  - `helmetlogo_*` 1024×512;
  - `*_base_*` — основа без нашивок, есть у 122 комплектов adidas с 2022–23. Нет у BOS, BUF, CGY, CAR, EDM, OTT,
    PHI, SJ, VAN;
  - `branding_jersey_*_N_*` — нашивки слоями.
- **Комплекты:** `home`, `away`, `three`, прошлые `two`, `four`…`nine`, Reverse Retro `twentytwo`, `twentythree`. Всего
  570 (adidas 246, rbk 194, nineties 130).
- **Номера и фамилии** не запечены — атлас плюс раскладка, как в Legacy.
- **Особенности:**
  - центр ворота adidas на 3,5–4 мм левее оси (`edge_kit.x_fix`, `SHIELD_OFFSET_CM`);
  - нормали: X вдоль +u, Y — по DirectX; кладутся как есть, B восстанавливается;
  - кокетка спереди 1,63 м, сзади 1,648 м; у EA спина 1,60 м.
- **Раскладку нашивок и флаг шнуровки** (EBX `stamp_jersey_*`) мы не читали: типы EBX — в exe, в дампе их нет.
  Нашивки находятся как «готовый минус основа».

### 5.2. Что делает `edge_kit kit` внутри

Это `pilot.cmd_build` с подменами, комплект собирается до трёх раз:
1. без кокетки — чтобы снять её многоугольник и цвета;
2. для цветов вставки;
3. итоговая сборка.

Цепочка:
- **сетка:**
  - `deform` — перед ворота поднят;
  - `Island` — остров переда ворота в пустом углу атласа, только у lod 2;
- **перенос** — `coord_transfer` по гладким координатам (`CoordMap`), рукав — `SleeveMap` (полосы ровно по шву,
  сжатие к кисти в самом переносе);
- **«маляры» до нашивок:** кокетка `YokePaint`, кромка `TrimPaint`, вставка `InsertPaint`;
- **нашивки:**
  - щит — на месте NHL 24 (`SHIELD_OFFSET_CM`, `SHIELD_SCALE`);
  - плечевые — к шее и меньше (`SHOULDER_*`);
- **надпись сзади** — `BrandSwap` (свой рисунок `wordmark_alpha`, рельеф `wordmark_relief`);
- **рельеф и блеск** — `rebuild_relief`: складки и плетение Edge без его швов, свои швы по границам цветов, сетка
  кокетки, ровный блеск `SM_BASE`;
- **хвосты:** `pad_island` → `fill_old_place` (тот же рисунок на старом месте атласа — для lod 0/3) → превью.

  где меряет `kitport check`) и верх «серебра» щита при посадке `kit_hybrid.plan_decals`, и делением отрезка находит
  сдвиг по высоте (x — 0,41 см, как у всех). Проверка без сборки — `python -m fb.edge_kit shield --club КЛУБ [--gap 4]`:

  `shield_gap_mm`, ни `shield_offset_cm`, ворот без шнуровки — `SHIELD_GAP_DEFAULT_MM` 4 мм (решение пользователя по
  NJD 3 мм и TBL 4–5 мм). `"source"` — зазор источника: у NHL 27 кромки посередине переда нет (вырез adidas), щит на
  5,4 мм ниже края ворота у тёмных форм и на 6,8 мм у белых. Задан `shield_offset_cm` (MIN, NJD, TBL) — как раньше,
  байт в байт: расчёт не включается. Для TBL при 4 мм расчёт даёт y −0,18 / −0,25 см — пользователь подбором пришёл к
  −0,20.
- `sock = auto` — ровные полосы по гетрам источника этой формы (`edge_kit.sock_parts_auto`: ткань — самый частый

- `helmet_logo = source` — `helmetlogo` источника (у NHL 27 — реклама Prudential), уменьшение с премультипликацией в
  контейнер наклейки той же длины имени (`HELMET_CONTAINERS`).
- Номер формы другой длины, чем у образца (`0_17_10`): контейнер `kitpaint` — форма стиля 0 из архива с номером той
  же длины (`slot_container`, `0_108_0`).
- Цвет каски — `tools/legacy_data/nhl24_helmets.json`. Значение — `[R, G, B]` (каска, зоны 2–9 как у тёмных шлемов
  EA) или `{"zones": [...]}` — зоны по порядку. Так, например, зоны 1–9 из `stockteamequipmenttable` NHL 27.

Новый клуб:
1. Номера форм в реестре: `nhl24.py alloc КЛУБ edge_home edge_away --style 0 --write`. `jerseyindex` у клуба —

   стоит, иначе он сдвинет уже поставленные формы. Если в реестре между ними есть не поставленные формы, номера
   правятся в реестре вручную (NJD, 21.10: edge 12/13, прежние не поставленные three/home/away — 14–16).
2. Раздел клуба в `edge_clubs.toml`. При необходимости — цвет каски в `nhl24_helmets.json`.
3. Сборка и проверка: `kitport build --club КЛУБ --stages kit`, листы; затем `slot`, `pack,overlay`, `install`.

**NJD из NHL 27 (21.10).** Что пришлось поправить по ходу:

Замечания пользователя по NJD и что сделано (21.10):

## 6. Каталог параметров

Значения сейчас — `python -m kitport params`. Ниже — смысл и происхождение. Даты — решения пользователя.

### 6.1. Ворот и щит

- `LIFT_TH` (40°, 88°), `LIFT_R` 0,075 м — край ворота как у adidas до 40° от середины переда, к 88° как у Edge.
- **Остров развёртки:**
  - `ISL_D` 0,075 м, `ISL_TH` 88°;
  - `ISL_LACE` — столбец шнуровки (|x| 0,048, низ 1,540 м; при 0,042/1,57 по низу планки шли зубцы, 19.10);
  - `ISLAND_LODS` (2,) — у lod 0/3 остров давал клинья у кокетки (20.10).
- **Щит:**
  - `SHIELD_SCALE` 0,88 — «слишком большой» (19.10); у EA на Edge — 0,8;
  - `SHIELD_OFFSET_CM` [0,41; 0,6; 0] — x: середина горловины NHL 24 левее оси;
  - в подходе A — `legacy_uv` (0,5; 0,595) и ×0,8 (12.10).
- **Вставка и кромка:**
  - `INSERT_HW` — полуширина вставки по высоте, «края ровные, а не полукругами»; угол на 1,629 м;
  - `TRIM_K` 1,3 — кромка «чуть побольше» (19.10); `TRIM_D` (0,012; 0,03).
- **Ворот со шнуровкой в подходе A** — правило `[collar_lace]` (раскладка EA `1_14_2`/`1_14_3`, режимы `recolor`
  false / "palette"), MIN дом — v4 (12.10).

### 6.2. Плечи и кокетка

- **Плечевые нашивки:**
  - `SHOULDER_IN_CM` 2,0 — заходили на границу кокетки (19.10);
  - `SHOULDER_SCALE` 0,9 — «близковато к соседним элементам» (20.10).
- **Кокетка:**
  - `YOKE` — по EA-форме клуба;
  - `YOKE_BACK_FROM` `1_14_3` — у NHL 24 спина 1,648 м, «зелёное кончается высоко»;
  - `YOKE_PAD` 0,05 — при 0,02 были тёмные следы у плеч.
- **Сетчатая ткань кокетки** («у погон решётчатая», 19.10):
  - `PERF_CELL` 4×4 текселя ≈ 6–8 мм;
  - `PERF_RMS` 40 (у NHL 24 ≈ 50/127, у плетения Edge ≈ 6);
  - `PERF_SM` 6 — ямки тусклее.
- **Пройма** — `ARMHOLE_UV` (по EA MIN `1_14_0`), `ARMHOLE_ZONES`, `ARMHOLE_X` 0,15 м.

### 6.3. Рукава

- **Подход C.** `SLV_U` (0; 0,234), `SLV_V` (0,30; 0,72), `SLV_U24` (0,03; 0,30) — рукав по координатам руки: полосы
  «ровно по шву, а не волной» (19.10).
- **Правило `[sleeve]`** (11.10, все подходы) — полосы ближе к кисти:
  - `rows` [0,28; 0,73], `gap_min` 0,05 до зоны номера, `base_k` 0,85, `min_k` 0,7;
  - образец — EA CHI `1_6_0`, зазор 0,066;
  - в подходе C сжатие идёт в самом переносе, правило `pilot` выключено: оно тянуло грудную полосу в строках
    подмышки.
- **Граница полосы** (21.10) — смена цвета по ≥ 0,8 кольца (`SLV_RING_FRAC`). **Над полосами** нет места у рукава Edge

### 8.1. Лист «ставим или правим»: `kitport present`

| Строка листа | Что на ней | Откуда |
|---|---|---|
| 1. Наша форма | перед, спина, бок, ворот крупно (цвет и рельеф) на сетке Edge слота; превью меню | `slot/kits/<КЛУБ>_<форма>/jersey_cm, _nm, fe.png`, сетка `edge_kit.mesh_for(0, 1, 2)` |

| 3. «Одетый» свитер | спина (фамилия, номер), бок (номер на рукаве), 3/4, перед (буква) | карта номеров `name_cm.png` и атлас `font_cm.png` слота |
| 4. Игрок | свитер, шорты, гетры — наш (сетки Legacy `pilot.PANT_L`, `SOCK_L`) и оригинал (сетки NHL 24); каска; наклейка; атлас шрифта на цвете под фамилией | `pant_cm/_nm`, `sock_cm` слота; цвет каски — `nhl24_helmets.json` (зона 1); наклейка — `slot/cache/rendering/logo/texlib_A_0_V.rx2` |

Фамилия и номер по умолчанию — звезда клуба (`jersey_mesh.STARS`: TBL — KUCHEROV 86), буква — C; свои — `--name`,
`--number`, `--letter`.

**«Одетый» свитер — насколько он похож на игру.**
- Точно: места — прямоугольники зон карты номеров слота (по ней рисует игра: зона 0 — фамилия, 1 — номер, 2/3 —
  рукава, 5 — буква; 7 — второе место буквы, на листе обведено жёлтым); глифы — из атласа слота. Нарезка атласа —
  `jersey_mesh.font_glyphs`: строки `FONT_ROWS` (§2.5), внутри строки — по пустым столбцам альфы, у букв — к центрам
  клеток EA `FONT_SLOTS` (между ними бывают `'` `.` `-`). На всех атласах слота (MIN, NJD, TBL) находятся все 58 знаков.
- Приблизительно (как раскладывает игра — не разбиралось, §11):
  - высота надписи — высота зоны, по центру зоны; шире зоны — сжатие по ширине;
  - разрядка фамилии — 0,06 высоты букв, цифр номера — 0,05, без дуги;
  - номер на рукаве — малые цифры (строка атласа 379–438), какую из двух строк малых цифр берёт игра — неизвестно;
  - «вверх» надписи — мировой +y в плоскости ткани в середине зоны (`jersey_mesh.stamp`). Игра, скорее всего,
    кладёт глифы прямо в прямоугольник зоны на развёртке: на спине это то же самое, на рукаве угол может отличаться;
  - зона 5 или 7 — где игра ставит C, а где A, не проверялось: буква — в зоне 5.
- Значит, по листу видно, **где** элементы и не наезжают ли они на рисунок (полосы рукава, герб), но не точный кегль
  и разрядку. Окончательно — в игре.

## 10. Грабли (и как обошли)

**Источник и упаковка**
- Без TOC чанки не находятся или путаются по размеру → TOC, сверка sha1 каждого чанка (`fb.verify`).
- UV разных сеток «похожи», но как есть не садятся (25–70 px) → только 3D-перенос.
- Длина номера меняет длину имён растров → контейнеры подходящей длины (§2.3).

**Нашивки и ворот**
- Круглый ворот adidas на V Edge: в V ложилась изнанка ворота → заливка цветом свитера по моде окна.
- Щит уходил под воротник → точка EA (0,5; 0,595) и ×0,8 (A), своё место NHL 24 (C).
- Без основы без нашивок (`base`):
  - в A — щит и бренд вырезаются из стандартных мест;
  - в B — герб закрашивается тканью зеркально.
- Герб на букве капитана → `[crest_fit]`; блёстки VGK не должны попасть в маску → окно сглаживается.
- Двойной «Reebok» в рельефе; гладкий прямоугольник под надписью без сетки → рельеф там же, где цвет; метки
  чистого рельефа — только в складках.

**Рукава и номера**
- Полосы рукава у локтя под номером → `[sleeve]`. В подходе C полосы шли волной → `SleeveMap`.
- Карта номеров czkit с зонами рукавов вдвое больше → карта EA контейнера.
- Фамилия цветом кокетки → `NAME_CONTRAST`.
- PHI: буквы шрифта на белой подложке → нарезка атласа по цвету.

**База и сейвы**
- Белые шлемы у новых форм: сдвиг `rangelow`, era, порядок загрузки → модель `add_helmets`.
- Новые формы по умолчанию не находились (`locstring` 6) → дом/выезд 0/1, прежние — 6 «(EA)».
- `isdefault` у слота стиля 0 как домашнюю игра не берёт.
- Без `nhl24.py save` новых форм в составах нет; сейв на старой базе может не вместить строки экипировки.

**Сетки (B, C)**
- Сетка adidas (B):
  - «плечи странные», «приталенность» → тело по Edge (`morph_to`);
  - «чёрное вокруг шеи», «горб» сзади, ворот торчит в посадке катания → правки v3–v6 по 12 секторам вокруг шеи;
  - у вратаря поднятый ворот вытягивал шею, маска проваливалась → у вратарей ворот над рубашкой не поднимать.
- Ворот и вставка NHL 24 на 4 мм левее оси → `x_fix`.
- Остров на lod 0/3 давал клинья → остров только на lod 2, на старом месте атласа тот же рисунок, края добиты.
- AO острова брал серый фон угла → `ao_for_slot`.
- Белая рубашка торчала кольцом у выезда → цвет подкладки NHL 24.
- Вратари без подъёма ворота: рисунок ложился на V Edge → тот же сдвиг края, что у полевого.
- Старые швы Edge видны блеском при новом рельефе → блеск тоже заново.

**Превью**
- Модель позы снята с V-выреза → сдвиг поднятого ворота.
- «Шнуровка — месиво» → проекция сетки, крупные шнурки.
- Швы EA в свете модели («и новые, и старые») → медианой.

**Окружение**
- Python на Windows пишет текстовые файлы с CRLF, `sed` из Git Bash превращает CRLF в LF. У части файлов репозитория
  окончания строк смешанные. Править с сохранением окончаний (бинарно или построчно), проверять `git diff --stat`.

### 12.1. Типы форм adidas (что различает их для инструмента)

- **Кокетка** (`yoke`, `yoke_color`, `yoke_shape_color`):
  - нет;
  - «до плеча» — кончается на плечевом суставе. Бока берутся с EA-формы с такой кокеткой: MIN 1_14_3;
  - «на плечо» — заходит на сустав и руку (MTL, COL, выезд DAL). Тогда край на руке — одна прямая наискосок от

- **Щит NHL** (`shield_offset_cm`, `shield_scale`) — по месту у клуба: на мысе кокетки NJD — по середине чёрного, с
  полями сверху и снизу.

**Общие правила для всех клубов (пользователь, 21.10):**
- номера на рукаве (на плече, не на ключице) — там же, где у MIN: зоны 2/3 карты номеров с домашней MIN 1_14_4
  (`edge_kit.SLEEVE_ZONES_REF`); у MIN — свои (`sleeve_zones_from = "own"`);
- верх полос на гетрах — как у MIN: `edge_kit.SOCK_TOP_V` = 0,49 (v развёртки гетр от колена) у `flat` и `auto`;
  `legacy` — в строки `flat` другой формы клуба. Прежние формы NHL 24 (A) — 0,51–0,66, у MIN A 0,574: если в матче
  полосы «не на одном уровне», проверить, какая форма стоит по умолчанию;
- подпись в меню — «Home (NHL 27)» / «Away (NHL 24)»: форма и источник (`label` по умолчанию);
- одобренная пользователем форма — сразу по умолчанию дома и в гостях: `default = true` в слоте профиля. В базе
  (`nhl24.py default_roles`) на клуб и роль побеждает последняя в очереди строк. Прежняя по умолчанию — locstring 6 с
  подписью: EA — «Home (EA)», наша — «Home (old)». Форма NHL 24 того же пакета — со своей подписью «Home (NHL 24)».
  У формы по умолчанию подпись в меню стандартная — Home / Away (locstring 0 / 1);
- шрифт фамилии — с обводкой источника, как есть: `pilot.name_contrast` перекрашивает только самый частый цвет букв
  (21.10, NJD). У TBL `ten` буквы белые без обводки, цифры — с синей: так и перенесено;
- кромка ворота «ступенькой» (пользователь, 21.10, TBL: «таких форм в НХЛ много»): спереди тонкая, сзади широкая, но
  не шире обода — край кромки идёт по шву обода (`RING_KNOTS`), сбоку ступенька. `edge_kit.trim_profile` меряет у
  источника сплошную полосу цвета кромки по углу (шаг 1°): узкая, широкая, угол ступеньки. Если широкая ≥ 2× узкой
  (`TRIM_STEP_RATIO`) — `step_width`: до ступеньки — узкая × `TRIM_K`, после — до обода, переход — 1,5°. Спереди —
  до середины, без разрыва (пользователь: «белый доходит не до конца»; «разрыв» ±24° замер даёт у всех клубов — это
  вырез adidas у сетки NHL 24). Ткань за кромкой (зачистка `TRIM_CLEAR`) — цвет за кромкой источника: у TBL на 2–3,5 см
  от края — сама кромка, зачистка красила ещё 8 мм белым (сзади выходило 3,9 см вместо 3,05). Профиль `collar_trim`
  (auto | step | smooth). TBL: узкая 1,0 см, ступенька 79°; у MIN и NJD ступеньки нет — как раньше;
- цвет каски и краг новых форм — из NHL 27, синий (и другие цвета клуба) — по палитре клуба NHL 27
  (`stockteamcolorstable`), если цвет экипировки NHL 27 с тканью свитера не совпадает (пользователь, 21.10, TBL: каска
  NHL 27 (18, 46, 77) «другого оттенка, много зелёного» при свитере (26, 37, 93)). Краги — поле `"gloves"` формы в
  `tools/legacy_data/nhl24_helmets.json` (зоны 1–9 как у NHL 27, equipment 4) → своя строка `nhl24.py add_gloves`: иначе
  новые формы стиля 0 берут общую строку стиля 0 клуба (у TBL — «чёрный / синий / белый»). Палитра клуба —
  `tools/legacy_data/nhl24_team_colors.json` (`nhl24.py team_colors`): у TBL синий NHL 27 и белый, чёрного нет;
- полосы низа свитера — вдоль края низа одной толщины (пользователь, 21.10, BOS: «белая полоса растянулась посередине
  вверх и вниз»). Низ переносится «от края» (`fb.hem`: угол вокруг тела и высота над краем) только в зоне `HEM_H`
  (9 см, верхние 3 см — переход к переносу по высоте), а края низа у сеток разные (у Edge середина спереди на 1,5 см
  ниже, чем у NHL 24). У NHL 27 полосы низа бывают до 13–14 см (BOS, TBL) — верхние попадали в переход. Поле профиля
  `hem_h` — зона выше полос (верх полос + 4 см), генератор ставит сам. У TBL полосы тоже до 14 см, но форма одобрена —
  поле не задано (при жалобе — `hem_h = 0.188` по генератору);
- полосы рукава у NHL 27 бывают длиннее рукава Edge (BOS: до самого конца): после сжатия к кисти над ними — ткань
  (`SLV_FILL_S24`), и в переходе к пройме тоже ткань (иначе ближайшая точка NHL 24 брала там верхнюю полосу — золотая
  дуга на плече, BOS 21.10);
- ширина кромки ворота у новых клубов — сплошной полосой цвета кромки от края по углу, по основе без нашивок
  (`trim_measure = "contiguous"`, генератор ставит сам; DET 22.10: прежний замер — 95-й процентиль цвета кромки в 3 см
  от края — у широкой кромки выезда давал 3,7 см по всему кругу, а красный мыс спереди — мельче источника; в
  `clean_color` щит стёрт вместе с кромкой под ним). Узкой кромке — «чуть шире» (`TRIM_K`, не больше
  `TRIM_K_MAX_ADD` 4 мм), широкой — нет. У всех клубов кромка не шире шва обода там, где обод есть (у ворота без
  шнуровки — с `RING_PLAIN_TH`; мыс спереди не ограничен). У MIN, NJD, TBL, BOS — прежний замер (`percentile`);
- щит NHL на широкой кромке: если кромка посередине переда шире, чем щит (`SHIELD_H` × масштаб) + зазор источника от
  края ворота + 3 мм, щит ставится на неё, на зазоре источника от края ворота (DET: на красном мысе, 5,4 мм), иначе —
  на `SHIELD_GAP_DEFAULT_MM` под кромкой. Пользователь у DET выбрал место щита как у NJD — `shield_offset_cm` NJD
  (22.10: «шильдик NHL должен быть выше, там же, где у Нью-Джерси»);
- герб на груди — не на букву капитана (`[crest_fit]`: сначала ниже, до низа 0,85, потом меньше, до зоны буквы — `gap_min`).
  У NHL 27 гербы крупные — уменьшались до ×0,73–0,90. Поле профиля `crest_fit = { gap_min = 0.008 }` — зазор 0,6 см
  вместо 1,5: герб на ~10 % крупнее (пользователь, 22.10: TBL, BOS, DET — «логотип немного больше, но чтобы с литерами
  не пересекались»). Генератор пока не ставит — решение по клубу;
- краги новой формы — своей строкой: era как у краг стиля формы, а если она перехватывает прежние формы клуба по
  компаратору игры (у DET нет общей строки краг era 0 — строка новой era 0 доставалась и 0_10_3), — era −1
  (`nhl24.py add_gloves` выбирает по модели);
- поправки клуба по просьбе пользователя — полями профиля: `hem_shift_cm` (полосы низа ниже на столько — LAK 3 см),
  `font_name_scale` с `font_name_anchor = "top"` (фамилия мельче, верх букв на месте — до номера свободнее; LAK 0,9,
  DET 0,85, BOS 1,4 — крупнее). Замер полос низа генератором — по доле круга туловища (полоса — не меньше половины),
  ткань — на 30–40 см над краем (у LAK полосы до 22 см);
- фамилия и буквы капитана — по атласу шрифта источника. Если у атласа NHL 27 буквы мелкие для своих клеток (BOS: 32 px
  высоты из 47, у EA 46; промежутки 17 px против 9; C и A 46–56 px шириной против 67–71), фамилия в игре мелкая и
  разреженная: игра берёт знак из клетки фиксированного размера. Поля профиля `font_name_scale` (буквы крупнее в своих
  клетках — центры `jersey_mesh.FONT_SLOTS`) и `font_captain_x` (C и A шире) — `fb.fonts.scale_glyphs` на стадии slot
  (BOS 22.10: 1,4 и 1,3). Замер — по атласу слота, сравнить с EA-формой клуба;
- нашивки шорт (герб, щит NHL) — наклейками, не переносом текстуры (пользователь, 21.10, NJD: «поехали логотипы»):
  `fb.pant_decals`. Шорты Legacy шире NHL 24/27 в ~1,45 раза и короче: перенос по ближайшей точке растягивал нашивки
  по ширине и поворачивал на изгибах. Теперь ткань — перенос `pant_*_base_color` (без нашивок), нашивки — разница
  `color − base_color`, каждая — наклейка, вертикально и без растяжения. Место и размер — как у EA (`EA_SLOTS`, замер по
  84 формам EA): щит NHL сзади — одна рамка развёртки у всех, высота 5,5 см; герб спереди — на той ноге, где у
  источника, в середине рамок EA этой стороны, по диагонали ~11,5 см. Первый вариант (место — по точке источника)
  пользователь забраковал: щит мельче EA, герб на загибе у края штанины «сплюснутый». Альфа `base_color` у NHL 27 —
  служебная маска, не прозрачность: в шорты идёт только RGB. Включено в `pilot` (`PANT_DECALS`): у
  `pant = "source"` (NJD, TBL) и у форм подхода A при пересборке. Лист — `FB_GAME=nhl24 python -m fb.pant_decals sheet
  --club newjersey --kit home --source nhl27`.

**Что выяснилось на TBL (агент, 21.10; §12.5):**
- реклама NHL 27 на груди снимается сама (`[sponsor]`); если EA «запекла» её и в рельеф основы — `base_normal_decals`;
- `helmetlogo` у NHL 27 — реклама (NJD — Prudential, TBL — TGH дома, BRANDT в гостях), у EA-образца Legacy — эмблема
  клуба. `helmet_logo = source` ставит рекламу (так одобрен NJD), `legacy` — эмблему образца; `kitport present`
  показывает обе;
- герб из нескольких связных частей (TBL: молния и кольцо) — `merge_parts = ["crest"]`, иначе `[crest_fit]` уменьшает
  части порознь;
- щит под кромкой — с полем: у NJD 3 мм (`kitport check`, «до кромки»). У формы без кокетки кромка (`TrimPaint`, ширина
  NHL 27 × `TRIM_K` 1,3) на середине кончается ниже, чем у источника, и щит на месте NHL 27 заходит на неё: TBL —
  `shield_offset_cm` y −1,1, `shield_scale` 0,68.

### 12.3. Перенос клуба: шаги (с 21.10 — генератором профиля)

1. Профиль, номера, каска — генератор: `python -m kitport profile --club КОД` (проба: решения с «+ уверен» /
   «? проверить» и причиной, сравнение с тем, что уже записано), затем `--write`. Он пишет раздел клуба в
   `tools/fb/edge_clubs.toml`, номера `edge_home` / `edge_away` в реестре `tools/legacy_data/nhl24_kits.json` (с
   перенумерацией не поставленных форм, §5.3 п. 1) и каску с крагами в `nhl24_helmets.json`. Что и как он решает — §12.6
   и docstring `tools/kitport/profile.py`. Готовый раздел профиля генератор не переписывает (правка — руками).
   Палитра клуба (`nhl24_team_colors.json`) — только `--write-palette`, после решения пользователя.
2. По желанию — щит без сборки: `python -m fb.edge_kit shield --club КОД` (где встанет, низ кромки, зазор).
3. Сборка: `python -m kitport build --club КОД --kits away,home --stages kit,slot` (~4–6 мин на клуб).
4. Проверка — `python -m kitport check --clubs КОД`: ворот крупно, рельеф без цвета, превью меню, «до кромки» у щита —
   около 4 мм (`edge_kit.SHIELD_GAP_DEFAULT_MM`). Смотреть: щит, края кокетки на плече и сбоку, швы у ворота, черта на
   груди, реклама на груди (должна сняться `[sponsor]`; генератор печатает, попала ли она в правило). Если правился
   общий код — ещё `kitport compare --clubs MIN,NJD` против снимка до правки (§5.3).
5. Пользователю — `python -m kitport present --clubs КОД` (§8.1): по листу на форму, рядом с оригиналом. Решения «?»
   генератора — по этим листам.
6. Одобрил — `default = true` в слотах профиля (руками: это одобрение пользователя, генератор его не ставит).
7. `--stages pack,overlay`.
8. Установка — только с «да» пользователя, при закрытой игре. Перед ней — копия `nhlng.db` из `cache:` в
   `game/work/legacy-data/roster-merge/old-cache-nhlng-<время>.db`. Затем `kitport install --tag …`.
9. Сейв ROSTER — самый свежий по времени (игра пересохраняет его под новым именем): `ls -lt` папки сейвов.
   - `python tools/legacy_data/roster_merge.py "<ROSTER>" --old <копия из п. 8> --new
     game/work/legacy-data/out-nhl24-ahl32/db/nhlng.db` — пробой; если таблиц к записи не 0 — с `--write`. С 21.10
     таблицу без места (у шлемов в сейве запаса нет) он расширяет сам, как `nhl24.py save`, — и новые строки, и правки
     прежних («по умолчанию») за один проход. Проверка после — `nhl24.py save "<ROSTER>"` без `--write`: «сейв уже
     совпадает с базой».
10. Строка — в журнал `nhl24-uniforms.md` §15.1 (заготовку печатает `install`).

### 12.4. Что ещё сделать для гладкого переноса

С 21.10 генератор (`kitport profile`, §12.6) закрыл прежние пункты: `source_kits` из базы NHL 27, номера в реестре с
перенумерацией не поставленных форм, каска и краги из `stockteamequipmenttable` NHL 27 с подменой цветом палитры,
ворот и кокетка по текстуре, `merge_parts` и `base_normal_decals` по замеру, щит по зазору под кромкой (без подбора
пересборками). Что осталось руками и почему:
- **одобрение** — `default = true` в слотах профиля: решение пользователя по листам `present`;
- **палитра клуба** (`nhl24_team_colors.json`) — генератор только предлагает палитру NHL 27 (`--write-palette`): у TBL
  второй цвет NHL 27 тёмный, пользователь выбрал белый — это вкус, а не замер;
- **особые цвета краг** — правило «без чёрного» у TBL (зона 7 краг (32, 32, 32) → белая) — решение пользователя по
  клубу, генератор его не знает (берёт зоны NHL 27 как есть, подменяет только цветные оттенки на цвет палитры);
- **кокетка «на плечо»** (тип MTL, §12.1) — генератор её узнаёт («? проверить»), но `yoke_side_blend` не подбирает; у
  NJD он видит «на плечо» (у NHL 27 чёрное заходит на руку), а пользователь выбрал «до плеча» (бока MIN 1_14_3) — так
  генератор и пишет, с пометкой «проверить»;
- **цвет кокетки** — `edge_kit.yoke_mask` знает только green и dark; кокетка другого цвета (EDM, SJS?) — «проверить»;
- **ворот со шнуровкой** — щит на вставке, замера нет: генератор ставит значения MIN («проверить»);
- **реклама на шлеме** (`helmet_logo`) — пока как у одобренных NJD и TBL (`source`, реклама NHL 27); общего правила
  пользователя нет;
- **рельеф по профилю** (сетчатая ткань кокетки, обод, сила швов) — у всех как у MIN, у ворота без шнуровки — как у NJD;
- **сборка** — ~4–6 мин на клуб; пересборка нужна теперь только по замечаниям к листам.
- **полосы рукава у клубов с длинным блоком полос** (BOS: 7 границ, верх полос у самого конца рукава Edge) — сжатие
  к кисти, как у MIN / NJD / TBL, оставлено; выше колена сжатия — ткань над верхней полосой (`SLV_FILL_S24`, §12.6).
  Опция на потом, только если будет плохо выглядеть (пользователь, 21.10): выравнивать полосы по нижней границе (у
  кисти) вместо сжатия — чтобы полосы не уходили на кисть.

**Руками (профиль, реестр, данные):**
- нынешние комплекты — `ten` / `eleven`, а не `adidas/home` / `away` (там — формы времён NHL 24 с другим шрифтом):
  поле `source_kits`;
- реестр: `nhl24.py alloc` дал `jerseyindex` 12/13; перенумерован вручную, как у NJD: edge 9/10, не поставленные
  home/away/three (1_26_6…8) — 11–13;
- цвет каски — зоны 1–9 из `stockteamequipmenttable` NHL 27 (era 2, варианты 10 / 11: тёмно-синяя (18, 46, 77) /
  светлая) в `nhl24_helmets.json`;
- профиль `[TBL]`: образцы 1_26_3 / 1_26_4, `body_color = back`, `insert = []`; щит — размер и высота подобраны по
  `kitport check` (ниже) — 7 сборок по ~6 мин.

**Чинилось в коде** (найдено по листам, каждое — за полем профиля или без изменений у MIN и NJD):
1. Сжатие полос рукава к кисти молча не работало у клуба без кокетки и вставки: нет «первой сборки» — нет карты
   переноса и `kit.json`, белая полоса заходила в зону номера на рукаве. Теперь первая сборка делается сама
   (`edge_kit.cmd_kit`); у MIN и NJD её и так делали кокетка или вставка — путь тот же. Итог: k 0,70, зазор до зоны
   0,052 (как у NJD).
2. Герб TBL — две связные части (молния и кольцо: рамка молнии выходит за кольцо), `[crest_fit]` уменьшал их порознь
   (0,75 и 0,99) — молния съёживалась внутри кольца. Поле `merge_parts = ["crest"]` (`kit_hybrid.merge_parts`). Итог —
   герб целиком ×0,73–0,75 (так требует зазор до буквы капитана, `[crest_fit]`), пропорции как у оригинала.
3. В `_base_normal` у `ten` EA «запекла» рельеф YMCA и молнии герба: у сдвинутого и уменьшенного герба — двойной
   контур. Поле `base_normal_decals = "flat"` (`edge_kit.decal_mask`): рельеф источника выравнивается в выпуклой
   оболочке каждой нашивки (кольцо герба открыто) + 20 px, спад 10 px (при 6 и 12 оставался контур). Остаток — на
   рельефе без цвета при усиленном контрасте видно слабое пятно без плетения NHL 27 на месте прежнего герба.
4. `kitport check`: белую кромку замер принимал за щит; теперь кромка — полоса цвета верха, «серебро» — только
   нейтральный серый. `kitport survey --clubs` затирал общие листы `survey_N.png` — теперь свой лист.

**Щит** (профиль, руками): кромка (`TrimPaint`) на середине кончается на ~1,635 м, щит на месте NHL 27 заходил на
неё. Подбор по `kitport check`: 0,76 и y 0 → −0,3 → −0,5 → −0,7 → −0,9 (сдвиг по наклонной груди — ~0,7 от y), затем
0,68 (как NJD) и −1,1: щит 1,610–1,632 м, «до кромки» 4 мм дома и в гостях (тем же замером у NJD — 3 мм).

**Открытые дефекты (не доведены, решение — за пользователем):**
- ворот: у `ten` / `eleven` кромка спереди прервана (белые / синие концы, посередине — ткань), у нас — сплошная
  (`TrimPaint` спереди не мерит, ширина — от ±40°). Замер спереди по сетке NHL 24 не работает: у середины от края
  ворота — подворот, кромка дальше (проба 21.10 — ширина 0 даже у NJD, у которого кромка сплошная), нужен другой замер;
- рельеф дома: на месте прежнего герба при усиленном контрасте — слабый ореол по контуру выровненной зоны (СКО наклона
  в полосе 12 px за краем 0,044 против 0,020 у ткани); в цвете и в обычном свете не виден;
- герб ×0,73 (дом) / ×0,75 (выезд) — заметно меньше оригинала: так требует `[crest_fit]` (зазор 0,02 до зоны буквы);
- наклейка на шлем — реклама NHL 27 (TGH / BRANDT), как Prudential у NJD; эмблема образца — `helmet_logo = legacy`.

**Что мешает переносить клуб одной командой** — пункты в §12.4: `source_kits` и цвет каски из базы, `alloc` с
учётом не поставленных форм, высота щита от кромки вместо подбора, решение по рекламе на шлеме, `merge_parts` и
`base_normal_decals` — кандидаты в умолчание.

**«Одетый» свитер против игры** (§8.1): места и глифы — те же, что у игры (карта номеров и атлас слота); кегль,
разрядка, дуга, ориентация номера на рукаве и место C/A (зона 5 или 7) — приблизительно. Лист показывает, где стоят
элементы и не наезжают ли на рисунок, окончательно — в игре.
