# Логотипы клубов 2026/27 в NHL Legacy (агент logos)

10.10.2026. Задача пользователя: логотипы всех клубов — нынешние (формы и прочая графика — отдельно). Здесь — логотипы
клубов НХЛ и АХЛ: наборы интерфейса t/s/d/c/w/r и другие места, где игра берёт логотип по `artid`. Ничего не
поставлено: выход — деревья `cache:` в `game/work/logos/out-nhl/` и `out-ahl/` (с `manifest.json`), ставит legacy-data
(этап build-all `logos`, ниже), игру проверяет nhl-legacy-port (ТЕСТ LOGOS). Листы на проверку —
`game/work/logos/compare/logos_nhl.png` и `logos_ahl.png` («Legacy сейчас | новый», t и s).

Инструменты — `tools/logos/` (в git). SVG НХЛ, промежуточные картинки и выход — только для личного использования, в git
не идут (`game/work/logos/…`).

## Кадр EA по клубу (`tools/logos/eafocus.py`)

В наборах-«крупных планах» EA у каждого клуба выбирала свой фрагмент: у «Рейнджерс» в «таблетке» — надпись RANGERS, у
«Питтсбурга» — голова и живот пингвина, у «Бостона» в w — буква B. Чтобы новый логотип того же рисунка лёг так же:
- новый логотип рисуется целиком без блика и тени в кадре t (рамка вписана в 188×196, центр 128, 128);
- для каждого набора EA этого клуба (s, c, w, значок ленты, pb) ищется подобие — масштаб (перебор 64 значений и
  уточнение ±4 %) и сдвиг (взаимная корреляция полей градиента яркости через FFT, без поворота);
- результат переводится в параметры сборки: точка рамки нового логотипа в центре кадра и размер рамки (`small_focus`,
  `wide_focus`, `calendar_focus`, `ui_extra.tw_focus`, `ui_extra.pb_box`) — `game/work/logos/work-nhl/reg/<КЛУБ>.json`;
- листы проверки — `work-nhl/reg/<КЛУБ>_<набор>.png`: картинка EA и контур нового логотипа по найденному подобию.
  Кадр принят только там, где контур лёг на рисунок EA (`ea_sets` в `clubs.json`).

Проверка метода на самих EA (t EA → наборы EA, `game/work/logos/eafocus.json`): корреляция s — медиана 0,83, c — 0,75,
значок — 0,87, w — 0,54 (у w сильная растушёвка), pb — 0,29 (бледный водяной знак), контур везде на месте. У EA
бывают и другие логотипы: у WSH в s — орёл, у MIN в значке — логотип с надписью MINNESOTA.

Новый рисунок (кадр EA не переносится): ANA (2024), FLA (2016), LA (2024), OTT (2020), TOR (2016). По умолчанию кадр —
медианы EA 0…29: s — центр рамки, рамка в 2,1 высоты «таблетки»; w — (0,45; 0,46), 2,4; c — (0,49; 0,48), 1,3;
значок — (0,39; 0,46), 1,29 ширины окна; pb — центр (499, 252), рамка 540×450. У ANA так и осталось (в центре рамки —
маска утки), у OTT, FLA, LA, TOR кадры s/c/w/значка заданы вручную по сетке долей рамки (`frame` в `clubs.json`): у OTT
центр рамки попадал на красный плащ, теперь в кадре голова сенатора; у FLA — морда пантеры, у LA — надпись KINGS, у
TOR — надпись TORONTO MAPLE LEAFS (как у EA в 2015). У WSH в s вместо орла EA — надпись Capitals (вручную), у MIN в
значке ленты — кадр по умолчанию (у EA там логотип с надписью MINNESOTA), у BOS w и у VAN w и значок — по умолчанию
(сопоставление не легло).

## Размер t/d/r (`ea_size`)

EA в Legacy подгоняла логотипы t скорее по большей стороне (~165 px, у 25 из 29 — 157…174), чем по площади. Медиана
площади (14 980, как у SEA/VGK/UTA) делала круглые логотипы того же рисунка на 15–20 % мельче EA (BOS 138 px против 161,
NYR, WPG, EDM, NYI, NJ, BUF), а широкие — крупнее (ANA, CAR, DET, NSH, SJ). Поэтому у клуба с тем же рисунком (`ea_sets`
не пуст; `ea_size: false` — исключение) цель размера — его же t/d EA: площадь непрозрачной части и рамка не больше EA + 5 %
(`build.ea_size_target`, в SPEC — `size_target`; teamart не менялся: build.py на время сборки клуба подменяет
`SIZE_TARGET_LEGACY`). r берёт масштаб t, как у teamart. Итог по 23 клубам (с NYI): площадь t — как у EA ± 0,5 %, рамка
больше на 0…8 px (MIN 216×140 при EA 212×138); у STL, TB, WSH упор в рамку EA + 5 % — площадь 92–97 % от EA.

## «Таблетка» s

Рисунок — как у EA (`teamart.html_for_ea('s')`): скруглённый прямоугольник 114×46 от (7, 9), градиент цвета клуба,
блик сверху и тень снизу, внутренняя тень. Цвета — по цветам клубов 2026/27 (`pill` в `clubs.json`: низ, верх): тот же
основной цвет, что у EA (у EA «таблетка» — главный цвет клуба), у клубов со сменой цветов — новый: ANA — оранжевый,
PIT — золото Pittsburgh Gold вместо «вегас», BUF — королевский синий, EDM — тёмно-синий.

## Сборка

```bash
V=game/work/logos/venv/Scripts/python.exe
python tools/logos/fetch_nhl.py                       # SVG НХЛ (уже скачанное не качается)
$V tools/logos/eafocus.py game/work/logos/eafocus.json   # проверка метода: кадры EA → EA (необязательно, ~25 мин)
$V tools/logos/build.py [КЛУБ…] [--stages svg,reg,spec,ui,extra,verify]   # → game/work/logos/out-nhl
$V tools/logos/sheets.py nhl game/work/logos/compare/logos_nhl.png        # лист «сейчас | новый» (t и s)
$V tools/logos/sheets.py more game/work/logos/compare/logos_nhl_more.png  # остальные наборы
python tools/logos/outcopy.py manifest game/work/logos/out-nhl            # манифест (md5) для этапа build-all
```

Время: reg — ~1 мин на клуб, ui+extra — ~1,5 мин на клуб (Chrome без окна; клубы можно гнать в 2–3 потока).

## Проверки

- `build.py --stages verify`: каждый файл против шаблона — `.big` против t0/s0/d0/c0/w0/r0 (у pb и значка — файлы EA
  арта 22): записи BIGF, Apt, заголовок XPR2, константа выборки, сцена; `.rx2` — против файла EA того же номера: всё,
  кроме пикселей; разбор → сборка байт в байт (у `.rx2` — и все уровни мипов).
- `teamart.py roundtrip --game legacy` по всему `out-nhl`.
- Итог 10.10: `out-nhl` — 295 файлов (26,4 МБ, с t104 Юты), verify — 0 ошибок, roundtrip — 0.
- `teamart.py roundtrip --deep` помечает все pb (DXT5) как `'8888': False` — так же и у EA `pb_22`, и у Юты `pb_104`:
  проверка «повторное сжатие = те же блоки» имеет смысл только у 8888, у DXT сжатие с потерями. `build.py verify` её у
  DXT не берёт.

## Этап build-all `logos` (вписывает legacy-data; координатор, 10.10)

Готовые файлы ставятся в общий выход `game/work/legacy-data/out` копией по манифесту (md5), пересобирать их в build-all
не нужно (Chrome, ~40 мин):

```bash
if want logos; then
  # логотипы клубов 2026/27 (агент logos, docs/logos-2026.md): готовые файлы по манифесту (md5) → out;
  # пересборка — game/work/logos/venv/Scripts/python.exe tools/logos/build.py [--league ahl]
  for LO in game/work/logos/out-nhl game/work/logos/out-ahl; do
    if [ -f "$LO/manifest.json" ]; then say "логотипы: $LO"; python tools/logos/outcopy.py copy "$LO" $O
    else say "логотипы: нет $LO/manifest.json — пропуск"; fi
  done
fi
```

Место — после `art`: у АХЛ HSK (арт 103) этап `art` пишет прежние логотипы из SVG Википедии, `logos` заменяет их
нынешними. С `utah` и `nhl24` пути не пересекаются (Юта 104/105 и Тусон не трогаются; центр льда, шайбы и наклейки на
шлем — пакет nhl24). Копия в пустой `cache:` пользователя только добавляет файлы: сейчас у него из этих путей нет ни одного
(t/s/d/c/w/r 0…29, баннеры, прожекторы 0…29, pb, значки ленты). Откат — убрать файлы манифеста.
