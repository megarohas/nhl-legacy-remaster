# Настоящий календарь сезона: новые франшизы и ближайший матч любимой команды

Просьба пользователя 02.11.2026: взять из NHL 27 настоящий календарь НХЛ на 2026/27, чтобы новые франшизы играли по нему, а
ближайший матч любимой команды был настоящим. Инструмент — `tools/legacy_data/schedule.py`,
этап `schedule` в `tools/legacy_data/build-all.sh`. Существующие франшизы не меняются.

## Откуда календарь

В базе NHL 27 (`game/work/nhl27/db/nhl_game.db`, дамп — [frostbite-sources.md](frostbite-sources.md)) таблицы `nhlschedule`,
`favoriteteamschedule`, `nhlscheduledebug` совпадают и содержат 1344 матча: 32 клуба × 84 игры, по 42 дома, 29.09.2026 …
10.04.2027. Сверка с открытым API НХЛ (`api-web.nhle.com`, `/v1/club-schedule-season/{клуб}/20262027`, 02.11.2026): **все 1344
матча совпали по дате, хозяевам и гостям** (`schedule.py check`). Матч звёзд в таблице EA не записан, перерывы есть:
20.11, 26.11, 23–25.12, 4–7.02.

`nhlfutureschedule` у EA другая: круговой шаблон без настоящих дат. Она для нас не нужна.

Номера клубов у NHL 27 и Legacy совпадают, кроме 30/31: у NHL 27 — VGK/SEA, у Legacy — SEA/VGK. Инструмент сверяет клубы по
аббревиатуре в обеих базах, номера не зашиты.

Источник по умолчанию — база NHL 27: без сети, и это тот же календарь, что у API. Для другого сезона — API
(`NHL_SEASON=2027 python tools/legacy_data/schedule.py fetch`, кэш `game/work/schedule/api/<сезон>`, пауза 1,1 с). В таблицах EA
года нет, поэтому сезон дампа записан в `EA_SEASON`.

## Что читает игра

| Таблица | Кто читает | Когда |
|---|---|---|
| `favoriteteamschedule` | ближайший матч любимой команды, 82BAC198 → 82BABE40 | SELECT TEAMS, смена любимой команды |
| `nhlschedule` | создание лиги: 82B3B028 (r4 = 1) → 82A0E460 → 82A0DB08 (селектор 1) | только при создании франшизы, «Стань профи», сезона |
| `nhlfutureschedule` | 82B3B028 (r4 = 0) → 82B218E0 → 82A0DB08 (селектор 2) | со второго сезона |

Таблица по селектору — 82A07C78: номер в массиве хешей имён 82056F48 (98 — `nhlschedule`, 97 — `nhlfutureschedule`).

**Ближайший матч любимой команды.** В игре это пара клубов по умолчанию на PLAY NOW / SELECT TEAMS: гости слева, хозяева справа.
82BAC198 берёт системную дату (826568E0) и через 82BABE40 запрашивает `favoriteteamschedule`: хозяева или гости = клуб, month = M, плюс
условие по status (в таблицах он везде 0). Месяцы идут от текущего, ответ — первая строка месяца с day ≥ сегодня, поэтому строки
должны идти по дням. Месяц без игр — конец поиска. Других читателей таблицы в коде нет: хеш имени встречается только в 82BABE40.
Следствия по коду, в игре не проверялись:

- 30–31 декабря, если у клуба в декабре игр больше нет, поиск уходит в месяц 12, строк нет, игра берёт запасной вариант. Так же было и раньше;
- с 11 апреля по 28 сентября следующего матча нет. С 29 сентября 2027 снова пойдут матчи этой таблицы: календарь надо обновить под новый сезон.

**Создание лиги.** Календарь первого сезона копируется в `leaguescheduletable` сейва, дальше игра его из базы не читает. Старт
франшизы и предсезонка считаются от первой строки: 82B3B380 — первая игра − 17 дней (`li r4, 2015` — год, его сдвигает врезка
года), 82B1BBD0 (событие 23) — то же по `leaguetempscheduletable`. Поэтому строка 0 должна быть самой ранней.

**Второй сезон.** `nhlfutureschedule` с перестановкой команд внутри дивизионов (82AFA838) и переносом дат на дни недели нового года.
Настоящего календаря на будущие сезоны нет, инструмент эту таблицу не трогает.

## ROSTER

`nhlschedule`, `favoriteteamschedule` и `nhlfutureschedule` входят в группу сохранения `rosters`: они есть в каждом сейве ROSTER.
Игра при запуске сама грузит самый новый ROSTER поверх базы, поэтому **одной базы мало**: нужна команда `save`. Проверено в игре: с новой
базой и старым ROSTER любимая команда PIT получала старую пару TB–PIT. Старый ROSTER, поставленный поверх, вернёт старый календарь. Порядок при обновлении составов: сначала составы, потом `save` по самому
новому ROSTER.
Число строк то же, поэтому сейв не становится «damaged» ([legacy-data.md](legacy-data.md), «ROSTER damaged»).

## Команды

```bash
python tools/legacy_data/schedule.py show                     # источник, проверка, первые матчи
python tools/legacy_data/schedule.py check                    # сверка дампа и кэша API матч в матч
python tools/legacy_data/schedule.py fetch                    # скачать API НХЛ в кэш
python tools/legacy_data/schedule.py db                       # проба по всем базам out*
python tools/legacy_data/schedule.py db --write               # запись; копия — game/work/legacy-data/schedule/backup/
python tools/legacy_data/schedule.py save "<ROSTER>"          # проба по сейву
python tools/legacy_data/schedule.py save "<ROSTER>" --write  # на месте; копия — game/work/legacy-data/backup-saves/
python tools/legacy_data/schedule.py db ЦЕЛЬ --from-db БАЗА --write   # откат таблиц из другой базы
```

Файл сейва — внутри папки: `…/ROSTER <время>/ROSTER <время>`. Сейв на месте при запущенной игре не пишется.

Этап `schedule` в `build-all.sh` идёт перед `nhl24` и ещё раз вызывается внутри него: `kitport build --stages overlay` зовёт только
`nhl24`, а накладка берётся из `out/db`.

## Проверки инструмента

- у всех клубов поровну игр, домашних половина, никто не играет дважды в день, нет повторов, все даты в сезоне;
- строки по порядку дат;
- после записи: CRC базы и обёртки, размер файла сейва тот же, прочие таблицы байт в байт, повторный план пуст.

## Что проверено

02.11.2026, копия userdata на exe 0.14.0, база с `--ahl32`, любимая команда PIT.

| Что | Результат |
|---|---|
| календарь NHL 27 против API НХЛ | 1344 из 1344 совпали по дате, хозяевам и гостям |
| новая база + старый ROSTER, SELECT TEAMS | старая пара TB–PIT: ROSTER главнее базы |
| новая база + новый ROSTER, SELECT TEAMS | VGK–PIT, настоящий ближайший матч (03.11); матч запустился в PPG Paints Arena |
| откат `--from-db` | база и ROSTER равны исходным по обеим таблицам |
| `nhlfutureschedule` после записи | без изменений |

**В игре не проверено:** новая франшиза (первые матчи, сим, предсезонка), старт с драфта, загрузка существующей франшизы, полный сезон и
второй сезон, Winter Classic, база без `--ahl32` со строкой Матча звёзд, полный прогон этапа `schedule`. Подпись с датой («4/11/2026» в
описании пользователя) на снимках не попалась: виден только выбор клубов.

Что изменится у новой франшизы, посчитано по коду и не видено в игре: первая игра сдвигается с 7.10 на 29.09, предсезонка — с 20.09 на
12.09, старт — с 17.09 примерно на 9.09, поэтому первый год лиги длиннее примерно на 8 дней. Это первое, что надо смотреть при
проверке. Существующие франшизы по разбору не затронуты: календарь лежит в их сейве, `nhlschedule` читается только при создании лиги.
