# Клюшки из NHL 27 в NHL Legacy (`tools/fb/sticks.py`, 23.10.2026)

Перенос рисунков клюшек NHL 27 в слоты каталога Legacy, новые имена в редакторе и белая CCM из Legacy в свободном слоте.
Что в каком слоте — `tools/fb/stick_slots.toml`; в игру клюшки идут вместе с формами (`kitport build --stages
pack,overlay`, `kitport install`).

## Как устроены клюшки

**Legacy.** Модель одна на всех: `rendering/playerstick/playerstick_H_V.rx2` (H — хват: 0 левый, 1 правый, зеркальный;
V — 2 и 4, одна сетка). Рукоять и середину крюка закрывает лента — отдельная сетка `playersticktape_H_V` со своей
текстурой (`tools/sticktape.py`). Бренд задаёт только текстура `cacherender/rendering/playerstick/texlib_<N>.rx2`
(`playerstick_<N>_cm`, 1024×128, DXT1). Рельеф и блик общие, в `texlib_999`. N хранится у игрока в поле
`exhibitionskaterequipment.stick`.

**Каталог редактора** зашит в исполняемый файл (`default.bin`, с 0x19b9128): 27 записей по 0x7C байт —
`[разблокировка, 0, N, N, указатель на ключ имени, бренд, …]`. Разблокировка −1 или 0 — клюшка доступна; 1, 4, 7 —
предзаказ CCM, Easton и Warrior, в редакторе закрыты. BAUER Preorder (−1) в редакторе тоже не выбирается
(проверил пользователь). Имя — строка `nhl_eng_us.db` по ключу записи (`bauervapor1x` → «BAUER Vapor 1X»). Ключи
`bauersupreme1s`, `bauervapor1x`, `bauerpreorder`, `ccmpreorder` и `eastonpreorder` общие с коньками каталога:
сменишь имя клюшки — сменится и имя конька. Порядок записей — порядок в редакторе. Буквы A…AA в плане и на листах —
это он.

**NHL 27.** Модель тоже одна: `content/character/skater/player/stick/common/components/player_stick_left_shaft_mesh`
(древко, 266 вершин) и `_blade_mesh` (крюк, 120). Текстура — `player_stick_<бренд>_<линия>_<модель>_color`,
1024×256. Обе модели в той же системе координат, что Legacy: древко по x от −0,08 до 1,59 м, крюк по z до 0,21 м.
Сечение — восьмигранник ±0,9 × ±1,5 см. Развёртка устроена так же: u вдоль длины, v вокруг сечения. Различаются
полосы по v (у Legacy древко на v 0,23–0,81, у NHL 27 — 0,47–0,91) и острова крюка, поэтому прямое копирование
не подходит. Нужен перенос по модели.

## Перенос (`fb.sticks.mapping`)

Каждому текселю развёртки Legacy (растр 2048×256, потом уменьшение до 1024×128) ищется точка на модели NHL 27:
- **древко** (x < 1,37 м): по длине x и углу вокруг своей оси. Ось — середина габарита сечения по (y, z) в полосах
  по 5 см (`_axis`). Медиана вершин восьмигранника попадала в угол. Ось Legacy на 2,4 см ниже, чем у NHL 27:
  перенос «по ближайшей точке» путал грани и давал растяжки по краям;
- **крюк**: по (x, z) своей стороны (знак нормали по y);
- **остальное** (кромки крюка, ~1700 текселей): ближайшая точка (`kit3d.project`).

Соответствие одно на все клюшки, поэтому полный перенос 26 клюшек занимает около 6 с. Вне развёртки цвет берётся
у ближайшего текселя (`distance_transform`), чтобы мипы не темнели по краям. Альфа = 255.

## Запуск

```bash
cd tools
python -m fb.sticks build                  # все слоты плана → game/work/equipment27/out/texlib_<N>.png
python -m fb.sticks sheet                  # лист плана: NHL 27 (своя модель) | в игре (модель Legacy) → sheet-plan.png
python -m fb.sticks sheet --pairs "C=105:bauer_vapor_flylite_base"   # нынешняя Legacy N | NHL 27 на модели Legacy
python -m fb.sticks fe-sheet               # превью в редакторе: EA → новое
python -m kitport build --stages pack,overlay && python -m kitport install --tag sticks --yes   # в игру (игра закрыта)
```

В пакет клюшки кладёт `fb.sticks.pack(man, cache)` из `edge_kit pack`. Шаблон — `texlib_<N>.rx2` архива Legacy,
`fb.pack.write_rx2_rgba` пересчитывает все мипы. Запись в манифесте — `type: stick`. Имена идут в поле манифеста
`loc` (`{ключ: текст}`), а `legacy_data/nhl24.py build` дописывает их в `fe/loc/NHL_ENG_US.db` накладки, как подписи
форм. База игроков не меняется: у игрока прежний N, меняются только картинка и имя. Поэтому сейв ROSTER сверять не
нужно.

Источник NHL 27: выгрузка `FB_GAME=nhl27 python -m fb.extract "/player_stick_(…)_color$" --out gear27`
(`game/work/nhl27/extract/gear27`). Модели NHL 27 кэшируются в `game/work/equipment27/stick27_meshes.pkl`
(`fb.heads.mesh`, PS5). Модели перечислены в `game/work/equipment27/nhl27_catalog.json` (108 клюшек, 30 коньков).

## Превью в редакторе

В карточке клюшки в редакторе стоит отдельная картинка: `fe/ion/artassets/createplayer/sticks/stick<N>.big`
(BIGF/Apt, текстура 8888 256×128, картинка 140×108 в левом верхнем углу). Если её не заменить, карточка показывает
старую клюшку (пользователь заметил 23.10.2026 после первой установки). У EA это рендер низа клюшки с белой лентой
на крюке, ракурс у всех превью один.

`render_fe` рисует клюшку из плана тем же ракурсом. Модель и лента взяты у EA из renderboot, без нашего мода ленты,
чтобы выглядело как у EA. `write_fe` кладёт результат в контейнер по шаблону превью EA этого слота. `pack` добавляет
превью в пакет вместе с текстурой (`type: stick`).

Ракурс `FE_POSE` и свет `FE_LIGHT` подобраны по превью EA (`python -m fb.sticks fe-fit`):
- **ракурс** — по силуэту `stick105`: перебор стороны и крена через 15°, затем Нелдер — Мид по семи параметрам
  (повороты, сдвиг, масштаб, перспектива). Расхождение силуэта — 1,6 % пикселей;
- **свет** — наименьшими квадратами по пяти превью (105, 94, 72, 108, 35): направление, окружение и рассеянный,
  отдельно для древка и ленты. Средняя яркость старых текстур в нашем рендере — в пределах ±10 % от EA. Оставшаяся
  разница — в мелких деталях: рисунок на модели слегка смещён.

Лист «EA → новое» — `python -m fb.sticks fe-sheet` (`game/work/equipment27/sheet-fe.png`). У многих клюшек NHL 27
надпись бренда стоит выше по древку, чем у старых EA, и в кадр превью не попадает. Видна только нижняя часть рисунка,
это рисунок самой клюшки.

## План (`stick_slots.toml`)

`[slot.<N>]` — `from = "nhl27:<модель>"` (перенос) или `"legacy:<N>"` (текстура слота N из архива Legacy как есть,
то есть оригинал, а не наша замена). `key` и `name` задают строку имени и новый текст. Решение пользователя
(23.10.2026): перенести из NHL 27 сколько получится, по предложению `game/work/equipment27/proposal.md`. В слот D
(BUSCH HPC 2.0, 0 игроков, открыт) — белую CCM RBZ из слота 72 (предзаказ, закрыт), «чтобы её можно было выбрать в
редакторе без разблокировки». Закрытые слоты X, Y, Z и AA тоже заменены — для игроков, у которых они стоят в базе.

Проверка — лист `sheet` (обе стороны, вся длина). Рукоять и середина крюка на листе пустые: в игре их закрывает
лента.

## Грабли

- Клюшки NHL 24 (`fb.pilot sticks`, `fb/stick_map.toml [replace]`) ложатся в те же `texlib_<N>`. В pack-edge
  слоты плана заменяют их записи, поэтому главным остаётся план.
- Слот D после замены берёт текстуру 72 из архива Legacy (`legacy:72`), а не из cache:. Слот 72 при этом занят
  XF Ghost.
- У белой CCM на древке напечатано NUGENT-HOPKINS: это рисунок самой EA (именная клюшка предзаказа).
- Коньки: модель и развёртка другие (`skate/playerskate_L`, `texlib_<N>` 1024×512). Нужен 3D-перенос, как для
  свитеров. Это отдельная работа, она не сделана (план — в `proposal.md`).
